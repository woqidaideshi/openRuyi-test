# TC-TR-0009-01 ｜ ext4 创建挂载与修复

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0009（存储与文件系统功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 存储与文件系统 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 ext4 能正常创建、挂载、读写、卸载，并在块位图不一致这一可修复故障场景下完成检查与修复。

## 前置条件

1. RISC-V 平台，具备可写工作目录与至少 512MB 可用空间。
2. 已安装 e2fsprogs。

## 测试步骤

1. 准备测试设备：创建 512MB 镜像文件并挂为 loop 设备（记作 `$DEV`）。若改用真实空闲盘/分区，直接使用其设备路径，并先执行 `findmnt` 查看根文件系统所在设备，避免误用在用盘。
2. 在 `$DEV` 上创建 ext4 文件系统并写入基线数据：
   - 用 `mkfs.ext4` 创建文件系统，挂载到 `/mnt/ext4`；
   - 写入多层目录、两个文件与一个符号链接；
   - 记录文件 md5 与目录树作为基线。
3. 卸载后重新挂载，比对文件 md5 与目录树（与基线对照）。
4. 卸载后做基线检查：`e2fsck -fn`。
5. 注入块位图不一致：先执行 `debugfs -R 'blocks file.txt' $DEV` 取到该文件占用的块号，再执行 `debugfs -w -R "freeb <块号>" $DEV` 将该块标记为空闲，最后执行 `e2fsck -fn $DEV` 检查。
   > 目的是制造“位图显示空闲、inode 仍在使用”的块，`e2fsck` 才会报 `Block bitmap differences。
6. 修复并复核：
   - 用 `e2fsck -fy` 修复后重新挂载；
   - 比对 md5 与目录树；
   - 查看文件系统状态；
   - 再次 `e2fsck -fn`。
7. 清理：
   - 卸载 `/mnt/ext4`；
   - 用 `losetup -d` 释放 loop 设备；
   - 删除镜像文件与挂载点目录 `/mnt/ext4`。

## 预期结果

1. 步骤 1：镜像创建成功，`$DEV` 指向 `/dev/loopN`，且不是根文件系统所在设备。
2. 步骤 2：
   - `mkfs.ext4` 成功；
   - 挂载与写入均成功，符号链接指向 `file.txt`；
   - 基线记录完成。
3. 步骤 3：文件内容与目录结构与卸载前完全一致，`file.txt` 内容仍为 `ext4-data`。
4. 步骤 4：`e2fsck` 跑完全部检查阶段，不产生交互询问，退出码为 0（未发现错误）。
5. 步骤 5：`e2fsck -fn` 报告 `Block bitmap differences` 并命中被释放的块号，退出码非 0，表示检出错误且未做修改。
6. 步骤 6：
   - 修复输出 `FILE SYSTEM WAS MODIFIED`；
   - 重挂载后文件与目录结构与基线一致，修复未损坏数据；
   - `Filesystem state` 为 `clean`；
   - 再次检查无待修项。
7. 步骤 7：
   - `/mnt/ext4` 已卸载；
   - loop 设备已释放，无残留；
   - 镜像文件与挂载点目录 `/mnt/ext4` 已删除。
