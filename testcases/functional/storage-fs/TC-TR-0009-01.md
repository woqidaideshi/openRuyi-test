# TC-TR-0009-01 ｜ ext4 创建挂载与修复

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0009（存储与文件系统功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 存储与文件系统 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 ext4 能正常创建、挂载、读写、卸载，并在块位图不一致这一可修复故障场景下完成检查与修复。

## 前置条件

1. RISC-V 平台，具备可写工作目录与至少 512MB 可用空间。
2. 已安装 e2fsprogs。

## 测试步骤

1. 创建测试镜像并挂为 loop 设备：
   ```bash
   CASE_TMP=/tmp/tc-ext4 && rm -rf $CASE_TMP && mkdir -p $CASE_TMP
   truncate -s 512M $CASE_TMP/disk.img
   DEV=$(sudo losetup -f --show $CASE_TMP/disk.img)
   echo "DEV=$DEV"
   rpm -q e2fsprogs
   ```
   > 若改用真实空闲盘/分区，把 `DEV` 直接设为该设备（如 `/dev/vdb`）并跳过镜像创建，同时先用 `findmnt -n -o SOURCE /` 确认它不是根文件系统所在盘。
2. 创建 ext4 文件系统，挂载、写入多层目录与文件并记录基线：
   ```bash
   sudo mkfs.ext4 -F "$DEV"; echo "mkfs:$?"
   sudo mkdir -p /mnt/ext4
   sudo mount "$DEV" /mnt/ext4
   sudo mkdir -p /mnt/ext4/data/sub
   echo "ext4-data" | sudo tee /mnt/ext4/file.txt
   echo "nested-data" | sudo tee /mnt/ext4/data/sub/nested.txt
   sudo ln -s file.txt /mnt/ext4/link.txt
   sudo find /mnt/ext4 -type f -exec md5sum {} + | sort -k2 > $CASE_TMP/before.md5
   sudo find /mnt/ext4 | sort > $CASE_TMP/before.tree
   ```
3. 卸载后重新挂载，比对文件 md5 与目录结构：
   ```bash
   sudo umount /mnt/ext4
   sudo mount "$DEV" /mnt/ext4
   sudo cat /mnt/ext4/file.txt
   sudo find /mnt/ext4 -type f -exec md5sum {} + | sort -k2 > $CASE_TMP/after.md5
   diff $CASE_TMP/before.md5 $CASE_TMP/after.md5; echo "md5-diff:$?"
   sudo find /mnt/ext4 | sort > $CASE_TMP/after.tree
   diff $CASE_TMP/before.tree $CASE_TMP/after.tree; echo "tree-diff:$?"
   sudo umount /mnt/ext4
   ```
4. 基线检查：
   ```bash
   sudo e2fsck -fn "$DEV"; echo "e2fsck:$?"
   ```
5. 注入可修复故障并检查：
   ```bash
   BLK=$(sudo debugfs -R 'blocks file.txt' "$DEV" | awk 'NR==1{print $1}')
   echo "block=$BLK"
   sudo debugfs -w -R "freeb $BLK" "$DEV"
   sudo e2fsck -fn "$DEV"; echo "e2fsck-check:$?"
   ```
6. 修复故障并比对数据：
   ```bash
   sudo e2fsck -fy "$DEV"; echo "e2fsck-fix:$?"
   sudo mount "$DEV" /mnt/ext4
   sudo find /mnt/ext4 -type f -exec md5sum {} + | sort -k2 > $CASE_TMP/fixed.md5
   diff $CASE_TMP/before.md5 $CASE_TMP/fixed.md5; echo "md5-diff:$?"
   sudo find /mnt/ext4 | sort > $CASE_TMP/fixed.tree
   diff $CASE_TMP/before.tree $CASE_TMP/fixed.tree; echo "tree-diff:$?"
   sudo umount /mnt/ext4
   sudo dumpe2fs -h "$DEV" 2>/dev/null | grep -i 'Filesystem state'
   sudo e2fsck -fn "$DEV"; echo "e2fsck-recheck:$?"
   ```
7. 清理（释放 loop 设备并删除镜像）：
   ```bash
   sudo rmdir /mnt/ext4
   sudo losetup -d "$DEV"
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：镜像创建成功，`DEV` 指向 `/dev/loopN`，e2fsprogs 已安装。
2. 步骤 2：
   - `mkfs` 退出码为 0；
   - 挂载成功，两个文件写入成功，`link.txt` 指向 `file.txt`；
   - `before.md5` 覆盖 `file.txt` 与 `data/sub/nested.txt`，`before.tree` 记录完整目录树（含 `data`、`data/sub`、`link.txt`；ext4 另有固有的 `lost+found`）。
3. 步骤 3：两次 `diff` 均无输出、退出码均为 0，即文件内容 md5 与目录结构与卸载前完全一致；`file.txt` 内容仍为 `ext4-data`。
4. 步骤 4：
   - `e2fsck` 跑完全部五个检查阶段（inode/块/文件大小、目录结构、目录连通性、引用计数、组摘要）；
   - 全程未出现 `Fix?` 询问行（`-n` 为只读模式，不应产生交互）；
   - `e2fsck` 退出码为 0（`0` = 未发现任何错误；若为 1 表示“发现并修正了错误”，说明注入前文件系统已不干净，本步骤不通过）。
5. 步骤 5：`e2fsck` 报告 `Block bitmap differences`（标记被占用的块在位图中显示为空闲），退出码为 4，表示检出错误且未做修改。
6. 步骤 6：
   - 修复输出 `FILE SYSTEM WAS MODIFIED`，退出码为 1（`e2fsck` 的 1 表示错误已修正）；
   - `md5-diff` 与 `tree-diff` 退出码均为 0 且无输出（文件内容与目录结构同基线一致，修复不损坏数据）；
   - `Filesystem state` 为 `clean`；
   - `e2fsck-recheck` 退出码为 0（确认无待修项）。
7. 步骤 7：清理完毕，`losetup -a` 无残留，镜像目录已删除。
