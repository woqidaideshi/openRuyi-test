# TC-TR-0009-02 ｜ XFS 创建挂载与修复

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0009（存储与文件系统功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 存储与文件系统 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 XFS 能正常创建、挂载、读写、卸载，并在超级块空闲块计数不一致这一可修复故障场景下完成检查与修复。

## 前置条件

1. RISC-V 平台，具备可写工作目录与至少 512MB 可用空间。
2. 已安装 xfsprogs。

## 测试步骤

1. 创建测试镜像并挂为 loop 设备：
   ```bash
   CASE_TMP=/tmp/tc-xfs && rm -rf $CASE_TMP && mkdir -p $CASE_TMP
   truncate -s 512M $CASE_TMP/disk.img
   DEV=$(sudo losetup -f --show $CASE_TMP/disk.img)
   echo "DEV=$DEV"
   rpm -q xfsprogs
   ```
   > 若改用真实空闲盘/分区，把 `DEV` 直接设为该设备（如 `/dev/vdb`）并跳过镜像创建，同时先用 `findmnt -n -o SOURCE /` 确认它不是根文件系统所在盘。
2. 创建 XFS 文件系统，挂载、写入多层目录与文件并记录基线：
   ```bash
   sudo mkfs.xfs -f "$DEV"; echo "mkfs:$?"
   sudo mkdir -p /mnt/xfs
   sudo mount "$DEV" /mnt/xfs
   sudo mkdir -p /mnt/xfs/data/sub
   echo "xfs-data" | sudo tee /mnt/xfs/file.txt
   echo "nested-data" | sudo tee /mnt/xfs/data/sub/nested.txt
   sudo ln -s file.txt /mnt/xfs/link.txt
   sudo find /mnt/xfs -type f -exec md5sum {} + | sort -k2 > $CASE_TMP/before.md5
   sudo find /mnt/xfs | sort > $CASE_TMP/before.tree
   ```
3. 卸载后重新挂载，比对文件 md5 与目录结构：
   ```bash
   sudo umount /mnt/xfs
   sudo mount "$DEV" /mnt/xfs
   sudo cat /mnt/xfs/file.txt
   sudo find /mnt/xfs -type f -exec md5sum {} + | sort -k2 > $CASE_TMP/after.md5
   diff $CASE_TMP/before.md5 $CASE_TMP/after.md5; echo "md5-diff:$?"
   sudo find /mnt/xfs | sort > $CASE_TMP/after.tree
   diff $CASE_TMP/before.tree $CASE_TMP/after.tree; echo "tree-diff:$?"
   sudo umount /mnt/xfs
   ```
4. 基线检查：
   ```bash
   sudo xfs_repair -n "$DEV"; echo "xfs_repair:$?"
   ```
5. 注入可修复故障并检查：
   ```bash
   sudo xfs_db -x -c 'sb 0' -c 'write fdblocks 0' "$DEV"
   sudo xfs_repair -n "$DEV"; echo "xfs_repair-check:$?"
   ```
6. 修复故障并比对数据：
   ```bash
   sudo xfs_repair "$DEV"; echo "xfs_repair-fix:$?"
   sudo mount "$DEV" /mnt/xfs
   sudo find /mnt/xfs -type f -exec md5sum {} + | sort -k2 > $CASE_TMP/fixed.md5
   diff $CASE_TMP/before.md5 $CASE_TMP/fixed.md5; echo "md5-diff:$?"
   sudo find /mnt/xfs | sort > $CASE_TMP/fixed.tree
   diff $CASE_TMP/before.tree $CASE_TMP/fixed.tree; echo "tree-diff:$?"
   sudo umount /mnt/xfs
   sudo xfs_repair -n "$DEV"; echo "xfs_repair-recheck:$?"
   ```
7. 清理（释放 loop 设备并删除镜像）：
   ```bash
   sudo rmdir /mnt/xfs
   sudo losetup -d "$DEV"
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：镜像创建成功，`DEV` 指向 `/dev/loopN`，xfsprogs 已安装。
2. 步骤 2：
   - `mkfs` 退出码为 0；
   - 挂载成功，两个文件写入成功，`link.txt` 指向 `file.txt`；
   - `before.md5` 覆盖 `file.txt` 与 `data/sub/nested.txt`，`before.tree` 记录完整目录树（含 `data`、`data/sub`、`link.txt`）。
3. 步骤 3：两次 `diff` 均无输出、退出码均为 0，即文件内容 md5 与目录结构与卸载前完全一致；`file.txt` 内容仍为 `xfs-data`。
4. 步骤 4：`xfs_repair -n` 各检查阶段全部跑完，未报告 `corrupt` / `bad` 类问题；退出码必须为 0（`-n` 下若为 1 表示“检出需要修复的错误”，说明注入前文件系统就不干净，本步骤不通过）。
5. 步骤 5：`xfs_repair -n` 报告 `sb_fdblocks 0, counted <N>`（超级块空闲块计数与实际不符），退出码为 1，表示检出错误且未做修改。
6. 步骤 6：
   - `xfs_repair` 修复退出码为 0；
   - `md5-diff` 与 `tree-diff` 退出码均为 0 且无输出（文件内容与目录结构同基线一致，修复不损坏数据）；
   - `xfs_repair-recheck` 退出码为 0（确认无待修项）。
7. 步骤 7：清理完毕，`losetup -a` 无残留，镜像目录已删除。
