# TC-TR-0009-05 ｜ 软 RAID1 降级与重建

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0009（存储与文件系统功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 存储与文件系统 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证软 RAID1（镜像）的创建、降级读取、换盘重建及停止后重新组装的恢复能力。

## 前置条件

1. RISC-V 平台，已安装 mdadm。
2. 具备两块 600MB 可写的 loop 镜像（默认方案，不占用物理盘、不涉及固件分区）。
3. 若必须使用物理盘，必须先确认该盘**不含固件/引导分区**。

## 测试步骤

1. 准备两块 600MB 的 loop 成员盘（用镜像文件挂为 loop 设备，记作 `$L1`、`$L2`）。
2. 用两块成员盘创建 RAID1 阵列到 `/dev/md0`（`mdadm --create /dev/md0 --level=raid1`），等待初始同步完成。
3. 在阵列上创建 ext4 文件系统并挂载到 `/mnt/md0`，写入 `file.txt`，记录 md5。
4. 制造降级：将 `$L2` 标记失效并移除，查看成员状态，并读取 `file.txt`。
5. 执行换盘重建：
   - 用 `mdadm --zero-superblock` 擦除 `$L2` 的旧超级块，再用 `mdadm --add` 重新加入 `$L2`；
   - 等待 `/proc/mdstat` 出现 `[UU]`；
   - 用 `mdadm --detail` 核对阵列状态。
   > 跳过擦除超级块时，`--add` 只会把该盘当作残留成员，不触发重建，`[UU]` 不会出现。
6. 停止阵列后用 `mdadm --assemble` 重新组装，重新挂载到 `/mnt/md0` 并复核数据。
7. 清理：
   - 停止阵列（`mdadm --stop`）；
   - 用 `mdadm --zero-superblock` 擦除成员盘超级块；
   - 用 `losetup -d` 释放 loop 设备；
   - 删除镜像文件与挂载点目录 `/mnt/md0`。
   > 阵列未停止时 `mdadm --zero-superblock` 会报 `Couldn't open … for write - not zeroing`，超级块实际未被清除。

## 预期结果

1. 步骤 1：两块 loop 设备创建成功。
2. 步骤 2：RAID1 创建成功，初始同步完成后 `/proc/mdstat` 显示 `[2/2] [UU]`。
3. 步骤 3：文件系统创建与挂载均成功，`file.txt` 内容为 `raid-data`，md5 记录成功。
4. 步骤 4：成员状态显示为 `[U_]`，阵列处于降级状态；降级后 `file.txt` 仍可读为 `raid-data`。
5. 步骤 5：
   - 重建完成后 `/proc/mdstat` 恢复为 `[2/2] [UU]`；
   - `mdadm --detail` 中 `State` 不含 `degraded`；
   - `Active Devices` 为 `2`。
6. 步骤 6：
   - `mdadm --assemble` 提示 `has been started with 2 drives`；
   - 重新挂载成功；
   - 数据 `raid-data` 完整（md5 与步骤 3 一致）。
7. 步骤 7：
   - 阵列已停止，`/proc/mdstat` 无 `md0`；
   - 成员盘超级块已擦除；
   - loop 设备已释放，无残留；
   - 镜像文件与挂载点目录 `/mnt/md0` 已删除。
