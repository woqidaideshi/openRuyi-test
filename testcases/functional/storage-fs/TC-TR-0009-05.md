# TC-TR-0009-05 ｜ 软 RAID1 降级与重建

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0009（存储与文件系统功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 存储与文件系统 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证软 RAID1（镜像）的创建、降级读取、换盘重建及停止后重新组装的恢复能力。

## 前置条件

1. RISC-V 平台，已安装 mdadm。
2. 具备两块 600MB 可写的 loop 镜像（默认方案，不占用物理盘、不涉及固件分区）。
3. 若必须使用物理盘，必须先确认该盘**不含固件/引导分区**。

## 测试步骤

1. 准备两块 loop 成员盘：
   ```bash
   rpm -q mdadm
   sudo mkdir -p /srv/tc-md
   sudo truncate -s 600M /srv/tc-md/m1.img /srv/tc-md/m2.img
   L1=$(sudo losetup -f --show /srv/tc-md/m1.img)
   L2=$(sudo losetup -f --show /srv/tc-md/m2.img)
   echo "L1=$L1 L2=$L2"
   ```
2. 创建 RAID1 并等待初始同步完成：
   ```bash
   sudo mdadm --create /dev/md0 --level=raid1 --raid-devices=2 "$L1" "$L2" --run
   for i in $(seq 1 180); do
     grep -q '\[UU\]' /proc/mdstat && break
     sleep 1
   done
   cat /proc/mdstat
   ```
3. 创建文件系统并挂载读写：
   ```bash
   sudo mkfs.ext4 /dev/md0 > /dev/null 2>&1; echo "mkfs:$?"
   sudo mkdir -p /mnt/md0
   sudo mount /dev/md0 /mnt/md0; echo "mount:$?"
   echo "raid-data" | sudo tee /mnt/md0/file.txt
   md5sum /mnt/md0/file.txt
   ```
4. 制造降级后读取数据：
   ```bash
   sudo mdadm --fail /dev/md0 "$L2"
   sudo mdadm --remove /dev/md0 "$L2"
   grep -oE '\[[U_]+\]' /proc/mdstat
   sudo cat /mnt/md0/file.txt
   ```
5. 换入“新盘”并等待重建完成：
   ```bash
   sudo mdadm --zero-superblock "$L2"
   sudo mdadm --add /dev/md0 "$L2"
   for i in $(seq 1 180); do
     grep -q '\[UU\]' /proc/mdstat && break
     sleep 1
   done
   grep -E '\[[0-9]+/[0-9]+\]|\[[U_]+\]' /proc/mdstat
   sudo mdadm --detail /dev/md0 | grep -E 'State|Raid Devices|Active Devices'
   ```
   > 本步骤需要注意以下两点：
   > - **`mdadm --add` 前必须加 `--zero-superblock`**（对成员盘执行）。否则将不会擦除旧超级块，`--add` 只会把该盘当作残留成员，不触发重建（`--re-add` 也会报 `is not possible`）。
   > - **必须等到 `/proc/mdstat` 出现 `[UU]` 才判定重建完成**——这是唯一可靠的完成信号。
6. 停止并重新组装后校验数据：
   ```bash
   sudo umount /mnt/md0
   sudo mdadm --stop /dev/md0
   sudo mdadm --assemble /dev/md0 "$L1" "$L2"
   sudo mount /dev/md0 /mnt/md0; echo "mount:$?"
   sudo cat /mnt/md0/file.txt
   sudo umount /mnt/md0
   sudo mdadm --stop /dev/md0
   ```
7. 清理（擦除超级块并释放 loop 设备）：
   ```bash
   sudo mdadm --zero-superblock "$L1" "$L2"
   sudo losetup -d "$L1" "$L2"
   sudo rm -rf /srv/tc-md
   sudo rmdir /mnt/md0
   ```

## 预期结果

1. 步骤 1：mdadm 已安装，两块 loop 设备创建成功（`L1`、`L2` 均非空）。
2. 步骤 2：RAID1 创建成功，退出码为 0；初始同步完成后 `/proc/mdstat` 显示 `[2/2] [UU]`。
3. 步骤 3：`mkfs` 与 `mount` 退出码均为 0，`md5sum` 输出正常。
4. 步骤 4：`grep -oE` 输出 `[U_]`，阵列为降级状态；降级后 `file.txt` 内容仍为 `raid-data`。
5. 步骤 5：重建完成后，
   - `/proc/mdstat` 恢复为 `[2/2] [UU]`；
   - `mdadm --detail` 显示 `State` 不含 `degraded`、`Active Devices : 2`。
6. 步骤 6：
   - `mdadm --assemble` 提示 `has been started with 2 drives`；
   - 重新挂载退出码为 0；
   - 数据 `raid-data` 完整（md5 与步骤 3 一致）。
7. 步骤 7：清理完毕，`losetup -a` 无残留，`/proc/mdstat` 无 `md0`，`/srv/tc-md` 已删除。

| 项目 | 实测值 |
|---|---|
| 环境 | openRuyi riscv64，mdadm 4.6-5.10.or.riscv64；内核 `raid1.ko` 可用，两块 600MB loop 镜像 |
| 步骤 2 | `create=0`，`[2/2] [UU]` |
| 步骤 4 | 降级为 `[U_]`，`file.txt` 仍可读为 `raid-data` |
| 步骤 5 | 重建后 `[2/2] [UU]`、`Active Devices : 2`；`State` 实测为 `clean` 或 `active`（两者均不含 `degraded`），取决于阵列是否仍有未落盘数据，故不作为固定断言；`--add` 到出现 `[UU]` 约需 4～5 秒，必须轮询等待 |
| 步骤 6 | `mdadm: /dev/md0 has been started with 2 drives.`，md5 一致 |
| 清理校验 | `losetup -a` 无 `tc-md` 残留，`/proc/mdstat` 无 `md0` |
