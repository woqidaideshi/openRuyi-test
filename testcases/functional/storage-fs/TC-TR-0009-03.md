# TC-TR-0009-03 ｜ 软 RAID 创建组装恢复

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0009（存储与文件系统功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 存储与文件系统 |
| 优先级 | P1 |
| 覆盖设备 | 物理机 |
| 可自动化 | 否 |
| 自动化覆盖 | 否 |

## 描述

验证软 RAID 受支持级别（如 RAID1）的创建、组装及适用的降级恢复正常。

## 前置条件

1. RISC-V 平台，已就绪两块及以上非系统测试盘（如 `/dev/mmcblk0`、`/dev/mmcblk1`）。
2. 已安装 mdadm。
3. 使用前必须确认测试盘**不含固件/引导分区**：
   ```bash
   sudo blkid /dev/mmcblk0 /dev/mmcblk1
   ```
   若某盘存在 `LABEL_FATBOOT="BOOTFIRM"` 一类固件分区（如实测中 `/dev/mmcblk1p1`），**禁止**将该整盘用于 `mdadm --create`，否则会破坏板级固件。此时改用下方"安全替代方案（loop 设备）"。

### 安全替代方案（仅一块可用测试盘时）

用文件支撑的 loop 设备代替物理盘，可完整验证 mdadm 功能且不损硬件：
```bash
sudo mkdir -p /srv/tc-md
sudo truncate -s 600M /srv/tc-md/m1.img /srv/tc-md/m2.img
L1=$(sudo losetup -f --show /srv/tc-md/m1.img)
L2=$(sudo losetup -f --show /srv/tc-md/m2.img)
echo "L1=$L1 L2=$L2"
```
后续步骤中将 `/dev/mmcblk0` 替换为 `$L1`、`/dev/mmcblk1` 替换为 `$L2` 即可，清理时额外执行 `sudo losetup -d $L1 $L2`。

## 测试步骤

1. 确认工具与测试盘：
   ```bash
   rpm -q mdadm
   lsblk
   ```
2. 创建 RAID1：
   ```bash
   sudo mdadm --create /dev/md0 --level=raid1 --raid-devices=2 /dev/mmcblk0 /dev/mmcblk1
   echo $?
   cat /proc/mdstat
   ```
3. 创建文件系统并挂载读写（需等初始同步完成后建文件系统）：
   ```bash
   while grep -qE 'resync|recovery' /proc/mdstat; do sleep 1; done
   sudo mkfs.ext4 /dev/md0 >/dev/null 2>&1
   sudo mkdir -p /mnt/md0
   sudo mount /dev/md0 /mnt/md0
   echo "raid-data" | sudo tee /mnt/md0/file.txt
   md5sum /mnt/md0/file.txt
   ```
4. 制造降级并验证数据仍可读：
   ```bash
   sudo mdadm --fail /dev/md0 /dev/mmcblk1
   sudo mdadm --remove /dev/md0 /dev/mmcblk1
   grep -oE '\[[U_]+\]' /proc/mdstat
   sudo cat /mnt/md0/file.txt
   ```
5. 加入替换盘并**等待重建完成**：
   ```bash
   sudo mdadm --add /dev/md0 /dev/mmcblk1
   for i in $(seq 1 120); do
     grep -qE 'resync|recovery' /proc/mdstat || break
     sleep 1
   done
   sudo mdadm --detail /dev/md0 | grep -E 'State|Raid Devices|Active Devices'
   grep -oE '\[[U_]+\]' /proc/mdstat
   ```
   > 注意：判断阵列状态必须用 `grep -oE '\[[U_]+\]'`（**带 `-E`**）。若用基本正则 `grep -o '\[[U_]+\]'`，`+` 会被当成普通字符，导致恒匹配不到而误判重建未完成。
6. 停止并重新组装后校验数据：
   ```bash
   sudo umount /mnt/md0
   sudo mdadm --stop /dev/md0
   sudo mdadm --assemble /dev/md0 /dev/mmcblk0 /dev/mmcblk1
   sudo mount /dev/md0 /mnt/md0
   sudo cat /mnt/md0/file.txt
   sudo umount /mnt/md0
   sudo mdadm --stop /dev/md0
   ```
7. 清理（擦除超级块）：
   ```bash
   sudo mdadm --zero-superblock /dev/mmcblk0 /dev/mmcblk1
   sudo rmdir /mnt/md0
   ```

## 预期结果

1. 步骤 2：RAID1 创建成功，`/proc/mdstat` 显示阵列已激活（初始 `resync` 完成后为 `[UU]`）。
2. 步骤 3：文件系统创建、挂载、读写正常，`md5sum` 输出正常。
3. 步骤 4：`grep -oE` 输出 `[U_]`，阵列为降级状态；降级后 `file.txt` 内容仍为 `raid-data`。
4. 步骤 5：`mdadm --detail` 显示 `State : clean`、`Active Devices : 2`，`/proc/mdstat` 状态恢复为 `[UU]`。
5. 步骤 6：停止后重新组装成功（`has been started with 2 drives`），数据 `raid-data` 完整（md5 与步骤 3 一致）。
6. 步骤 7：清理完毕，`/proc/mdstat` 中无残留阵列（`unused devices: <none>`）。
