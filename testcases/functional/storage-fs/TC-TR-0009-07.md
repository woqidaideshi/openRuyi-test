# TC-TR-0009-07 ｜ NFS 客户端挂载与授权

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0009（存储与文件系统功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 存储与文件系统 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 NFS 客户端能连接受支持服务端，完成挂载、授权读写、未导出路径拒绝与卸载。服务端与客户端同机部署，通过 `127.0.0.1` 挂载，不依赖外部环境。

## 前置条件

1. RISC-V 平台，已安装 nfs-utils。
2. 本机 `2049` 端口可用（服务端与客户端同机部署）。

## 测试步骤

1. 准备 NFS 服务端：创建导出目录 `/srv/nfs`，在 `/etc/exports` 中加入 `127.0.0.1(rw,sync,no_root_squash)`，启动 `nfs-server`，并用 `showmount -e` 查看导出列表。
2. 挂载共享：`mount -t nfs 127.0.0.1:/srv/nfs /mnt/nfs`，用 `findmnt` 查看挂载类型。
3. 执行授权读写校验：先在本地生成源文件并记下 md5，再将它复制到挂载点为 `file.txt`，依次读取以下三处并计算 md5：
   - 挂载点内的 `/mnt/nfs/file.txt`；
   - 服务端导出目录中的 `/srv/nfs/file.txt`；
   - 重新挂载后，挂载点内的 `/mnt/nfs/file.txt`。
4. 创建空目录 `/mnt/nfs-bad`，尝试将未导出路径 `/srv/notexported` 挂载到该目录。
5. 清理：
   - 卸载 `/mnt/nfs` 并移除挂载点目录；
   - 删除空目录 `/mnt/nfs-bad`；
   - 停止 `nfs-server`；
   - 撤销 `/etc/exports` 中的导出行；
   - 删除导出目录 `/srv/nfs`（含测试文件 `file.txt`）。

## 预期结果

1. 步骤 1：`showmount -e` 的导出列表中存在 `/srv/nfs`。
2. 步骤 2：挂载成功，`findmnt` 显示类型为 `nfs4`（默认协商到 `vers=4.2`；如需 NFSv3，挂载时加 `-o vers=3`）。
3. 步骤 3：
   - 挂载点内的 `/mnt/nfs/file.txt` 与源文件 md5 一致，内容为 `nfs-data`；
   - 服务端导出目录中的 `/srv/nfs/file.txt` 与源文件 md5 一致；
   - 重新挂载后挂载点内的 `/mnt/nfs/file.txt` 仍与源文件 md5 一致。
4. 步骤 4：挂载失败，提示 `access denied by server`（未导出路径被服务端拒绝，授权控制有效）。
5. 步骤 5：
   - `/mnt/nfs` 已卸载，挂载点目录已移除；
   - `/mnt/nfs-bad` 为未使用的空目录，已删除；
   - `nfs-server` 已停止；
   - `/etc/exports` 中无该导出行；
   - `/srv/nfs` 及其中的 `file.txt` 均已删除。
