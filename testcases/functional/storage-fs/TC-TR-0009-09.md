# TC-TR-0009-09 ｜ 升级数据一致性

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0009（存储与文件系统功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 存储与文件系统 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证就地升级路径下，升级前已持久化的文件内容、目录结构及承诺保留的属性保持一致，重启后正常进入新版本，无非预期数据丢失或损坏。

## 前置条件

1. 已明确本次升级的目标版本（`dnf upgrade` 应能从当前版本到达该版本）。
2. 存在受支持的升级路径与可用升级源。
3. **必须在可一次性占用、允许重启的专用测试机（或虚拟机快照）上执行**；不要在多人共用或验证其他用例的机器上执行 `dnf upgrade`，否则会破坏环境、导致其他用例结论失效。
4. 执行前建议备份关键数据并确认可回滚（如虚拟机快照）。

## 测试步骤

1. 在 `/home`、`/etc`、`/var` 准备持久化测试数据，包含多层目录、符号链接、硬链接、非默认权限位与 `root` 属主文件。
2. 记录升级前基线：内核版本、`os-release` 版本、启动标识（`/proc/sys/kernel/random/boot_id`）、文件 md5 清单与属性清单（权限位、属主、属组、类型、链接指向）。
3. 执行全量就地升级：`dnf upgrade`。
4. 重启系统后重新登录，记录启动标识并与基线比对，再查看内核版本与系统版本。
5. 重新生成文件 md5 与属性清单，与基线比对。
6. 检查 `/etc` 下配置文件的升级保留情况（`*.rpmnew` / `*.rpmsave`）。
7. 扫描内核与文件系统错误日志。
8. 清理测试数据。

## 预期结果

1. 步骤 1：测试数据创建成功，同时包含多层目录、符号链接、硬链接、非默认权限位（`640`）与 `root` 属主文件。
2. 步骤 2：基线记录完整，属性清单覆盖所有目录、普通文件与符号链接。
3. 步骤 3：升级完成，无报错。
4. 步骤 4：
   - 重启后重新登录成功；
   - `boot_id` 与升级前不同（确实重启）；
   - 内核版本与系统版本均已到达目标版本。
5. 步骤 5：文件内容与属性清单均与基线一致（目录结构、权限位、属主、属组、符号链接指向均未变化）。
6. 步骤 6：
   - 不出现 `*.rpmsave`；
   - 若出现 `*.rpmnew`，说明该包配置被保留为新文件、原文件未被覆盖，属预期保留行为，需记录清单；
   - 测试用配置文件内容与属性不变。
7. 步骤 7：无 `EXT4-fs error` / `XFS` 损坏 / `I/O error` 类告警；其余错误条目逐条确认为与本次升级无关的既有告警。
8. 步骤 8：测试数据与临时目录已删除。
