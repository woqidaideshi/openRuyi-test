# TC-TR-0013-04 ｜ PAM 授权与资源限制

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0013（安全与认证基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 安全与认证 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 PAM 授权链路对提权与资源限制的约束：授权成员可提权，未授权用户被拒绝，资源限制按配置生效。

## 前置条件

1. 已安装 pam，`pam_limits` 与 `pam_wheel` 模块可用。
2. 具备 root 权限，用于创建与删除测试账号并修改 `/etc/security/limits.d/`。

## 测试步骤

1. 记录授权基线：
    1. 读取 `/etc/sudoers` 与 `/etc/sudoers.d/` 中的全部授权规则（按组与按用户），确定组授权对应的组名；
    2. 执行 `getent group` 取得该组成员清单；
    3. 查看 `/etc/pam.d/su` 是否引用 `pam_wheel`；
    4. 查看 `/etc/security/limits.d/` 现有规则。
2. 创建测试账号：用 `useradd` 新建 `sudoer-test` 与 `nosudo-test` 并设置口令，再用 `usermod` 将 `sudoer-test` 加入组授权组；两个账号均不写入按用户的 sudo 授权规则。
3. 验证授权成员提权：`sudoer-test` 用正确口令执行 `sudo id -u`。
4. 验证未授权用户被拒：`nosudo-test` 用正确口令执行 `sudo id`。
5. 验证 `su` 的授权口径：`nosudo-test` 执行 `su - sudoer-test` 并输入 `sudoer-test` 的口令。
6. 验证资源限制：
    1. 以 `nosudo-test` 建立会话并执行 `ulimit -Sn` 与 `ulimit -Hn`，记录原值；
    2. 新增限制文件 `/etc/security/limits.d/99-nofile-test.conf`，写入 `nosudo-test hard nofile 512`；
    3. 重新建立会话后执行 `ulimit -Sn` 与 `ulimit -Hn`；
    4. 删除 `/etc/security/limits.d/99-nofile-test.conf`；
    5. 重新建立会话后执行 `ulimit -Sn` 与 `ulimit -Hn`。
7. 清理：删除 `sudoer-test` 与 `nosudo-test` 及其家目录，复核 `/etc/security/limits.d/` 中无 `99-nofile-test.conf`、组授权组成员与 sudoers 内容未变化。

## 预期结果

1. 步骤 1：
    1. 按组授权规则为 `%wheel ALL=(ALL) ALL`，组名为 `wheel`；按用户授权规则仅 `root ALL=(ALL) ALL`；`/etc/sudoers.d/` 为空；
    2. `getent group wheel` 返回 `wheel:x:10:openruyi`（默认安装的初始成员）；
    3. `/etc/pam.d/su` 未引用 `pam_wheel`；
    4. `/etc/security/limits.d/` 为空，无自定义限制规则。
2. 步骤 2：两个账号创建成功，`sudoer-test` 属于 `wheel` 组，`nosudo-test` 不属于任何授权组。
3. 步骤 3：输入正确口令后提权成功，`id -u` 输出 `0`。
4. 步骤 4：提权被拒，提示该账号不在 sudoers 中，未取得 root 权限。
5. 步骤 5：`nosudo-test` 输入 `sudoer-test` 的正确口令后切换成功，当前用户为 `sudoer-test`，说明 `su` 只校验目标账号口令，不受 `wheel` 组成员资格限制。
6. 步骤 6：
    1. 记录到该账号未受限时的软限制与硬限制原值；
    2. 限制文件创建成功；
    3. 新会话的 `ulimit -Sn` 与 `ulimit -Hn` 均为 `512`；
    4. 限制文件删除成功；
    5. 两项均恢复为步骤 6.1 记录的原值。
7. 步骤 7：两个测试账号与新增限制文件均已删除，组授权组成员与 sudoers 内容与基线一致。
