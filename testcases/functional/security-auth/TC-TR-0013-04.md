# TC-TR-0013-04 ｜ 审计记录

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0013（安全与认证基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 安全与认证 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证规定安全事件生成完整、可查询的审计记录。

## 前置条件

1. 已安装 audit，auditctl / ausearch 可用。
2. 具备 root 权限（sudo）。
3. 内核命令行不含 `audit=0`。

## 测试步骤

1. 确认 audit 状态与内核命令行（若 auditd 未运行则先启动）：
   ```bash
   cat /proc/cmdline
   grep -o 'audit=[0-9]' /proc/cmdline || echo "no audit= param"
   sudo systemctl start auditd 2>/dev/null || true
   sudo systemctl is-active auditd
   sudo auditctl -s
   ```
   > **关键判据**：若 `cat /proc/cmdline` 中包含 `audit=0`，则内核已关闭审计子系统，`auditd` 与 `auditctl` 均无法工作（`auditctl -s` 报 `Cannot open netlink audit socket`）。此情形下本用例应直接判为**环境/系统不满足**并提交缺陷，不得继续执行后续步骤。
2. 添加审计规则监控 `/etc/passwd`：
   ```bash
   sudo auditctl -w /etc/passwd -p wa -k passwd_watch
   sudo auditctl -l
   ```
3. 触发受监控事件（修改 `/etc/passwd` 后恢复）：
   ```bash
   sudo cp /etc/passwd /etc/passwd.tcbackup
   echo "# ruyi-audit-test" | sudo tee -a /etc/passwd
   sudo mv /etc/passwd.tcbackup /etc/passwd
   ```
4. 查询审计记录：
   ```bash
   sudo ausearch -k passwd_watch
   ```
5. 清理审计规则：
   ```bash
   sudo auditctl -W /etc/passwd -p wa -k passwd_watch
   ```

## 预期结果

1. 步骤 1：内核命令行不含 `audit=0`，`auditctl -s` 可正常返回审计状态，auditd 状态为 `active`。
2. 步骤 2：规则添加成功，`auditctl -l` 显示该规则。
3. 步骤 4：`ausearch` 能查询到对应事件记录（包含时间、主体、对象、结果等字段）。
4. 步骤 5：规则删除成功。

## 已知问题（2026-11-10 在 riscv64 物理机实测）

**现象**：审计子系统完全不可用。

```
$ cat /proc/cmdline
BOOT_IMAGE=/e33e99f4.../7.0.11-530.2.or/linux root=UUID=9eabf1f0-... audit=0 systemd.machine_id=...

$ sudo systemctl start auditd; systemctl is-active auditd
inactive

$ sudo auditctl -s
Cannot open netlink audit socket

$ sudo auditctl -w /etc/passwd -p wa -k passwd_watch
Cannot open netlink audit socket        # 规则添加失败，exit 1

$ sudo ausearch -k passwd_watch
<no matches>
```

**根因**：镜像内核启动参数包含 **`audit=0`**，在启动时即禁用内核审计子系统，用户态 `auditd`（已安装 `audit-4.1.4-7.6.or.riscv64` 且 `systemctl is-enabled auditd` 为 `enabled`）即使尝试启动也处于 `inactive`。

**结论（系统/镜像问题，非测试用例问题）**：TR-0013 要求"安全事件生成完整可查询的审计记录"，但当前镜像默认启动参数关闭了审计，导致该需求**不满足**。需厂商从 `/etc/default/grub` / bootloader 中去掉 `audit=0`（或改为 `audit=1`）并重新验证。
