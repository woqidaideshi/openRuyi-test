# TC-TR-0013-05 ｜ 审计记录

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0013（安全与认证基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 安全与认证 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证规定安全事件生成完整、可查询的审计记录。

## 前置条件

1. 已安装 audit，`auditctl`、`ausearch`、`aureport`、`augenrules` 可用。
2. 具备 root 权限。
3. 内核命令行未关闭审计功能（即启动参数中不含 audit=0）。注意：若默认镜像预置了 audit=0，需提前在 /etc/kernel/cmdline 及对应的引导条目中移除该参数，并重启系统使配置生效。
4. 存在普通账号 `openruyi` 且正确口令已知。

## 测试步骤

1. 查看审计子系统状态：
    - 读取 `/proc/cmdline` 查看启动参数中是否含 `audit=0`；
    - 执行 `systemctl is-active auditd` 查看审计服务运行状态；
    - 执行 `auditctl -s` 查看内核审计启用状态（`enabled`）、日志缓冲区占用与上限（`backlog` 与 `backlog_limit`）、消息丢弃计数（`lost`）。
2. 记录规则基线并准备规则目录：执行 `auditctl -l` 保存现有规则清单，查看 `/etc/audit/rules.d` 目录（不存在则创建）。
3. 按事件清单下发规则：
    1. 执行 `auditctl -w /etc/passwd -p wa -k identity_test` 监视 `/etc/passwd` 的写入与属性变更；
    2. 执行 `auditctl -w /etc/shadow -p wa -k identity_test` 监视 `/etc/shadow` 的写入与属性变更；
    3. 执行 `auditctl -w /usr/bin/sudo -p x -k privilege_test` 监视提权命令的执行；
    4. 执行 `auditctl -w /var/log/auth -p wa -k login_fail_test` 监视认证日志的写入；
    5. 执行 `auditctl -w /etc/audit/rules.d -p wa -k audit_config_test` 监视审计规则目录的写入与属性变更；
    6. 执行 `auditctl -l` 查看当前规则集。
4. 逐类触发事件：
    - 用 `useradd` 新建并删除测试账号 `audit-tmp`，触发身份文件变更；
    - 执行 `sudo -n true` 触发提权执行；
    - 使用 `openruyi` 与错误口令通过 SSH 登录，触发认证日志写入；
    - 在 `/etc/audit/rules.d` 下新建空文件 `trigger-test.rules` 并删除，触发审计配置变更。
5. 逐类查询记录：
    1. 执行 `ausearch -if /var/log/audit/audit.log -k identity_test` 查询身份文件变更记录；
    2. 执行 `ausearch -if /var/log/audit/audit.log -k privilege_test` 查询提权执行记录；
    3. 执行 `ausearch -if /var/log/audit/audit.log -k login_fail_test` 查询登录失败记录；
    4. 执行 `ausearch -if /var/log/audit/audit.log -k audit_config_test` 查询审计配置变更记录。
6. 生成汇总：
    1. 执行 `aureport --input-logs --summary` 查看各类事件计数汇总；
    2. 执行 `aureport --input-logs -f` 查看文件访问记录。
7. 持久化规则：
    1. 把步骤 3 下发的五条规则写入 `/etc/audit/rules.d/99-audit-test.rules`；
    2. 执行 `auditctl -D` 清空当前运行时规则，避免与规则文件内容不一致的旧规则残留；
    3. 执行 `augenrules --load` 读取 `/etc/audit/rules.d/` 下的规则文件并加载到内核；
    4. 执行 `auditctl -l` 查看内核当前生效的规则集。
8. 清理：
    1. 删除 `/etc/audit/rules.d/99-audit-test.rules`；
    2. 执行 `auditctl -D` 清空运行时规则，使规则集回到基线；
    3. 若规则目录由本次创建则删除该目录；
    4. 执行 `auditctl -l` 查看规则集。

## 预期结果

1. 步骤 1：
    - `/proc/cmdline` 中不含 `audit=0`；若含 `audit=0`，审计在引导阶段被内核关闭，本用例不适用，记录为环境不满足并跳过步骤 2 至 8；
    - auditd 处于运行状态；
    - `auditctl -s` 输出 `enabled 1`、`lost` 为 0 且 `backlog` 未达 `backlog_limit`。
2. 步骤 2：`auditctl -l` 输出 `No rules`；`/etc/audit/rules.d` 原不存在，已创建。
3. 步骤 3：五条规则均下发成功（身份文件 2 条、提权执行 1 条、认证日志 1 条、审计配置 1 条），`auditctl -l` 中可见对应键名。
4. 步骤 4：四类事件均被触发，命令无报错。
5. 步骤 5：
    1. `identity_test` 查询有匹配记录，记录含 `type`、时间戳（`msg=audit(<时间>:<序号>)`）、`auid`/`uid`、`exe`、`name`、`success` 字段；
    2. `privilege_test` 查询有匹配记录，字段要求同上；
    3. `login_fail_test` 查询有匹配记录，字段要求同上；
    4. `audit_config_test` 查询有匹配记录，字段要求同上。
6. 步骤 6：
    1. 汇总时间范围覆盖本次操作时段，账号变更计数不为 0；
    2. 文件访问记录中包含 `/usr/bin/sudo` 的访问记录。
7. 步骤 7：
    1. 规则文件写入成功；
    2. `auditctl -D` 输出 `No rules`；
    3. `augenrules --load` 退出码为 0；
    4. `auditctl -l` 显示 5 条规则。
8. 步骤 8：
    1. 规则文件已删除；
    2. `auditctl -D` 输出 `No rules`；
    3. 本次创建的规则目录已删除；
    4. `auditctl -l` 输出 `No rules`。
