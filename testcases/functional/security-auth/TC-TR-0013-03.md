# TC-TR-0013-03 ｜ PAM 认证

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0013（安全与认证基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 安全与认证 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 PAM 认证链路正常：有效口令通过，无效口令与弱口令按策略被拒绝，失败次数达到阈值后账号被锁定。

## 前置条件

1. 已安装 `openssh`、`pam` 与 `sshpass`。
2. `sshd` 服务已启动且允许密码认证。
3. 存在普通账号 `openruyi` 且已知口令，可经 sudo 取得 root 权限，用于创建与删除测试账号、修改 PAM 配置、查看认证日志与锁定记录。

## 测试步骤

1. 保存 PAM 认证安全基线：`ssh` 登录（`/etc/pam.d/sshd`）与口令修改（`/etc/pam.d/passwd`）所引用 PAM 配置文件的完整内容。
2. 创建测试账号：用 `useradd` 新建非特权账号 `pam-test` 并设置已知口令，不加入 `wheel` 组、不写入按用户的 sudo 授权规则。
3. 使用 `openruyi` 的正确口令通过 SSH 密码认证登录并执行 `echo PAM_OK`。
4. 使用 `openruyi` 的错误口令尝试通过 SSH 密码认证登录。
5. 验证口令复杂度策略：
    1. 以 `pam-test` 身份用 `passwd` 把口令改为 6 位纯数字弱口令，再改为长度 8 至 15 位且满足复杂度要求的合规口令；
    2. 备份口令修改入口所引用的 `/etc/pam.d/system-auth` 指向的真实文件内容 `/etc/authselect/system-auth`，注意该路径是符号链接，直接复制链接不会得到配置内容；
    3. 在 `/etc/pam.d/system-auth` 的 `pam_pwquality.so local_users_only` 行末追加更严格的长度参数，例如 `minlen=16`；
    4. 以 `pam-test` 把口令改为另一个长度 8 至 15 位、满足复杂度要求且与当前口令不同的口令（不要沿用当前口令，否则会先触发口令重复校验，无法体现长度策略）；
    5. 还原 `/etc/pam.d/system-auth` 内容，再用步骤 5.4 的口令尝试设置。
6. 验证登录失败锁定：
    1. 对 `pam-test` 连续 5 次以错误口令尝试 SSH 登录，再用正确口令尝试登录；
    2. 备份 SSH 登录入口所引用的 `/etc/pam.d/password-auth` 指向的真实文件内容 `/etc/authselect/password-auth`，注意该路径是符号链接，直接复制链接不会得到配置内容；
    3. 在 `/etc/pam.d/password-auth` 中加入三行：`auth` 段的 `pam_env.so` 之后插入 `auth required pam_faillock.so preauth`，`pam_unix.so` 之后插入 `auth [default=die] pam_faillock.so authfail`，`account` 段的 `pam_unix.so` 之前插入 `account required pam_faillock.so`；
    4. 对 `pam-test` 连续 5 次以错误口令尝试 SSH 登录，再用正确口令尝试登录，并执行 `faillock --user pam-test` 查看失败记录；
    5. 执行 `faillock --user pam-test --reset` 清除失败记录，再用正确口令尝试登录；
    6. 还原该文件内容后，对 `pam-test` 连续 5 次以错误口令尝试 SSH 登录，再用正确口令尝试登录。
7. 在认证日志中核对 `openruyi` 与 `pam-test` 各自的会话开启与关闭记录是否成对（执行比对的本条会话尚未关闭，可不计入）。
8. 清理：删除 `pam-test` 及其家目录，比对两个 PAM 配置文件与基线，并尝试以 `openruyi` 重新登录。

## 预期结果

1. 步骤 1：`ssh` 登录经 `/etc/pam.d/sshd` 引用 PAM 配置文件 `/etc/pam.d/password-auth`（实际为 `/etc/authselect/password-auth`），`passwd` 经 `/etc/pam.d/passwd` 引用 PAM 配置文件 `/etc/pam.d/system-auth`（实际为 `/etc/authselect/system-auth`）；两个配置文件均含 `pam_unix`（口令认证）、`pam_pwquality`（口令复杂度）与 `pam_limits`（会话资源限制）模块。
2. 步骤 2：`pam-test` 创建成功，不属于 `wheel` 组。
3. 步骤 3：登录成功并输出 `PAM_OK`，认证日志中出现该账号的 `pam_unix` 会话开启记录。
4. 步骤 4：认证被拒，认证日志中出现该账号的 `pam_unix` 认证失败记录。
5. 步骤 5：
    1. 弱口令被拒绝并提示口令过短、口令未变更；长度 8 至 15 位的合规口令修改成功；
    2. 备份内容与该配置文件的真实内容一致；
    3. 追加参数后，长度不足 16 位的新口令被拒绝并提示长度不足，口令未变更；
    4. 还原配置后同一口令可设置成功。
6. 步骤 6：
    1. 未启用时连续 5 次错误口令后，正确口令仍可登录；
    2. 备份完成，`pam_faillock` 的三行配置加入成功；
    3. 启用后连续 5 次错误口令，失败记录到 3 条（默认阈值）后不再新增，正确口令被拒；
    4. 重置后可正常登录；
    5. 还原配置后连续 5 次错误口令，正确口令仍可登录。
7. 步骤 7：两个账号各自的会话开启与关闭记录均成对存在。
8. 步骤 8：两个 PAM 配置文件与基线一致，`pam-test` 已删除，`openruyi` 登录恢复。
