# TC-TR-0013-03 ｜ PAM 认证授权

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0013（安全与认证基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 安全与认证 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 PAM 认证流程正常且授权/限制策略生效。

## 前置条件

1. PAM 配置可用（`/etc/pam.d/`）。
2. 已安装 sshpass，sshd 已运行。
3. 具备 root 权限（sudo）。

## 测试步骤

1. 通过 ssh 密码认证触发 PAM（正确密码）：
   ```bash
   sshpass -p '<正确密码>' ssh -n -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no openruyi@localhost 'echo PAM_OK' </dev/null
   ```
2. 错误密码触发 PAM 被拒绝：
   ```bash
   sshpass -p 'wrong' ssh -n -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no -o NumberOfPasswordPrompts=1 openruyi@localhost 'echo NO' </dev/null
   ```
3. 验证 pam_limits 授权/限制策略生效（core dump 限制）：
   ```bash
   sudo grep -R 'pam_limits' /etc/pam.d/ | head
   ulimit -c
   ```
4. 查看 PAM 相关认证日志（认证日志由 rsyslog 写入 `/var/log/auth`）：
   ```bash
   sudo tail -30 /var/log/auth | grep -i 'pam_unix'
   ```

## 预期结果

1. 步骤 1：认证成功，输出 `PAM_OK`，退出码为 0，PAM 会话正常建立。
2. 步骤 2：认证失败，退出码非 0（实测 `255`），提示 `Permission denied`，PAM 拒绝认证。
3. 步骤 3：`/etc/pam.d/` 中至少有一个配置引用 `pam_limits.so`，`ulimit -c` 输出与配置一致。
4. 步骤 4：`/var/log/auth` 中存在 `pam_unix(sshd:session): session opened/closed` 记录。

> 实测提示：本镜像 `/dev/log` 由 rsyslog 接管，sshd 的 PAM 日志**不进 journald**。实测完成登录后 `journalctl --since '-5min' | grep pam_unix` 仍取不到记录，因此不能用 journalctl 判定，以 `/var/log/auth` 为准。
