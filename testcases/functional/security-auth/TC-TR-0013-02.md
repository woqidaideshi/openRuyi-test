# TC-TR-0013-02 ｜ SSH 认证与凭据策略

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0013（安全与认证基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 安全与认证 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 SSH 认证凭据策略：有效凭据认证成功，无效凭据与未授权访问按策略拒绝。

## 前置条件

1. openssh 服务可用（sshd 已运行），且允许密码认证。
2. openruyi 用户存在，已知其正确密码；已安装 sshpass。
3. 若目标用户仅配置密钥登录，可临时创建密码用户验证，验证后删除（`sudo useradd -m tcu` → `sudo passwd tcu` → 测试 → `sudo userdel -r tcu`）。

## 测试步骤

1. 使用有效凭据 SSH 登录并执行命令：
   ```bash
   sshpass -p '<正确密码>' ssh -n -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no openruyi@localhost 'whoami' </dev/null
   ```
2. 使用无效密码 SSH 登录，观察是否被拒绝：
   ```bash
   sshpass -p 'wrong-password' ssh -n -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no -o NumberOfPasswordPrompts=1 openruyi@localhost 'whoami' </dev/null
   ```
   > 必须用 `</dev/null` 或 `-n`，否则在脚本中内层 ssh 会吞掉外层标准输入。
3. 查看认证失败相关日志（认证日志由 rsyslog 写入 `/var/log/auth`，**以该文件为准**）：
   ```bash
   sudo tail -20 /var/log/auth | grep -iE 'Failed password|Invalid user|pam_unix'
   ```

## 预期结果

1. 步骤 1：有效凭据认证成功，`whoami` 输出对应用户名，退出码为 0。
2. 步骤 2：无效凭据被拒绝，退出码非 0（实测为 `255`），提示 `Permission denied (publickey,password).`，未建立会话。
3. 步骤 3：日志中存在认证失败记录（如 `sshd-session[...]: Failed password for <user> from ::1 port ... ssh2`）。

> 实测补充（2026-11-10，riscv64 物理机）：
> 1. **认证日志的落盘位置是 `/var/log/auth`，不是 `/var/log/secure`**。openRuyi 的 `/etc/rsyslog.conf` 配置为 `auth,authpriv.*  /var/log/auth`；实测 `/var/log/auth` 持续写入（含 `pam_unix(sshd:session)`、`sudo:` 记录），mtime 与当前时间一致。
> 2. `/var/log/secure` 虽然存在，但为 **0 字节**且停留在旧日期（属 RHEL 习惯遗留），**不能**作为核查依据，否则会误判为“无认证日志”。
> 3. 核查方式以 `/var/log/auth` 为准：
>    ```bash
>    sudo tail -20 /var/log/auth | grep -iE 'Failed password|Invalid user|pam_unix'
>    ```
>    `journalctl` **不一定**能查到：本镜像 `/dev/log` 由 rsyslog 接管，sshd 的认证日志不进 journald（实测刚完成一次成功/失败登录后，`journalctl --since '-5min' | grep pam_unix` 仍取不到，最近一条还是两天前）。
