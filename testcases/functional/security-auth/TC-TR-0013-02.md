# TC-TR-0013-02 ｜ SSH 认证与凭据策略

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0013（安全与认证基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 安全与认证 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 SSH 认证凭据策略：有效凭据认证成功，无效凭据与未授权访问按策略拒绝。

## 前置条件

1. 已安装 `openssh`、`openssh-clients`、`openssh-server` 与 `sshpass`。
2. `sshd` 服务已启动，且允许密码认证。
3. `openruyi` 用户已存在，其口令已知，且该用户可通过 sudo 获取 root 权限。
4. `openruyi` 的 `~/.ssh/authorized_keys` 可修改，验证后能恢复原内容。
5. 本用例在被测机本机执行，SSH 连接目标地址使用 `127.0.0.1`。

## 测试步骤

1. 记录基线：执行 `sshd -T` 提取 `PasswordAuthentication`、`PubkeyAuthentication`、`PermitRootLogin`、`MaxAuthTries` 四项取值，并保存 `~/.ssh/authorized_keys` 的当前内容。
2. 使用 openruyi 账号及正确口令通过 SSH 登录并执行 `whoami`。
3. 使用 openruyi 账号及错误口令通过 SSH 登录。
4. 用不存在的用户名通过 SSH 登录。
5. 公钥认证：
    1. 用 `ssh-keygen` 生成一对测试密钥，把公钥追加到 `openruyi` 的 `~/.ssh/authorized_keys`；
    2. 用前一步生成的私钥登录；
    3. 用另一对未登记的私钥登录；
    4. 从 `authorized_keys` 移除测试公钥。
6. 主机密钥校验：
    1. 执行 `ssh-keyscan 127.0.0.1` 取得真实主机公钥；
    2. 用 `ssh-keygen` 生成一对与主机密钥同类型的无关密钥；
    3. 对已取得的真实主机公钥，保留主机名与密钥类型，只把公钥部分替换为前一步生成的无关公钥，写入 `known_hosts_test`；
    4. 执行 `ssh -o StrictHostKeyChecking=yes -o UserKnownHostsFile=known_hosts_test openruyi@127.0.0.1`。
7. 通过 `journalctl` 或 rsyslog 日志（`/var/log/auth`）查看本次会话的认证记录。
8. 清理：删除测试密钥对与 `known_hosts_test`，确认 `~/.ssh/authorized_keys` 与基线一致。

## 预期结果

1. 步骤 1：密码认证与公钥认证均已启用，root 用户仅允许密钥登录，认证尝试上限为 6 次。
2. 步骤 2：`whoami` 输出 `openruyi`，退出码为 0。
3. 步骤 3：认证被拒，提示权限被拒绝，退出码为 255，未建立会话。
4. 步骤 4：认证被拒，提示权限被拒绝，退出码为 255。
5. 步骤 5：登记后的密钥可登录且退出码为 0；未登记密钥被拒且退出码为 255。
6. 步骤 6：连接被拒，提示主机身份已变更，退出码为 255。
7. 步骤 7：认证日志中同时存在成功登录记录与认证失败记录，失败记录覆盖失败口令与无效用户两类。
8. 步骤 8：测试文件已删除，`authorized_keys` 内容与基线一致。
