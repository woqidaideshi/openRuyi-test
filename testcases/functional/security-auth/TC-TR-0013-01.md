# TC-TR-0013-01 ｜ TLS/证书认证

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0013（安全与认证基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 安全与认证 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证合法证书链能够完成 TLS 连接，不受信 CA 签发、已过期及主机名不匹配三类证书均被拒绝。

## 前置条件

1. 已安装 openssl，`openssl version` 可执行。
2. 具备可写工作目录，本地回环端口 `4433`、`4434` 未被占用；若被占用可改用其他两个空闲端口，后续步骤与预期结果中的端口号同步替换。
3. 系统时间准确，过期证书的判定依赖系统时间。

## 测试步骤

1. 在工作目录用 `openssl` 生成测试材料：
   - 自签 CA `ca1` 的证书与 CA 私钥；
   - 另一套独立的自签 CA `ca2`，仅作不可信锚点；
   - 服务端私钥 `server.key` 与 CSR；
   - 由 `ca1` 用该 CSR 签发的 `server.crt`；
   - 由 `ca1` 用同一 CSR 签发、有效期落在过去时间区间的 `expired.crt`。
2. 用 `openssl s_server` 启动两个 TLS 端点：分别以 `server.crt`、`expired.crt` 为服务端证书，共用 `server.key` 为私钥，监听 `4433`、`4434`。
3. 校验合法证书链：执行 `openssl s_client -connect 127.0.0.1:4433 -CAfile ca1.crt`。
4. 校验不受信 CA：执行 `openssl s_client -connect 127.0.0.1:4433 -CAfile ca2.crt`。
5. 校验过期证书：执行 `openssl s_client -connect 127.0.0.1:4434 -CAfile ca1.crt`。
6. 校验主机名匹配：执行 `openssl s_client -connect 127.0.0.1:4433 -CAfile ca1.crt -verify_hostname example.com`。
7. 验证校验结果可被调用方感知：对步骤 3、4、5、6 四个场景分别追加 `-verify_return_error` 重新执行。
8. 清理：终止两个 TLS 端点，删除工作目录，确认两个端口不再监听。

## 预期结果

1. 步骤 1：各材料均生成成功；`server.crt` 能被 `ca1` 校验通过；`expired.crt` 有效期已过。
2. 步骤 2：两个端口均处于监听状态。
3. 步骤 3：校验通过，返回码为 0。
4. 步骤 4：校验失败，提示找不到本地签发者证书，返回码非 0。
5. 步骤 5：校验失败，提示证书已过期，返回码非 0。
6. 步骤 6：校验失败，提示主机名不匹配，返回码非 0。
7. 步骤 7：步骤 4、5、6 三个拒绝场景的退出码非 0，步骤 3 合法场景的退出码为 0；不使用 `-verify_return_error` 时四个场景的退出码均为 0。
8. 步骤 8：两个端点已终止，工作目录已删除，端口不再监听。
