# TC-TR-0015-04 ｜ 异常场景容错

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0015（归档压缩与基础工具功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 基础命令行工具 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证损坏输入、权限不足、空间不足场景下提供合理错误，不误报成功、不损坏非目标文件。

## 前置条件

1. 已安装 tar、gzip、xz、zstd、coreutils。
2. 具备可写工作目录，且可挂载 tmpfs 制造空间不足场景（需 root 权限）。

## 测试步骤

1. 构造损坏的 tar 包并尝试解包：用相对路径归档 `a.txt` 生成完整归档，再截取其前 512 字节生成截断归档并解包；另创建一个不参与归档的 `bystander.txt`（内容为 `I am a bystander`）并记录其 md5，作为非目标文件的完整性基线。
2. 权限不足场景：在权限为 `555` 的目录中解包完整归档。
3. 空间不足场景：在 `sudo` 权限下挂载 1M 的 tmpfs，归档一个 8MB 文件后向其解包，并查看挂载点占用。
4. 损坏压缩包场景：分别生成 gzip、xz、zstd 包并各截取一半，对三个坏包执行完整性校验与解压。
5. 核对非目标文件完好性：重新计算 `bystander.txt` 的 md5 并与基线比对，查看其内容，同时记录归档成员 `a.txt` 的大小。
6. 清理：在 `sudo` 权限下卸载 tmpfs，再删除测试目录。

> 步骤 1 归档时使用相对路径，避免 tar 剥离前导 `/` 引入额外变量。
> 失败解包中被 tar 先创建后截断的归档成员（如 `a.txt` 变为 0 字节）是 GNU tar 的正常行为，不属于缺陷，也不作为"非目标文件"的校验对象。

## 预期结果

1. 步骤 1：解包失败，退出码非 0，提示 `tar: Unexpected EOF in archive` 与 `Error is not recoverable`。
2. 步骤 2：解包失败，退出码非 0，提示 `tar: a.txt: Cannot open: Permission denied`。
3. 步骤 3：解包失败，退出码非 0，提示写入不完整（`Wrote only ... bytes` 与 `Exiting with failure status`）；`df -h` 显示 tmpfs 已用 100%。
4. 步骤 4：三个 `-t` 校验与三个解压命令的退出码均为 1，且报错明确——`gzip` 为 `unexpected end of file`、`xz` 为 `Unexpected end of input`、`zstd` 为 `Read error (39) : premature end`；任一命令返回 0 即判失败。
5. 步骤 5：`bystander.txt` 的 md5 与基线一致，内容仍为 `I am a bystander`（非目标文件未受影响）。
6. 步骤 6：tmpfs 已卸载，测试目录已删除，无残留。
