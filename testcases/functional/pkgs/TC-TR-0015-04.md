# TC-TR-0015-04 ｜ 异常场景容错

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0015（归档压缩与基础工具功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 基础命令行工具 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证损坏输入、权限不足、空间不足场景下提供合理错误，不误报成功、不损坏非目标文件。

## 前置条件

1. 已安装 tar、gzip、xz、zstd、coreutils。
2. 具备可写工作目录，且可挂载 tmpfs 制造空间不足场景（需 root 权限）。

## 测试步骤

1. 构造损坏的 tar 包并尝试解包（使用**相对路径**归档，避免 tar 剥离前导 `/` 引入额外变量）：
   ```bash
   CASE_TMP=/tmp/tc-faulttol && rm -rf $CASE_TMP && mkdir -p $CASE_TMP
   echo data > $CASE_TMP/a.txt
   echo "I am a bystander" > $CASE_TMP/bystander.txt
   cd $CASE_TMP && md5sum bystander.txt > bystander.md5
   tar -cf good.tar a.txt
   head -c 512 $CASE_TMP/good.tar > $CASE_TMP/bad.tar
   tar -xf $CASE_TMP/bad.tar -C $CASE_TMP; echo "bad-tar:$?"
   ```
   > 说明：`bystander.txt` 不进入归档，作为"非目标文件"的完整性基准。
2. 权限不足场景（向无写权限目录解包）：
   ```bash
   mkdir -p $CASE_TMP/nowrite && chmod 555 $CASE_TMP/nowrite
   tar -xf $CASE_TMP/good.tar -C $CASE_TMP/nowrite; echo "nowrite:$?"
   ```
3. 空间不足场景（挂载 1M tmpfs 后解包超大文件）：
   ```bash
   sudo mkdir -p /mnt/tiny && sudo mount -t tmpfs -o size=1M tmpfs /mnt/tiny && sudo chmod 777 /mnt/tiny
   dd if=/dev/zero of=$CASE_TMP/big.bin bs=1M count=8 status=none
   cd $CASE_TMP && tar -cf big.tar big.bin
   tar -xf $CASE_TMP/big.tar -C /mnt/tiny; echo "nospace:$?"
   df -h /mnt/tiny
   sudo umount /mnt/tiny && sudo rmdir /mnt/tiny
   ```
4. 损坏的压缩包场景（gzip / xz / zstd 截断后的校验与解压）：
   ```bash
   cd $CASE_TMP
   echo "case data" > only.txt
   gzip -kf only.txt; xz -kf only.txt; zstd -qf only.txt
   for f in only.txt.gz only.txt.xz only.txt.zst; do
     sz=$(stat -c %s "$f"); head -c $((sz/2)) "$f" > "bad.${f##*.}"
   done
   gzip -t bad.gz;   echo "gzip-t:$?"
   xz -t bad.xz;     echo "xz-t:$?"
   zstd -t bad.zst;  echo "zstd-t:$?"
   gzip -dc bad.gz   > /dev/null; echo "gunzip:$?"
   xz -dc bad.xz     > /dev/null; echo "unxz:$?"
   zstd -dc bad.zst  > /dev/null; echo "unzstd:$?"
   ```
5. 核对非目标文件完好性（并记录归档成员在失败解包后的状态）：
   ```bash
   cd $CASE_TMP && md5sum -c bystander.md5
   cat $CASE_TMP/bystander.txt
   stat -c 'a.txt size=%s' $CASE_TMP/a.txt
   ```
6. 清理测试数据：
   ```bash
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：损坏 tar 解包失败，返回非 0 退出码（实测为 `2`），提示 `tar: Unexpected EOF in archive` 与 `Error is not recoverable`。
2. 步骤 2：无写权限解包失败，返回非 0（实测为 `2`），提示 `tar: a.txt: Cannot open: Permission denied`。
3. 步骤 3：
   - 解包失败，返回非 0 退出码，提示写入不完整（形如 `Wrote only ... bytes` 并 `Exiting with failure status`）；
   - `df -h` 显示 tmpfs 已用 100%。
4. 步骤 4：六个命令（三个 `-t` 与三个解压）**退出码均为 `1`**，且报错明确：
   - `gzip`：`gzip: bad.gz: unexpected end of file`
   - `xz`：`xz: bad.xz: Unexpected end of input`
   - `zstd`：`bad.zst : Read error (39) : premature end`

   且**不得误报成功**（任一命令返回 0 即判失败）。
5. 步骤 5：`md5sum -c` 输出 `bystander.txt: OK`，`bystander.txt` 内容仍为 `I am a bystander`（**非目标文件未受影响**）。
   > 注意：归档成员 `a.txt` 在步骤 1 的失败解包中已被 tar 创建并截断为 0 字节（实测 size 由 `5` 变为 `0`），这是 GNU tar 先建文件后写入的正常行为，**不属于缺陷**，不应作为非目标文件校验对象。
6. 步骤 6：测试数据清理完毕。
