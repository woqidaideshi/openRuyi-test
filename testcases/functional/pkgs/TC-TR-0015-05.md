| 字段 | 值 |

## 描述

验证 util-linux 纳入范围的基础工具（设备/挂载查询、数据处理、文件锁、权限控制）执行结果与退出码符合预期。

> 注意，`uuidgen` 与 `logger` 上游属 util-linux 项目，但在 openRuyi 的包拆分中分别由 `libuuid` 与 `inetutils` 提供，因此 `uuidgen` 与 `logger` 未纳入本用例。

## 前置条件

1. 已安装 util-linux（含 `lsblk`、`findmnt`、`blkid`、`lscpu`、`hexdump`、`column`、`flock`、`fallocate`、`mount`、`umount`）。
2. 已存在具备 sudo 权限的普通用户（如 `openruyi`），用于验证权限控制。
3. 具备可写工作目录。

## 测试步骤

1. 查看 `util-linux` 包版本，并确认 `lsblk`、`findmnt`、`blkid`、`lscpu`、`hexdump`、`column`、`flock`、`fallocate`、`mount`、`umount` 十个命令均存在。
2. 系统信息类只读查询：执行 `lscpu` 查看架构、字节序与 CPU 数，执行 `lsblk -dno NAME` 列出磁盘，执行 `findmnt -n -o SOURCE,TARGET,FSTYPE /` 查看根文件系统。
3. 设备与挂载属性查询：执行 `blkid` 列出已识别设备的属性，执行 `findmnt -t vfat` 查看 vfat 挂载点。
4. 数据处理类工具：用 `hexdump -C` 查看文本的十六进制表示，用 `column -t` 对齐列，用 `fallocate -l 1M` 预分配文件后用 `stat` 查看 size 与 blocks。
5. 文件锁互斥：用 `flock -n` 对同一文件加锁，再启动第二个进程尝试加锁。
6. 权限控制：以普通用户 `openruyi` 身份尝试 `mount` 与 `umount`。
7. 清理：删除测试文件。

## 预期结果

1. 步骤 1：`rpm -q util-linux` 返回版本；十个命令的路径均存在（无 `MISSING`）。
2. 步骤 2：`lscpu` 输出架构、字节序与 CPU 数；`lsblk -dno NAME` 列出全部磁盘且含系统盘；`findmnt` 输出根文件系统的源设备、挂载点与类型；三者退出码均为 0。
3. 步骤 3：`blkid` 列出 `UUID`/`TYPE`/`LABEL` 等属性；`findmnt -t vfat` 输出 vfat 挂载点；退出码为 0。
4. 步骤 4：`hexdump -C` 输出与文件内容逐字节对应；`column -t` 按列对齐；`fallocate -l 1M` 退出码为 0，`stat` 显示 `size=1048576` 且 `blocks` 非 0（已真实分配）。
5. 步骤 5：第一次加锁成功；第二个进程加锁返回非 0，排他锁生效。
6. 步骤 6：两条命令均被拒绝，退出码均为 `32`，并提示 `must be superuser to use mount` / `must be superuser to unmount`；`findmnt /mnt` 无输出，未发生实际挂载。
7. 步骤 7：测试文件已删除，无残留。
