# TC-TR-0015-05 ｜ util-linux 基础工具

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0015（归档压缩与基础工具功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 基础命令行工具 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 util-linux 纳入范围的基础工具（设备/挂载查询、数据处理、文件锁、权限控制）执行结果与退出码符合预期。

## 范围说明

需求 TR-0015 的修订项 **D3（"纳入范围的文件操作"清单：coreutils/util-linux 命令与参数矩阵）尚未闭环**。本用例先覆盖**只读查询**、**无破坏性写入**、**文件锁**与**权限控制**四类；`mount`/`umount` 仅验证"非 root 被拒绝"，**不执行任何真实挂载/分区/擦除操作**。

> 另需注意：`uuidgen` 实际由 `libuuid` 包提供、`logger` 由 `inetutils` 包提供，二者**不属于 util-linux 包**，因此未纳入本用例。

## 前置条件

1. 已安装 util-linux（含 `lsblk`、`findmnt`、`blkid`、`lscpu`、`hexdump`、`column`、`flock`、`fallocate`、`mount`、`umount`）。
2. 已存在具备 sudo 权限的普通用户（如 `openruyi`），用于验证权限控制。
3. 具备可写工作目录（如 `/tmp`）。

## 测试步骤

1. 确认版本与命令可用性：
   ```bash
   rpm -q util-linux
   for c in lsblk findmnt blkid lscpu hexdump column flock fallocate mount umount; do
     printf '%-10s %s\n' "$c" "$(command -v "$c" || echo MISSING)"
   done
   ```
2. 系统信息类查询（只读）：
   ```bash
   lscpu | grep -E '^(Architecture|Byte Order|CPU\(s\))'
   lsblk -dno NAME | sort
   findmnt -n -o SOURCE,TARGET,FSTYPE /
   ```
3. 设备与挂载属性查询（只读）：
   ```bash
   blkid | head -3
   findmnt -n -o SOURCE,TARGET,FSTYPE -t vfat
   ```
4. 数据处理类工具（无破坏性写入）：
   ```bash
   CASE_TMP=/tmp/tc-utillinux && rm -rf $CASE_TMP && mkdir -p $CASE_TMP
   printf 'ABC\n' > $CASE_TMP/hex.txt
   hexdump -C $CASE_TMP/hex.txt
   printf 'a b c\nlonger x y\n' > $CASE_TMP/cols.txt
   column -t $CASE_TMP/cols.txt
   fallocate -l 1M $CASE_TMP/alloc.bin
   stat -c 'size=%s blocks=%b' $CASE_TMP/alloc.bin
   ```
5. 文件锁互斥（flock）：
   ```bash
   exec 9>$CASE_TMP/lockfile
   flock -n 9 && echo "first_lock=ok"
   bash -c "exec 9>$CASE_TMP/lockfile; flock -n 9; echo second_lock_rc=\$?"
   exec 9>&-
   ```
6. 权限控制（非 root 挂载/卸载）：
   ```bash
   sudo -u openruyi mount -t tmpfs tmpfs /mnt; echo "mount_rc=$?"
   sudo -u openruyi umount /boot/efi; echo "umount_rc=$?"
   ```
7. 清理测试数据：
   ```bash
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：`rpm -q util-linux` 返回版本（实测 `util-linux-2.41.3-11.40.or.riscv64`），10 个命令路径均非 `MISSING`。
2. 步骤 2：
   - `lscpu` 输出 `Architecture: riscv64`、`Byte Order: Little Endian`、`CPU(s): 64`（实测值，以机器实际为准）；
   - `lsblk -dno NAME` 列出全部磁盘（实测 `mmcblk0 mmcblk0boot0 mmcblk0boot1 mmcblk1 nvme0n1`）；
   - `findmnt` 输出根文件系统（实测 `/dev/nvme0n1p2 / xfs`），三者退出码均为 0。
3. 步骤 3：`blkid` 列出已识别设备的 `UUID`/`TYPE`/`LABEL` 等属性，`findmnt -t vfat` 输出 vfat 挂载点，退出码为 `0`。
4. 步骤 4：
   - `hexdump -C` 输出与内容完全对应，实测：
     ```
     00000000  41 42 43 0a                                       |ABC.|
     00000004
     ```
   - `column -t` 按列对齐输出，实测：`a       b  c` / `longer  x  y`；
   - `fallocate -l 1M` 退出码为 0，`stat` 显示 `size=1048576 blocks=2048`（1 MiB 且实际分配）。
5. 步骤 5：第一次加锁输出 `first_lock=ok`；**第二个进程加锁失败**，输出 `second_lock_rc=1`（非 0），证明排他锁生效。
6. 步骤 6：两者均被拒绝，退出码均为 **`32`**，且提示明确：
   ```
   mount: /mnt: must be superuser to use mount.
   umount: /boot/efi: must be superuser to unmount.
   ```
   并须确认**未发生实际挂载**：`findmnt /mnt` 无输出。
7. 步骤 7：测试数据清理完毕。

## 已知问题 / 易错点（2026-11-10 在 riscv64 物理机实测）

1. **`mount`/`umount` 的拒绝退出码是 `32`**，不是 `1`（`EXIT_FAILURE` 之外的 mount 专用码）。判定时不要按"非 0"泛化，建议直接比对 `32`。
2. **`findmnt` 传多个路径不会逐行输出**：`findmnt -n -o SOURCE,TARGET,FSTYPE / /boot/efi` 返回空。应按类型或用 `--target` 分别查询：
   ```bash
   findmnt -n -o SOURCE,TARGET,FSTYPE /
   findmnt -n -o SOURCE,TARGET,FSTYPE -t vfat
   ```
3. **`dmesg` 在本镜像上未受限**（`kernel.dmesg_restrict = 0`），普通用户可执行（`rc=0`）。若用它验证"权限控制"，需先确认该 sysctl 值，否则会误判。
4. **`uuidgen` 与 `logger` 不属 util-linux**（分别为 `libuuid`、`inetutils`），统计"util-linux 覆盖度"时不要计入。
5. 本用例**不含破坏性操作**；`fdisk`/`sfdisk`/`wipefs`/`mkfs` 类工具需配合专用测试盘单独设计用例，避免误伤系统盘或固件分区。
