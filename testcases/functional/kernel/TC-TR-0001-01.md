# TC-TR-0001-01 ｜ 内核更新后原内核保留、系统持续可用

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0001（内核更新不会移除当前使用的内核以及模块） |
| 测试类型 | 功能测试 |
| 功能模块 | 内核与引导 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证更新内核后，更新前运行的内核软件包、映像、配套模块及引导项完整保留，未重启时系统继续运行原内核且关键功能正常。

## 前置条件

1. 已安装产品默认配置的 Linux 内核，且当前运行内核非最新版本。
2. 网络可达 dnf 仓库。
3. `/boot/efi` 空间充足，剩余空间不少于 100 MB（`df -h /boot/efi`）；若不足，先删除一个**非当前运行版本**的内核释放空间（`dnf remove linux-<版本>`），**不得删除 `uname -r` 对应的内核**。
4. 具备 root 权限（sudo）。

## 测试步骤

1. 查看可升级的 `linux` 内核包。
2. 记录当前运行内核版本 `uname -r`（记作 `<version>`），并记录 `<version>` 对应的内核相关包清单（`rpm -qa | grep linux | grep "<version>"`）。
3. 执行内核更新：`sudo dnf update linux`。
4. 再次列出 `<version>` 对应的内核相关包清单，与步骤 2 比对。
5. 查看引导器配置中 `<version>` 的引导项（`/boot/efi/loader/entries/` 下文件名含 `<version>` 的 `.conf`）。
6. 查看 `<version>` 的内核映像 `linux` 与 `initrd`（位于 ESP 顶层以 `<version>` 命名的目录中）。
7. 查看 `/usr/lib/modules/<version>` 下的驱动模块文件。
8. 加载与卸载内核模块：加载内核模块 `dummy` 后查看内核模块列表，再卸载该模块后再次查看内核模块列表。

## 预期结果

1. 步骤 1：输出可升级的内核版本号，说明存在可更新内核。
2. 步骤 2：`<version>` 与对应包清单均已记录。
3. 步骤 3：更新完成并安装新内核，无报错。
4. 步骤 4：包清单与步骤 2 一致，旧内核包未被移除。
5. 步骤 5：存在 `<version>` 对应的 `.conf` 引导项。
6. 步骤 6：`linux` 与 `initrd` 两个文件均存在，且大小不为 0。
7. 步骤 7：`/usr/lib/modules/<version>` 下存在驱动模块文件。
8. 步骤 8：加载后内核模块列表中包含 `dummy`，卸载后列表不再包含 `dummy`。
