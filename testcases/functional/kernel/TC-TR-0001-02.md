# TC-TR-0001-02 ｜ 使用旧内核重启后功能正常

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0001（内核更新不会移除当前使用的内核以及模块） |
| 测试类型 | 功能测试 |
| 功能模块 | 内核与引导 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证内核更新后重启时，引导菜单中旧内核引导项仍存在，选择旧内核可正常启动，登录后运行内核为旧内核且关键功能正常。

## 前置条件

1. 已完成内核更新且系统未重启，当前运行内核仍为旧内核。

## 测试步骤

1. 记录当前（旧）内核版本号：`uname -r`，记作 `<version>`。
2. 重启系统：`sudo reboot`。
3. 进入引导菜单，查看其中的旧内核引导项。
4. 选择旧内核（`<version>`）引导项启动。
5. 登录系统，查看当前运行内核版本：`uname -r`。
6. 验证关键功能（加载一个未加载的内核模块）：
   1. 加载测试模块：`sudo modprobe dummy`
   2. 查看模块加载状态：`lsmod | grep '^dummy'`
   3. 卸载并确认：`sudo modprobe -r dummy`，再执行 `lsmod | grep '^dummy'`

## 预期结果

1. 步骤 2：系统重启并进入引导菜单。
2. 步骤 3：引导菜单中存在旧内核（`<version>`）引导项。
3. 步骤 4：旧内核成功启动并进入系统。
4. 步骤 5：`uname -r` 输出为 `<version>`（旧内核版本）。
5. 步骤 6：
   1. `sudo modprobe dummy` 无报错（退出码为 0）。
   2. `lsmod | grep '^dummy'` 非空。
   3. `sudo modprobe -r dummy` 退出码为 0，且 `lsmod | grep '^dummy'` 变为空。
