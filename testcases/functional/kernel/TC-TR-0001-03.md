# TC-TR-0001-03 ｜ 触发内核保留上限清理时最旧运行内核保留

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0001（内核更新不会移除当前使用的内核以及模块） |
| 测试类型 | 功能测试 |
| 功能模块 | 内核与引导 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证更新内核触发内核版本保留上限清理时，运行中的最旧内核软件包、映像、配套模块及引导项完整保留，未重启时系统继续运行原内核且关键功能正常，被清理的是超过保留上限的其它旧内核。

## 前置条件

1. 已安装多个内核版本，达到产品默认的内核保留上限（再更新一次即触发清理）。
2. 当前运行内核为已安装的最旧版本。
3. 网络可达 dnf 仓库。
4. `/boot` 分区空间充足，可容纳新增内核。

## 测试步骤

1. 查看可升级的内核版本（确认存在可更新内核）：
   ```bash
   dnf check-update linux 2>/dev/null | grep '^linux\.' | awk '{print $2}'
   ```
2. 记录更新前内核版本与内核相关包清单：
   ```bash
   uname -r                              # 当前运行内核版本，记作 <version>（即已安装最旧版本）
   rpm -qa | grep linux | grep "<version>" # 当前运行内核对应的内核相关包清单
   rpm -qa 'linux*' | sort                 # 全部内核相关包清单（按版本排序，识别最旧/次旧等）
   ```
3. 执行内核更新，触发保留上限清理：`sudo dnf update linux`，等待完成。
4. 查看更新后的全部内核相关包清单（与步骤 2 对比）：
   ```bash
   rpm -qa 'linux*' | sort
   ```
5. 查看运行内核相关包列表：
   ```bash
   rpm -qa | grep linux | grep "<version>"
   ```
6. 查看引导器配置中的运行内核引导项：
   ```bash
   find /boot/efi/loader/entries/ -name "*<version>.conf"
   ```
7. 查看运行内核映像文件（EFI 目录下的 `linux` 与 `initrd`）：
   ```bash
   find /boot/ -type d -name "<version>" -print -exec ls -la {} \;
   ```
8. 查看运行内核模块：
   ```bash
   find /usr/lib/modules/<version> -name '*.ko*' | head
   ```
9. 验证运行内核关键功能（加载一个未加载的内核模块）：
   1. 查看 kvm 模块当前加载状态：`lsmod | grep kvm`
   2. 加载 kvm 模块：`sudo modprobe kvm`
   3. 再次查看 kvm 模块加载状态：`lsmod | grep kvm`

## 预期结果

1. 步骤 1：输出可升级的内核版本（存在可更新内核）。
2. 步骤 3：更新完成，安装了新内核，退出码为 0。
3. 步骤 4：与步骤 2 清单对比，触发保留上限清理：被移除的是超过上限的非运行旧内核（如次旧版本），运行中的最旧内核（`<version>`）相关包仍在；新内核新增。
4. 步骤 5：运行内核相关包清单与步骤 2 一致，未被移除。
5. 步骤 6：存在匹配 `*<version>.conf` 的引导项。
6. 步骤 7：`<version>` 目录存在，且含 `linux`、`initrd` 两个文件。
7. 步骤 8：`/usr/lib/modules/<version>` 下存在 `.ko*` 模块文件（非空）。
8. 步骤 9：
   1. `lsmod | grep kvm` 初始为空。
   2. `sudo modprobe kvm` 无报错（退出码为 0）。
   3. 再次 `lsmod | grep kvm` 非空。
