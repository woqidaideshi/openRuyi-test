# TC-TR-0001-03 ｜ 触发内核保留上限清理时最旧运行内核保留

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0001（内核更新不会移除当前使用的内核以及模块） |
| 测试类型 | 功能测试 |
| 功能模块 | 内核与引导 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证更新内核触发内核版本保留上限清理时，运行中的最旧内核软件包、映像、配套模块及引导项完整保留，未重启时系统继续运行原内核且关键功能正常，被清理的是超过保留上限的其它旧内核。

## 前置条件

1. 已安装多个内核版本，达到产品默认的内核保留上限（再更新一次即触发清理）。
2. 当前运行内核为已安装的最旧版本。
3. 网络可达 dnf 仓库。
4. `/boot/efi` 空间充足，剩余空间不少于 100 MB。
5. 具备 root 权限（sudo）。

## 测试步骤

1. 查看可升级的 `linux` 内核包，并记录当前运行内核版本 `uname -r`（记作 `<version>`，即已安装的最旧版本）。
2. 记录全部内核相关包清单（`rpm -qa 'linux*' | sort`），识别最旧与次旧版本。
3. 执行内核更新，触发保留上限清理：`sudo dnf update linux`。
4. 再次列出全部内核相关包清单，与步骤 2 比对。
5. 查看 `<version>` 对应的内核相关包。
6. 查看引导器配置中 `<version>` 的引导项（`/boot/efi/loader/entries/` 下文件名含 `<version>` 的 `.conf`）。
7. 查看 `<version>` 的内核映像 `linux` 与 `initrd`（位于 ESP 顶层以 `<version>` 命名的目录中）。
8. 查看 `/usr/lib/modules/<version>` 下的驱动模块文件。
9. 加载与卸载内核模块：加载内核模块 `dummy` 后查看内核模块列表，再卸载该模块后再次查看内核模块列表。

## 预期结果

1. 步骤 1：输出可升级的内核版本号；当前运行内核为已安装的最旧版本。
2. 步骤 2：得到完整的内核包清单，可区分最旧与次旧版本。
3. 步骤 3：更新完成并安装新内核，无报错。
4. 步骤 4：
   - 新内核已新增；
   - 被移除的是超过保留上限的非运行旧内核（如次旧版本）；
   - 运行中的最旧内核（`<version>`）包仍在。
5. 步骤 5：`<version>` 的包清单与步骤 2 一致，未被移除。
6. 步骤 6：引导器配置中仍有 `<version>` 对应的引导项。
7. 步骤 7：`linux` 与 `initrd` 两个文件均存在，且大小不为 0。
8. 步骤 8：`/usr/lib/modules/<version>` 下存在驱动模块文件。
9. 步骤 9：加载后内核模块列表中包含 `dummy`，卸载后列表不再包含 `dummy`。
