# TC-TR-0002-01 ｜ 内核更新后新内核安装完整、引导项生成

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0002（内核更新后增加对应引导项） |
| 测试类型 | 功能测试 |
| 功能模块 | 内核与引导 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证更新内核后，新内核软件包、映像、配套模块及引导项安装完整。

## 前置条件

1. 已安装产品默认配置的 Linux 内核，且当前运行内核非最新版本。
2. 网络可达 dnf 仓库。
3. `/boot/efi` 空间充足，剩余空间不少于 100 MB（`df -h /boot/efi`）；若不足，先删除一个**非当前运行版本**的内核释放空间（`dnf remove linux-<版本>`），**不得删除 `uname -r` 对应的内核**。
4. 具备 root 权限（sudo）。

## 测试步骤

1. 查看可升级的内核包，记下将要安装的版本（记作 `<新版本>`）。
2. 执行内核更新：`sudo dnf update linux`。
3. 查看更新后已安装的最新内核版本（`rpm -q --qf '%{version}-%{release}\n' linux | sort -V | tail -1`），记作 `<version>`。
4. 查看 `<version>` 对应的内核相关包清单（`rpm -qa | grep linux | grep "<version>"`）。
5. 查看 `<version>` 的内核映像 `linux` 与 `initrd`（位于 ESP 顶层以 `<version>` 命名的目录中）。
6. 查看 `/usr/lib/modules/<version>` 下的驱动模块。
7. 查看引导器配置中 `<version>` 的引导项（`/boot/efi/loader/entries/` 下文件名含 `<version>` 的 `.conf`）。

## 预期结果

1. 步骤 1：输出可升级的内核版本号。
2. 步骤 2：更新完成，无报错。
3. 步骤 3：`<version>` 与步骤 1 记录的 `<新版本>` 一致。
4. 步骤 4：内核本体与配套子包（如 `linux-core`、`linux-modules`、`linux-dtbs`）均已安装。
5. 步骤 5：`linux` 与 `initrd` 两个文件均已生成，且大小不为 0。
6. 步骤 6：`/usr/lib/modules/<version>` 下存在驱动模块文件。
7. 步骤 7：引导器配置中已生成 `<version>` 对应的引导项。
