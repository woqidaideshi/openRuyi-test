# TC-TR-0026-01 ｜ gdb 基础调试

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0026（调试与追踪工具功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 调试与追踪 |
| 优先级 | P2 |
| 覆盖设备 | KVM (RVA20/RVA23) |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 gdb 启动调试、断点、单步、变量查看与调用栈回溯等操作正常，无残留。

## 前置条件

1. 已安装 gdb、gcc。

## 测试步骤

1. 确认 gdb 可用：执行 `gdb --version`。
2. 编写含函数调用的 C 程序，内容如下：
   ```bash
   #include <stdio.h>
   int add(int a, int b) { return a + b; }
   int main(void) {
       int x = add(1, 2);
       int y = x * 2;
       printf("%d\n", y);
       return 0;
   }
   ```
2. 以调试信息编译：执行 `gcc -g -o gdb-demo gdb-demo.c`。
3. 设置断点并查看参数与调用栈：执行 `gdb -batch -ex 'break add' -ex run -ex 'print a' -ex 'print b' -ex bt -ex finish ./gdb-demo`。
4. 在 `main` 函数内单步并查看变量：执行 `gdb -batch -ex 'break main' -ex run -ex 'next' -ex 'print x' -ex 'next' -ex 'print y' ./gdb-demo`。
5. 确认无被调试进程与调试器残留：执行 `pgrep -x gdb-demo` 与 `pgrep -x gdb`。
6. 清理：删除 `gdb-demo` 与 `gdb-demo.c`。

## 预期结果

1. 步骤 1：输出版本号。
2. 步骤 2：源文件 `gdb-demo.c` 生成，含 `add` 函数与 `main` 函数。
3. 步骤 3：编译成功，退出码为 0，生成可执行文件 `gdb-demo`。
4. 步骤 4：断点命中于 `add`，输出 `Breakpoint 1, add (a=1, b=2) at gdb-demo.c:2`；`print a`/`print b` 分别输出 `1`、`2`；`bt` 输出 `#0` 为 `add`、`#1` 为 `main` 两行栈帧；`finish` 显示函数返回值为 `3`。
5. 步骤 5：第一次 `next` 后 `print x` 输出 `3`；第二次 `next` 后 `print y` 输出 `6`。
6. 步骤 6：两条 `pgrep` 均无输出（退出码 1），无残留的被调试进程与 gdb 进程。
7. 步骤 7：测试产物清理完毕。
