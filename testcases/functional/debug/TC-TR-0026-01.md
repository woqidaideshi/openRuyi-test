# TC-TR-0026-01 ｜ gdb 基础调试

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0026（调试与追踪工具功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 调试与追踪 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 gdb 启动调试、断点、单步、变量查看与调用栈回溯等操作正常，无残留。

## 前置条件

1. 已安装 gdb、gcc。
2. 具备可写工作目录（如 `/tmp`）。

## 测试步骤

1. 编写含函数调用的 C 程序并以调试信息编译：
   ```bash
   CASE_TMP=/tmp/tc-gdb && mkdir -p $CASE_TMP
   cat > $CASE_TMP/gdb-demo.c <<'EOF'
   #include <stdio.h>
   int add(int a, int b) { return a + b; }
   int main(void) {
       int x = add(1, 2);
       printf("%d\n", x);
       return 0;
   }
   EOF
   gcc -g -o $CASE_TMP/gdb-demo $CASE_TMP/gdb-demo.c
   ```
2. 使用 gdb 批量执行断点命中、参数查看与调用栈回溯：
   ```bash
   gdb -batch -ex 'break add' -ex run -ex 'print a' -ex 'print b' -ex bt -ex finish $CASE_TMP/gdb-demo
   ```
   > 注意：断点命中函数入口后**不要**立即执行 `next`——`add` 为单行函数，`next` 会直接跨出函数，导致 `a`/`b` 超出作用域无法打印。应先 `print`/`bt`，再用 `finish` 运行至函数返回。
3. 在 `main` 函数内对变量 `x` 做单步与查看验证：
   ```bash
   gdb -batch -ex 'break 4' -ex run -ex 'next' -ex 'print x' -ex 'info frame' $CASE_TMP/gdb-demo
   ```
4. 确认无被调试进程残留：
   ```bash
   pgrep -f gdb-demo || true
   ```
5. 清理测试目录：
   ```bash
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：编译成功，退出码为 0。
2. 步骤 2：断点正常命中（输出 `Breakpoint 1, add (a=1, b=2)`），`print a`/`print b` 分别显示 `$1 = 1`、`$2 = 2`，`bt` 输出至少包含 `add` 与 `main` 两级栈帧，`finish` 显示 `Value returned is $3 = 3`。
3. 步骤 3：`next` 单步后 `print x` 显示 `$1 = 3`，`info frame` 显示当前栈帧位于 `main`。
4. 步骤 4：`pgrep` 无输出（无残留被调试进程）。
5. 步骤 5：测试产物清理完毕。
