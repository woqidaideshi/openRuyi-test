# TC-TR-0026-04 ｜ 调试工具异常与诊断

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0026（调试与追踪工具功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 调试与追踪 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 gdb、strace、valgrind 在权限不足与无效输入下给出明确诊断，且无非预期崩溃、卡死与被调试进程残留。

## 前置条件

1. 已安装 `gdb`、`strace`、`valgrind`。
2. 以非 root 普通账号 `openruyi` 执行本用例全部命令，系统中存在属于 root 的进程（如进程号 1 的 init），`openruyi` 附加非自身进程受权限限制。
3. `valgrind` 仅在 RVA20 平台要求；非 RVA20 平台跳过步骤 2、4、5 中的 `valgrind` 命令及对应判据。

## 测试步骤

1. 确认 `openruyi` 未获 `CAP_SYS_PTRACE`：执行 `grep CapEff /proc/self/status`。
2. 正向对照，用三个工具分别运行无错误的 `/bin/true`，执行以下命令：
    - `gdb -batch -ex run /bin/true`
    - `strace -o /dev/null /bin/true`
    - `valgrind --error-exitcode=1 /bin/true`
3. 附加 root 进程，执行以下命令：
    - `gdb -batch -p 1`
    - `strace -p 1`
4. 对不存在的可执行文件调用三个工具，执行以下命令：
    - `gdb -batch ./no-such-file`
    - `strace ./no-such-file`
    - `valgrind ./no-such-file`
5. 对不受支持的参数调用三个工具，执行以下命令：
    - `gdb -batch -ex 'nosuchcommand' /bin/true`
    - `strace -e trace=nosuchsyscall /bin/true`
    - `valgrind --tool=nosuchtool /bin/true`
6. 确认无残留进程：执行 `pgrep -x gdb`、`pgrep -x strace` 与 `pgrep -x valgrind`。

## 预期结果

1. 步骤 1：`CapEff` 中 `0x80000` 位即 `CAP_SYS_PTRACE` 未置位，典型值为 `CapEff: 0000000000000000`；若该位置位，记录为环境不满足，跳过本用例。
2. 步骤 2：三个工具均正常执行，退出码均为 0。
3. 步骤 3：`gdb` 与 `strace` 均提示权限被拒绝，提示文案为 `Operation not permitted`，退出码均为 1；两条命令均秒级返回，无挂起。
4. 步骤 4：三个工具均提示目标文件不存在
    - `gdb` 提示 `No such file or directory` 且退出码为 1；
    - `strace` 提示 `Cannot stat` 且退出码为 1；
    - `valgrind` 提示 `No such file or directory` 且退出码为 127。
5. 步骤 5：三个工具均提示选项不受支持，且退出码均为 1
    - `gdb` 提示 `Undefined command`；
    - `strace` 提示 `invalid system call`；
    - `valgrind` 提示 `failed to start tool`。
6. 步骤 6：三条 `pgrep` 均无输出，退出码为 1；全程无 `Segmentation fault`，无 core dump 产生。
