# TC-TR-0026-03 ｜ valgrind 内存检测

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0026（调试与追踪工具功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 调试与追踪 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 valgrind 在目标平台识别预设的非法访问、未初始化值使用及内存泄漏。

## 前置条件

1. 已安装 valgrind、gcc（valgrind 仅对 rva20 平台要求，rva23 平台不适用）。
2. 具备可写工作目录（如 `/tmp`）。
3. valgrind 在 riscv64 上依赖 `glibc-debuginfo` 提供的 `ld.so` 符号表，需确认 `glibc-debuginfo` 与 `glibc` **为同一次构建产出**：
   ```bash
   rpm -q --qf 'glibc          = %{VERSION}-%{RELEASE}\n' glibc
   rpm -q --qf 'glibc-debuginfo= %{VERSION}-%{RELEASE}\n' glibc-debuginfo
   ```
   两者版本串必须完全一致；若不一致，valgrind 将无法启动（见文末"已知问题"）。

## 测试步骤

1. 确认 valgrind 可用：
   ```bash
   valgrind --version
   ```
2. 编写并编译含非法写、未初始化值使用、内存泄漏的检测用例：
   ```bash
   cat > /tmp/valgrind-demo.c <<'EOF'
   #include <stdlib.h>
   int main(void) {
       int *p = NULL;
       *p = 1;              /* 非法写 */
       int x; if (x) {}      /* 未初始化使用 */
       int *q = malloc(10); /* 泄漏（未释放） */
       (void)q;
       return 0;
   }
   EOF
   gcc -g -o /tmp/valgrind-demo /tmp/valgrind-demo.c
   ```
3. 运行 valgrind 内存检测并记录退出码：
   ```bash
   valgrind --leak-check=full --error-exitcode=1 /tmp/valgrind-demo
   echo $?
   ```
4. 若 valgrind 因平台符号重定向失败（见文末"已知问题"），改用 AddressSanitizer 完成等价内存错误检测：
   ```bash
   gcc -g -fsanitize=address -o /tmp/valgrind-demo-asan /tmp/valgrind-demo.c
   /tmp/valgrind-demo-asan
   echo $?
   ```
5. 清理测试产物：
   ```bash
   rm -f /tmp/valgrind-demo /tmp/valgrind-demo.c /tmp/valgrind-demo-asan
   ```

## 预期结果

1. 步骤 1：`valgrind --version` 正常输出版本信息（如 `valgrind-3.27.0`）。
2. 步骤 3：valgrind 分别报出 `Invalid write`、`Conditional jump or move depends on uninitialised value`、`definitely lost`，错误类别与预设一致；因指定 `--error-exitcode=1`，退出码为 1。
3. 步骤 4（降级路径）：AddressSanitizer 报出 `SEGV on unknown address` 等非法访问错误，进程以非 0 状态退出。
4. 步骤 5：测试产物清理完毕。

## 已知问题（2026-11-10 在 riscv64 物理机实测）

**现象**：安装 `valgrind-3.27.0-8.16.or.riscv64` 后，对任意程序运行 `valgrind` 立即报致命错误并退出（退出码 1）：

```
valgrind:  Fatal error at startup: a function redirection
valgrind:  which is mandatory for this platform-tool combination
valgrind:  cannot be set up.  Details of the redirection are:
valgrind:  A must-be-redirected function
valgrind:  whose name matches the pattern:      strcmp
valgrind:  in an object with soname matching:   ld-linux-riscv64-lp64d.so.1
valgrind:  was not found whilst processing
valgrind:  symbols from the object with soname: ld-linux-riscv64-lp64d.so.1
```

**实测根因（两处缺陷叠加）**：

1. **`glibc-debuginfo` 与 `glibc` 版本/构建不一致**（打包缺陷）：

   | 包 | 版本 |
   |---|---|
   | `glibc` | `2.44-22.1.or.riscv64` |
   | `glibc-debuginfo` | `2.44+git20261107.c5c6fc6f449d-26.1.or.riscv64` |

   `glibc-debuginfo` 的 debug 文件与被调试的 `/usr/lib/ld-linux-riscv64-lp64d.so.1` 并非同一次构建，即使安装后 valgrind 依然无法关联符号表。
2. **`ld.so` 符号缺失**：即使已安装 `glibc-debuginfo`，其 debug 文件 `.symtab` 含 410 个 `FUNC` 符号，但 **不含 `strcmp`**；同时 `ld.so` 的 `.dynsym` 仅导出 38 个符号，亦不含 `strcmp`。valgrind riscv64 后端要求该重定向必须成立。

**规避方案**：

- 短期：使用步骤 4 的 AddressSanitizer/LeakSanitizer 完成等价的内存错误检测。
- 长期（需厂商修复）：(a) 重新打包 `glibc-debuginfo`，确保与 `glibc` 同源同版本；(b) 让 `ld.so` 以标准调用约定导出 `strcmp`（或以非 strip 方式提供符号），使 valgrind 重定向可建立。

**复现命令**：

```bash
sudo dnf install -y valgrind glibc-debuginfo
printf 'int main(void){return 0;}\n' > /tmp/vg.c && gcc -o /tmp/vg /tmp/vg.c
valgrind /tmp/vg   # 必然失败：strcmp redirection cannot be set up
```
