# TC-TR-0026-03 ｜ valgrind 内存检测

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0026（调试与追踪工具功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 调试与追踪 |
| 优先级 | P2 |
| 覆盖设备 | KVM (RVA20) |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 valgrind 在 RVA20 平台检测程序的非法内存访问、未初始化值使用与内存泄漏，并输出对应诊断。

## 前置条件

1. 已安装 valgrind 与 gcc。
2. 目标平台为 RVA20，本用例仅在 RVA20 平台执行。

## 测试步骤

1. 确认 valgrind 可用：执行 `valgrind --version`。
2. 编写含非法写、未初始化值使用、内存泄漏的检测程序，内容如下：
   ```bash
   #include <stdlib.h>
   int main(void) {
       int *p = NULL;
       *p = 1;              /* 非法写 */
       int x; if (x) {}      /* 未初始化使用 */
       int *q = malloc(10); /* 泄漏（未释放） */
       (void)q;
       return 0;
   }
   ```
3. 以调试信息编译：执行 `gcc -g -o valgrind-demo valgrind-demo.c`。
4. 运行内存检测：执行 `valgrind --leak-check=full --error-exitcode=1 ./valgrind-demo`。
5. 确认无被检测进程与检测器残留：执行 `pgrep -x valgrind-demo` 与 `pgrep -x valgrind`。
6. 清理：删除 `valgrind-demo` 与 `valgrind-demo.c`。

## 预期结果

1. 步骤 1：输出版本号。
2. 步骤 2：源文件 `valgrind-demo.c` 生成。
3. 步骤 3：编译成功，退出码为 0，生成可执行文件 `valgrind-demo`。
4. 步骤 4：步骤 2 程序中的三处缺陷均被检出：空指针写入报 `Invalid write`，未初始化变量参与分支报 `Conditional jump or move depends on uninitialised value`，`malloc(10)` 未释放报 `definitely lost`；因指定 `--error-exitcode=1`，退出码为 `1`。
5. 步骤 5：两条 `pgrep` 均无输出，退出码为 1。
6. 步骤 6：测试产物清理完毕。
