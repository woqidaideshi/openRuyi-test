# TC-TR-0022-03 ｜ 虚拟磁盘读写与重启一致

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0022（虚拟化基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 虚拟化 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证虚拟磁盘正常识别与读写，数据在客户机重启后保持一致。

## 前置条件

1. 虚拟磁盘已挂载，客户机已启动。

## 测试步骤

1. 向虚拟磁盘写入数据并记录校验和：
   ```bash
   echo "vm-data" > /tmp/vm-data.txt
   md5sum /tmp/vm-data.txt
   ```
2. 重启客户机：
   ```bash
   sudo virsh -c qemu:///system reboot <域>
   ```
3. 重启后校验数据：
   ```bash
   md5sum /tmp/vm-data.txt
   cat /tmp/vm-data.txt
   ```

## 预期结果

1. 步骤 1：写入成功。
2. 步骤 2：客户机正常重启。
3. 步骤 3：数据 md5 与重启前一致，内容为 `vm-data`。

## 环境依赖说明（2026-11-10 实测）

同 TC-TR-0022-02，本用例依赖**可引导客户机镜像**与客户机内可登录环境，实测验证机无客户机镜像且无 `/dev/kvm`，故未执行。

补充建议：
1. 脚本中注意 “重启前/重启后” 需在**客户机内**执行 `md5sum`，而非宿主机；建议将数据写入持久化路径（如 `/root/vm-data.txt`）而不是 `/tmp`（部分发行版将 `/tmp` 置为 tmpfs，重启即丢失，会导致误判为数据不一致）。
2. `virsh reboot` 需要客户机内 ACPI/agent 响应；若客户机无响应会超时，可改用客户机内 `reboot` 后等待 `virsh domstate` 重新变为 `running`。
3. 若无客户机镜像，可降级为宿主机侧验证：向域磁盘 qcow2 写入数据→ `virsh start`/`destroy` 后校验 qcow2 内容不变，但**不能替代**本用例要求的客户机内验证。
