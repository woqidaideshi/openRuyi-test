# TC-TR-0022-03 ｜ 虚拟网络创建、通信与隔离

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0022（虚拟化基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 虚拟化 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证虚拟网络能够按配置完成地址获取与节点间通信、跨网络隔离符合预期，且清理后无网络资源残留。

## 前置条件

1. 已准备可引导的 openRuyi riscv64 客户机镜像（qcow2）及配套 UEFI 固件（`RISCV_VIRT_CODE.fd`、`RISCV_VIRT_VARS.fd`）。
2. 客户机具备可登录账号（通过串口控制台登录）。

## 测试步骤

1. 确认 libvirt 网络守护已启用并可连接：
    - 启用并启动 socket（未启用时执行）：`sudo systemctl enable --now virtnetworkd.socket`
    - 查看 socket 是否随系统启动：`systemctl is-enabled virtnetworkd.socket`
    - 查看 socket 是否正在监听：`systemctl is-active virtnetworkd.socket`
    - 确认网络接口可连接：`sudo virsh -c qemu:///system net-list --all`
2. 准备虚拟网络 XML，下文 `<net.xml>` 均指代此文件。内容示例如下；其中 `<name>` 为网络名（示例取 `net-a`，下文 `<网络>` 均指代此名），`<bridge name>` 为网桥名（下文 `<网桥>` 均指代此名），`<ip address>` 为网桥地址（下文 `<网桥地址>` 均指该地址），`<dhcp>` 的 `<range>` 为地址池，`<forward mode>` 取 `nat`（可出网并提供默认路由）或 `none`（孤立网络，无默认路由）：

    ```xml
    <network>
      <name>net-a</name>
      <forward mode='none'/>
      <bridge name='virbr-a' stp='on' delay='0'/>
      <ip address='192.168.100.1' netmask='255.255.255.0'>
        <dhcp>
          <range start='192.168.100.100' end='192.168.100.199'/>
        </dhcp>
      </ip>
    </network>
    ```

3. 执行 `sudo virsh -c qemu:///system net-define <net.xml>` 定义网络，查看定义结果：
    - 网络是否已登记及其状态：`sudo virsh -c qemu:///system net-list --all`
4. 执行 `sudo virsh -c qemu:///system net-start <网络>` 启动网络，查看运行状态：
    - 网络状态：`sudo virsh -c qemu:///system net-list --all`
    - 网桥地址：`ip -br addr show <网桥>`
5. 基于客户机镜像创建差分磁盘（新的 qcow2 文件，仅记录与客户机镜像的差异）：`qemu-img create -f qcow2 -b <客户机镜像> -F qcow2 <差分磁盘> <容量>`，并复制一份 NVRAM `<nvram 副本>`，避免改动客户机镜像与原始 UEFI 变量文件；执行 `qemu-img info <差分磁盘>` 查看格式与底层镜像。
6. 准备域 XML，网卡指向步骤 2 定义的网络，内容示例如下；其中 `<name>` 为域名（示例取 `vm-a`，下文 `<域>` 均指代此名），`<source network>` 为步骤 2 的 `<网络>`，`<source file>` 与 `<nvram>` 分别指向步骤 5 的差分磁盘与 NVRAM 副本，`type` 按 `/dev/kvm` 是否存在取 `kvm` 或 `qemu`：

    ```xml
    <domain type='kvm'>
      <name>vm-a</name>
      <memory unit='GiB'>1</memory>
      <currentMemory unit='GiB'>1</currentMemory>
      <vcpu placement='static'>1</vcpu>
      <os>
        <type arch='riscv64'>hvm</type>
        <loader readonly='yes' type='pflash'>/path/RISCV_VIRT_CODE.fd</loader>
        <nvram>/path/vm-a-vars.fd</nvram>
        <boot dev='hd'/>
      </os>
      <cpu mode='host-passthrough'/>
      <devices>
        <disk type='file' device='disk'>
          <driver name='qemu' type='qcow2'/>
          <source file='/path/vm-a.qcow2'/>
          <target dev='vda' bus='virtio'/>
        </disk>
        <interface type='network'>
          <source network='net-a'/>
          <model type='virtio'/>
          <rom enabled='no'/>
        </interface>
        <serial type='pty'>
          <target port='0'/>
        </serial>
        <console type='pty'>
          <target type='serial' port='0'/>
        </console>
      </devices>
    </domain>
    ```

7. 执行 `sudo virsh -c qemu:///system define <xml>` 定义域，查看定义结果：
    - 域是否已登记及其状态：`sudo virsh -c qemu:///system list --all`
    - 网卡归属：`sudo virsh -c qemu:///system domiflist <域>`
8. 执行 `sudo virsh -c qemu:///system start <域>` 启动域，查看运行状态与网络归属：
    - 域运行状态：`sudo virsh -c qemu:///system domstate <域>`
    - 网桥状态：`ip -br addr show <网桥>`
    - DHCP 分配记录：`sudo virsh -c qemu:///system net-dhcp-leases <网络>`
9. 登录主客户机：串口控制台执行 `sudo virsh -c qemu:///system console <域>`（此时仅 `<域>` 一台已启动）。
10. 在主客户机内查看地址与路由：
    - 查看地址：`ip addr`
    - 查看路由：`ip route`
11. 准备其余网络与客户机（按步骤 2–8 的相同方式，并为每台客户机各自创建差分磁盘与 NVRAM 副本）：
    - 第二台同网段客户机（示例取 `vm-a2`）：`<source network>` 取同一 `<网络>`
    - 另一网段的网络（示例取 `net-b`）与其上的客户机（示例取 `vm-b`）：网段与地址池配置与 `<网络>` 不重叠
12. 在客户机内验证节点间通信：
    - 查看网桥地址是否可达：`ping -c 4 <网桥地址>`
    - 查看同网段另一台客户机是否可达：执行 `ping -c 4 <同网段客户机地址>`
13. 验证跨网段隔离：分别登录两个网段的客户机（登录方式同步骤 9），在各客户机内执行 `ping -c 4 <对端客户机地址>`。
14. 停止并删除域与网络，检查残留：
    - 停止域：`sudo virsh -c qemu:///system destroy <域>`（对步骤 6、11 中定义的各域逐台执行）
    - 删除域定义：`sudo virsh -c qemu:///system undefine --nvram <域>`
    - 停止虚拟网络：`sudo virsh -c qemu:///system net-destroy <网络>`（对两个网络逐一执行）
    - 删除网络定义：`sudo virsh -c qemu:///system net-undefine <网络>`
    - 查看域与网络列表：`sudo virsh -c qemu:///system list --all`、`sudo virsh -c qemu:///system net-list --all`
    - 查看网桥是否残留：`ip -br addr show <网桥>`

## 预期结果

1. 步骤 1：`virtnetworkd.socket` 已设置为开机启用且正在监听；`net-list --all` 正常返回，无连接错误。
2. 步骤 2：虚拟网络 XML 文件生成成功。
3. 步骤 3：网络定义成功，`net-list --all` 中该网络已登记，状态为 `inactive`、`Persistent` 为 `yes`。
4. 步骤 4：`net-list --all` 中该网络状态为 `active`；宿主出现对应网桥，状态为 `DOWN`（尚无客户机接入），且已持有网络 XML 中 `<ip address>` 所配置的地址。
5. 步骤 5：差分磁盘与 NVRAM 副本创建成功；`qemu-img info` 显示 `file format: qcow2`，且 `backing file` 为客户机镜像。
6. 步骤 6：域 XML 文件生成成功。
7. 步骤 7：域定义成功，`list --all` 中该域状态为 `shut off`；`domiflist` 显示 `Type` 为 `network`、`Source` 为该网络名。
8. 步骤 8：`domstate` 为 `running`；网桥状态转为 `UP`；`net-dhcp-leases` 出现该客户机 MAC 与配置网段内的地址。
9. 步骤 9：登录成功并出现 shell 提示符。
10. 步骤 10：`ip addr` 显示的地址与 DHCP 租约一致；`ip route` 中存在本网段路由（NAT 模式还应存在默认路由，`forward='none'` 的孤立网络不提供默认路由）。
11. 步骤 11：`net-list --all` 中两个网络均为 `active`；`list --all` 中三台域均为 `running`。
12. 步骤 12：`ping` 网桥地址与同网段客户机均可达，丢包率 0%。
13. 步骤 13：不同网段的客户机互相 `ping` 不通（`Network is unreachable` 或丢包 100%），隔离符合配置。
14. 步骤 14：各域与两个网络均已删除，`list --all` 与 `net-list --all` 中均无对应条目，网桥不存在，无残留 `qemu-system-riscv64` 进程。
