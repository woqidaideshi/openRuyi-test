# TC-TR-0022-01 ｜ 虚拟机生命周期

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0022（虚拟化基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 虚拟化 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证通过 libvirt 调用 QEMU 完成虚拟机定义、启动、状态查询、关机与删除，且删除后无资源残留。

## 前置条件

1. 宿主机已安装 `qemu`、`libvirt-daemon`、`libvirt-client`。
2. 已准备可引导的 openRuyi riscv64 客户机镜像（qcow2）及配套 UEFI 固件（`RISCV_VIRT_CODE.fd`、`RISCV_VIRT_VARS.fd`）。
3. 宿主机具备可用磁盘空间存放差分磁盘与 NVRAM 副本。
4. 域 XML 使用 virtio 网卡时需添加 `<rom enabled='no'/>`（当前仓库无包提供 `efi-virtio.rom`，否则启动报 `failed to find romfile`）。

## 测试步骤

1. 确认软件包与宿主虚拟化能力：执行 `rpm -q qemu libvirt-client libvirt-daemon` 查看软件包版本，执行 `ls -l /dev/kvm` 查看虚拟化加速设备是否存在。
2. 确认 libvirt 守护已启用并可连接：
    - 启用并启动 socket（未启用时执行）：`sudo systemctl enable --now virtqemud.socket`
    - 查看 socket 是否随系统启动：`systemctl is-enabled virtqemud.socket`。
    - 查看 socket 是否正在监听：`systemctl is-active virtqemud.socket`。
    - 确认 virsh 可连接：`sudo virsh -c qemu:///system version`。
3. 基于客户机镜像创建差分磁盘（新的 qcow2 文件，仅记录与客户机镜像的差异）：`qemu-img create -f qcow2 -b <客户机镜像> -F qcow2 <差分磁盘> <容量>`，并复制一份 NVRAM `<nvram 副本>`，避免改动客户机镜像与原始 UEFI 变量文件；执行 `qemu-img info <差分磁盘>` 查看格式与底层镜像。
4. 准备域 XML（vCPU、内存、磁盘、virtio 网卡、virtio-rng、pflash 固件、串口），内容示例如下；其中 `<name>` 为域名（示例取 `test-vm`，下文 `<域>` 均指代此名）；`<source file>` 指向步骤 3 的差分磁盘、`<nvram>` 指向步骤 3 的 NVRAM 副本，`type` 按 `/dev/kvm` 是否存在取 `kvm` 或 `qemu`，TCG（`type='qemu'`）下 `<cpu>` 改用 `<cpu mode='maximum'/>`：

    ```xml
    <domain type='kvm'>
      <name>test-vm</name>
      <memory unit='GiB'>2</memory>
      <currentMemory unit='GiB'>2</currentMemory>
      <vcpu placement='static'>2</vcpu>
      <os>
        <type arch='riscv64'>hvm</type>
        <loader readonly='yes' type='pflash'>/path/RISCV_VIRT_CODE.fd</loader>
        <nvram>/path/test-vm-vars.fd</nvram>
        <boot dev='hd'/>
      </os>
      <cpu mode='host-passthrough'/>
      <devices>
        <disk type='file' device='disk'>
          <driver name='qemu' type='qcow2'/>
          <source file='/path/test-vm.qcow2'/>
          <target dev='vda' bus='virtio'/>
        </disk>
        <interface type='user'>
          <model type='virtio'/>
          <rom enabled='no'/>
        </interface>
        <serial type='pty'>
          <target port='0'/>
        </serial>
        <console type='pty'>
          <target type='serial' port='0'/>
        </console>
        <rng model='virtio'>
          <backend model='random'>/dev/urandom</backend>
        </rng>
      </devices>
    </domain>
5. 执行 `sudo virsh -c qemu:///system define <xml>` 定义域，查看定义结果：
    - 域是否已登记及其状态：`sudo virsh -c qemu:///system list --all`
    - `CPU(s)` 与 `Max memory`：`sudo virsh -c qemu:///system dominfo <域>`
    - 网卡类型与 MAC 地址：`sudo virsh -c qemu:///system domiflist <域>`
6. 执行 `sudo virsh -c qemu:///system start <域>` 启动域，查看运行状态与资源占用：
    - 运行状态：`sudo virsh -c qemu:///system domstate <域>`
    - vCPU 数量与所在物理 CPU：`sudo virsh -c qemu:///system vcpuinfo <域>`
    - 内存统计：`sudo virsh -c qemu:///system dommemstat <域>`
    - 磁盘容量：`sudo virsh -c qemu:///system domblkinfo <域> vda`
    - qemu 进程及加速方式：`ps -eo pid,args | grep -F qemu-system-riscv64 | grep -v grep`
7. 执行 `sudo virsh -c qemu:///system shutdown <域>` 正常关机，随后执行 `sudo virsh -c qemu:///system domstate <域>` 查看状态；若状态未变为 `shut off` 则继续执行步骤 8，否则跳过步骤 8。
8. 执行 `sudo virsh -c qemu:///system destroy <域>` 强制停止，随后执行 `sudo virsh -c qemu:///system domstate <域>` 查看状态。
9. 执行 `sudo virsh -c qemu:///system undefine --nvram <域>` 删除域，检查残留情况：
    - 域列表中是否还有该域：`sudo virsh -c qemu:///system list --all`
    - 是否残留 qemu 进程：`ps -eo pid,args | grep -F qemu-system-riscv64 | grep -v grep`
    - NVRAM 副本是否已随删除移除：`ls -l <nvram 副本>`
10. 删除差分磁盘与域 XML 临时文件。

## 预期结果

1. 步骤 1：`qemu`、`libvirt-client`、`libvirt-daemon` 均已安装，输出中可见版本号；宿主 CPU 支持 RISC-V H 扩展且内核启用 KVM 时存在 `/dev/kvm`，可用 KVM 加速（域用 `type='kvm'`）；不支持 H 扩展或内核未启用 KVM 时该设备不存在，只能以 TCG 运行（域用 `type='qemu'`），两种情况均不影响本用例判定。
2. 步骤 2：`virtqemud.socket` 已设置为开机启用，且当前正在监听；`virsh version` 正常返回，无连接错误。
3. 步骤 3：差分磁盘与 NVRAM 副本创建成功；`qemu-img info` 显示 `file format: qcow2`，且 `backing file` 为客户机镜像。
4. 步骤 4：域 XML 文件生成成功。
5. 步骤 5：域定义成功，`virsh list --all` 中该域状态为 `shut off`；`virsh dominfo` 显示的 `CPU(s)` 与 `Max memory` 与 XML 配置一致；`virsh domiflist` 显示配置的 virtio 网卡及其 MAC 地址。
6. 步骤 6：`domstate` 显示状态为 `running`；`vcpuinfo` 显示的 vCPU 数量与 XML 一致；`dommemstat` 正常返回内存统计；`domblkinfo` 的 `Capacity` 与差分磁盘容量一致；存在该域对应的 `qemu-system-riscv64` 进程，命令行含 `-accel kvm`（`type='qemu'` 时为 `-accel tcg -cpu max`）。
7. 步骤 7：域状态由 `running` 变为 `shut off`，属正常关机。步骤 8 跳过。
8. 步骤 8：`destroy` 后状态为 `shut off`；本次属非正常关机路径，记录中需注明。
9. 步骤 9：域删除成功；`virsh list --all` 中无该域，无残留 `qemu-system-riscv64` 进程，NVRAM 副本已不存在。
10. 步骤 10：差分磁盘与域 XML 已删除。
