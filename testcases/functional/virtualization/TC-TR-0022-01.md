# TC-TR-0022-01 ｜ 虚拟机生命周期

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0022（虚拟化基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 虚拟化 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 libvirt/QEMU 虚拟机定义、创建、启动、状态查询、关机及删除全生命周期正常，无资源残留。

## 前置条件

1. 宿主机为 riscv64 平台，已安装 qemu 与 libvirt（`virsh` 可用）。
2. libvirt 服务（`libvirtd` 或 `virtqemud`）可启动。
3. 虚拟化加速可用：KVM 或 TCG。
4. 已准备可引导的客户机镜像（qcow2）。
5. 已具备可用的虚拟网络（未预置时可用 `virsh net-define` 自行创建）。

## 测试步骤

1. 确认虚拟化工具与宿主虚拟化能力：
   ```bash
   rpm -q qemu libvirt-client libvirt-daemon
   sudo virsh -c qemu:///system version
   ls -la /dev/kvm 2>&1
   ```
2. 启动 libvirt 服务（如未运行）：
   ```bash
   sudo systemctl start libvirtd 2>/dev/null || sudo systemctl start virtqemud 2>/dev/null
   sudo systemctl is-active libvirtd virtqemud 2>/dev/null
   ```
3. 准备虚拟网络（`default` 网络不存在时创建并启动）：
   ```bash
   CASE_TMP=/tmp/tc-libvirt && mkdir -p $CASE_TMP
   sudo virsh -c qemu:///system net-list --all
   cat > $CASE_TMP/default-net.xml <<'EOF'
   <network>
     <name>default</name>
     <forward mode='nat'/>
     <bridge name='virbr0' stp='on' delay='0'/>
     <ip address='192.168.122.1' netmask='255.255.255.0'>
       <dhcp><range start='192.168.122.2' end='192.168.122.254'/></dhcp>
     </ip>
   </network>
   EOF
   sudo virsh -c qemu:///system net-define $CASE_TMP/default-net.xml
   sudo virsh -c qemu:///system net-start default
   ip -br addr show virbr0
   ```
4. 定义虚拟机（配置 vCPU、内存、磁盘、网络）：
   ```bash
   sudo virsh -c qemu:///system define <xml>
   sudo virsh -c qemu:///system list --all
   ```
   > 域 XML 中带网卡时，`<interface>` 必须加 **`<rom enabled='no'/>`**，否则启动会因缺少 `efi-virtio.rom` 失败（见下方已知问题）：
   > ```xml
   > <interface type='network'>
   >   <source network='default'/>
   >   <model type='virtio'/>
   >   <rom enabled='no'/>
   > </interface>
   > ```
5. 启动并查询状态：
   ```bash
   sudo virsh -c qemu:///system start <域>
   sudo virsh -c qemu:///system list
   sudo virsh -c qemu:///system dominfo <域>
   ```
6. 正常关机并查询状态：
   ```bash
   sudo virsh -c qemu:///system shutdown <域>
   sudo virsh -c qemu:///system list --all
   ```
7. 删除虚拟机并清理临时目录：
   ```bash
   sudo virsh -c qemu:///system undefine <域>
   sudo virsh -c qemu:///system list --all
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：`libvirt-daemon` 与 `libvirt-client` 已安装（主包会连带装上 `driver-qemu`、`driver-others` 等驱动），`virsh version` 可连接；`/dev/kvm` 在无 H 扩展的 riscv64 平台上不存在属正常（须用 `type='qemu'`/TCG）。
2. 步骤 2：libvirt 服务启动成功。
3. 步骤 3：`net-list --all` 中 `default` 网络状态为 `active`，`virbr0` 获得 `192.168.122.1/24`（未挂客户机时为 `DOWN` 属正常）。
4. 步骤 4：虚拟机定义成功，`virsh list --all` 可见。
5. 步骤 5：启动成功，状态为 `running`。
6. 步骤 6：关机后状态为 `shut off`。
7. 步骤 7：删除成功，无残留域定义与资源。

## 实测记录与已知问题（2026-11-10，riscv64 物理机）

### 实测通过项

在 `qemu-11.0.1` + `libvirt 12.9.0`、**无 `/dev/kvm`（纯 TCG）** 环境下，生命周期全链路通过：

| 步骤 | 实测结果 |
|---|---|
| `virsh define` | `Domain 'tc-vm-01' defined from ...` |
| `virsh list --all` | `tc-vm-01  shut off` |
| `virsh dominfo` | `OS Type: hvm`、`CPU(s): 2`、`Max memory: 524288 KiB` |
| `virsh start` | `Domain 'tc-vm-01' started`，状态 `running`，可见 `qemu-system-riscv64` 进程 |
| `virsh vcpuinfo` / `dommemstat` | 正常返回（`CPU time: 4.2s`、`rss 76968`） |
| `virsh destroy` | `destroyed`，状态 `shut off` |
| `virsh undefine` | `has been undefined`，`residual_domains=0`、`residual_qemu_procs=0` |

> 虚拟网络：`net-define` 输出 `Network default defined`，`net-start` 输出 `Network default started`，`virbr0` 获得 `192.168.122.1/24`（无客户机时为 `DOWN`）。

> 说明：若域内无可用客户机系统，`virsh shutdown` 会返回 `is being shutdown` 而状态仍为 `running`（无 OS 响应 ACPI 关机），这是**预期现象**，不是缺陷；测试时需用 `destroy` 收尾。

### ⚠ 踩坑：只装驱动子包会让 `virtqemud` 起不来

**现象**：仅执行 `sudo dnf install libvirt-daemon-driver-qemu` 时，`sudo systemctl start virtqemud` 失败，继而 `virsh` 完全不可用：

```
Failed to start virtqemud.service: Unit virtlogd.socket not found.

error: failed to connect to the hypervisor
error: Failed to connect socket to '/var/run/libvirt/virtqemud-sock': No such file or directory
```

**根因**：`virtlogd.socket` 由 **`libvirt-daemon-driver-others`** 提供（`dnf provides '*/virtlogd.socket'` 可查得该归属），而 `libvirt-daemon-driver-qemu` 并不依赖它。正确做法是安装主包 `libvirt-daemon`，它对全部驱动子包（含 `driver-others`）有强制依赖，装主包不会出现此问题。

**规避**：
```bash
sudo dnf install -y libvirt-daemon libvirt-client
sudo systemctl start virtqemud
```

### ⚠ 缺陷 2：包版本错配

安装 `libvirt-daemon-driver-others` 时，仓库中仅有 `12.9.0`，导致全套包被升级：

| 包 | 修复前 | 修复后 |
|---|---|---|
| libvirt-client | 12.2.0-4.3.or | 12.9.0-8.1.or |
| libvirt-daemon-driver-qemu | 12.2.0-4.3.or | 12.9.0-8.1.or |
| python-libvirt | 12.2.0-1.15.or | **12.2.0（未随之升级）** |

`python-libvirt` 与 C 库存在主次版本错配，使用 python 绑定（如 `virt-manager`、自研脚本）时存在兼容风险，建议打包侧对齐版本。

复核（2026-11-10）：仓库仍只提供 `python-libvirt-12.2.0-1.15.or`，而 `libvirt-client` 已是 `12.9.0-8.1.or`，`sudo dnf upgrade python-libvirt` 返回 `Nothing to do.`，错配持续存在。另注意不同镜像的仓库版本并不一致（他机 Base 中 `libvirt-daemon` 为 `12.2.0-6.1.or`，本机为 `12.9.0-8.1.or`），跨机比对时以本机 `dnf list` 为准。

### ⚠ 缺陷：带 virtio 网卡的域无法启动（缺 `efi-virtio.rom`）

**现象**：域配置包含 `<interface>`（即使是 `type='user'`）时，`virsh start` 直接失败：

```
error: Failed to start domain 'tc-vm-01'
error: internal error: process exited while connecting to monitor:
  qemu-system-riscv64: -device {"driver":"virtio-net-pci", ...}:
  failed to find romfile "efi-virtio.rom"
```

**根因**：仓库**没有任何包提供 `efi-virtio.rom`**（`dnf provides '*/efi-virtio.rom'` 返回 `No matches found`，也无 `ipxe-roms-qemu` 类包），`/usr/share/qemu/` 下只有 `qboot.rom` 等少数 ROM。不带网卡的域可以正常启动，一旦加网卡就触发。

**规避**：给接口加 `<rom enabled='no'/>`，实测可正常启动并挂上 virtio 网卡：

```
Domain 'tc-vm-02' started
 Id   Name       State
  2    tc-vm-02   running
 Interface   Type   Source   Model    MAC
 -           user   -        virtio   52:54:00:b7:48:38
```

**建议**：打包侧补上 virtio 网卡 option ROM（如 `ipxe-roms-qemu`），否则任何带虚拟网卡的域都需手工加 `rom enabled='no'`，开机自检（PXE）也不可用。

### 注意事项
- 所有 `virsh` 命令需加 `sudo` 并显式指定 `-c qemu:///system`。`virsh` 默认 URI 是 `qemu:///session`（普通用户可用），但那是用户会话实例，看不到系统的域与网络；而 `qemu:///system` 需要 root。实测本机普通用户访问 system 连接连只读操作都失败：`error: error from service: GDBus.Error:org.freedesktop.PolicyKit1.Error.Failed: Action org.libvirt.unix.manage is not registered`——原因是未安装主包 `libvirt-daemon`，缺少 `/usr/share/polkit-1/actions/org.libvirt.unix.policy`（`dnf provides '*/org.libvirt.unix.policy'` 可查得归属 `libvirt-daemon`）；系统也没有 `libvirt` 组可加。
- openRuyi 未预置 `default` 网络（`/usr/share/libvirt/networks/` 不存在），`virtnetworkd` 由 `libvirt-daemon-driver-others` 提供，需自行 `sudo virsh -c qemu:///system net-define`/`net-start`。
- 本机无 `/dev/kvm`，`<domain type='kvm'>` 不可用，必须用 `type='qemu'`（TCG）。TCG 下性能很低，验证功能正确性即可。
