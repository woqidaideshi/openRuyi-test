# TC-TR-0022-02 ｜ 客户机启动、设备识别与磁盘一致性

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0022（虚拟化基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 虚拟化 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证客户机能够进入操作系统，正确识别配置的虚拟 CPU、内存与规定设备；虚拟磁盘可正常读写，写入的数据在重启后保持一致，且镜像未损坏。

## 前置条件

1. 已准备可引导的 openRuyi riscv64 客户机镜像（qcow2）及配套 UEFI 固件（`RISCV_VIRT_CODE.fd`、`RISCV_VIRT_VARS.fd`），并已基于镜像创建差分磁盘与 NVRAM 副本。
2. 域已定义并启动，XML 配置 vCPU、内存、virtio 磁盘、virtio 网卡（带 `<rom enabled='no'/>`）、virtio-rng 与串口。
3. 客户机具备可登录账号（通过串口控制台登录），且存在可写的持久化路径（非 `/tmp` 等内存文件系统）。

## 测试步骤

1. 在宿主侧查询域配置：
    - 查看 vCPU 数量与所在物理 CPU：`sudo virsh -c qemu:///system vcpuinfo <域>`
    - 查看 `CPU(s)` 与 `Max memory`：`sudo virsh -c qemu:///system dominfo <域>`
    - 查看磁盘列表与源路径：`sudo virsh -c qemu:///system domblklist <域>`
    - 查看网卡列表与 MAC 地址：`sudo virsh -c qemu:///system domiflist <域>`
2. 登录客户机（串口控制台：`sudo virsh -c qemu:///system console <域>`），确认已进入操作系统：执行 `uname -m` 查看架构，执行 `cat /proc/uptime` 查看系统已运行时长。
3. 在客户机内查看 CPU 与内存识别情况：
    - 查看 CPU 核数：`nproc`
    - 查看 CPU 架构信息：`lscpu | head`
    - 查看内存总量与可用量：`free -h`
4. 在客户机内查看磁盘与设备识别情况：
    - 查看块设备与分区：`lsblk`
    - 查看网络接口：`ip link`
    - 查看 PCI 设备列表：`ls /sys/bus/pci/devices`（有 `lspci` 时执行 `lspci`）
    - 查看 virtio-rng 设备节点：`ls -l /dev/hwrng`
5. 在客户机内向持久化路径写入测试数据，计算其 MD5 校验值并确认根分区剩余空间。
6. 在客户机内执行 `sudo systemctl reboot` 重启客户机，等待其重新上线，确认域状态回到运行态，并重新登录客户机。
7. 在客户机内复核数据：重新计算 MD5 校验值并与重启前比对、查看文件内容，并执行 `dmesg | grep -iE "i/o error|ext4-fs error|xfs.*error"` 检查磁盘与文件系统错误。
8. 停止域后，在宿主侧执行 `qemu-img check <差分磁盘>` 检查镜像完整性。

## 预期结果

1. 步骤 1：宿主侧四条命令均正常返回；`vcpuinfo` 的 vCPU 数量、`dominfo` 的 `CPU(s)` 与 `Max memory`、`domblklist` 的磁盘与 `domiflist` 的网卡均与域 XML 配置一致。
2. 步骤 2：登录成功并进入 shell；`uname -m` 输出 `riscv64`，`/proc/uptime` 输出大于 0 的秒数。
3. 步骤 3：`nproc` 输出与域配置的 vCPU 数量一致；`lscpu` 显示 riscv64 架构信息；`free -h` 显示的总内存与域配置的内存一致（允许内核保留造成的小幅差异）。
4. 步骤 4：`lsblk` 中可见配置的 virtio 磁盘及其分区；`ip link` 中可见 virtio 网卡接口；PCI 设备列表中可见 `virtio` 相关设备；`/dev/hwrng` 存在对应 virtio-rng 设备。
5. 步骤 5：写入成功，MD5 校验值计算正常，根分区剩余空间充足。
6. 步骤 6：域状态为 `running`，客户机可重新登录并进入 shell。
7. 步骤 7：MD5 校验值与重启前一致，文件内容为 `vm-data`；`dmesg` 中无 I/O 错误或文件系统错误。
8. 步骤 8：`qemu-img check` 未发现镜像损坏（无 `corruptions found`、错误计数为 0）。
