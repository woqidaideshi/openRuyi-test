# TC-TR-0022-02 ｜ 客户机设备识别

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0022（虚拟化基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 虚拟化 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证客户机进入操作系统后识别配置的虚拟 CPU、内存及规定设备。

## 前置条件

1. 已配置虚拟 CPU/内存及规定设备（网卡、磁盘等），客户机已启动。

## 测试步骤

1. 查询宿主侧配置：
   ```bash
   sudo virsh -c qemu:///system vcpuinfo <域>
   sudo virsh -c qemu:///system dommemstat <域>
   ```
2. 登录客户机，检查 CPU、内存识别：
   ```bash
   nproc
   lscpu | head
   free -h
   ```
3. 检查磁盘与设备识别：
   ```bash
   lsblk
   lspci 2>/dev/null || ls /sys/bus/pci/devices
   ```

## 预期结果

1. 步骤 1：宿主侧 vCPU/内存配置可查询。
2. 步骤 2：客户机 `nproc`/`free -h` 与配置一致。
3. 步骤 3：磁盘与规定设备被正确识别。

## 环境依赖说明（2026-11-10 实测）

本用例**必须有可引导的 riscv64 客户机镜像**才能执行。实测验证机（riscv64 物理机）上：

- 无任何 qcow2 客户机镜像（`/var/lib/libvirt/images/` 初不存在，全盘扫描仅剩固件镜像 `hppa-firmware.img` 等）；
- 无 `/dev/kvm`，只能 TCG 仿真。

因此本用例当前**不具备执行条件**。执行前请准备：
1. 可引导的 riscv64 qcow2 镜像（含 OpenSBI/U-Boot 或 `-kernel` 直引）；
2. 可通过串口控制台登录客户机（域 XML 需含 `<serial type='pty'>` + `<console type='pty'>`）；
3. 宿主机先按 TC-TR-0022-01 修复 `libvirt-daemon-driver-others` 并启动 `virtqemud`。

宿主侧查询命令已验证可用（`virsh vcpuinfo` / `dommemstat` 均能正常返回）；客户机内的 `nproc`/`free -h`/`lsblk` 待有镜像后补充。
