# TC-TR-0022-04 ｜ 虚拟网络与异常诊断

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0022（虚拟化基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 虚拟化 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证虚拟网络地址获取、节点通信、隔离与访问控制符合预期，失败时有明确诊断。

## 前置条件

1. 虚拟网络配置就绪（NAT/隔离网络）。

## 测试步骤

1. 查看虚拟网络列表与配置：
   ```bash
   sudo virsh -c qemu:///system net-list
   sudo virsh -c qemu:///system net-dumpxml <网络>
   ```
2. 客户机内验证地址获取：
   ```bash
   ip addr
   ip route
   ```
3. 规定节点间通信：
   ```bash
   ping -c 4 <对端>
   ```
4. 验证隔离与访问控制（不同网络/网络策略）。
5. 触发操作失败场景（如使用不存在的镜像路径定义虚拟机）：
   ```bash
   sudo virsh -c qemu:///system define /nonexistent.xml
   echo $?
   ```

## 预期结果

1. 步骤 1：虚拟网络配置正确。
2. 步骤 2：客户机获得预期网络地址。
3. 步骤 3：规定节点间通信正常。
4. 步骤 4：隔离与访问控制符合预期。
5. 步骤 5：失败时提供明确诊断（退出码非 0），无磁盘损坏。

## 实测记录与已知问题（2026-11-10，riscv64 物理机）

### 实测通过项（步骤 5 错误诊断）

| 场景 | 实测输出 | 退出码 |
|---|---|---|
| `virsh define /nonexistent.xml` | `error: Failed to open file '/nonexistent.xml': No such file or directory` | `1` |
| 启动域时磁盘镜像不存在 | `error: Cannot access storage file '/var/lib/libvirt/images/does-not-exist.qcow2' (as uid:107, gid:107): No such file or directory` | `1` |

诊断信息明确（含缺失路径、执行身份 uid/gid），且失败后无残留域（`residual_domains=0`）。

### ⚠ 问题 1：`virsh net-list` 需先启动 `virtnetworkd`

未启动网络守护时直接查询会失败：

```
error: Failed to list networks
error: Failed to connect socket to '/var/run/libvirt/virtnetworkd-sock': No such file or directory
```

**规避**：`sudo systemctl start virtnetworkd` 后即可正常查询。建议文档前置条件中显式要求启动该服务。

### ⚠ 问题 2：没有预置的 `default` 网络

启动 `virtnetworkd` 后，`virsh net-list --all` **为空**，`virsh net-dumpxml default` 报 `Network not found`；且仓库中不存在默认网络定义文件：

```
$ dnf provides '*/networks/default.xml'
No matches found.
$ ls /usr/share/libvirt/networks/
No such file or directory
```

影响：域 XML 中引用 `<interface type='network'><source network='default'/></interface>` 将无法启动，需自行定义网络。

### 实测：自建 NAT 网络可用

自建 NAT 网络验证通过：

```bash
cat > /tmp/tcnet.xml <<'XML'
<network>
  <name>tcnet</name>
  <forward mode='nat'/>
  <bridge name='tcvbr0' stp='on' delay='0'/>
  <ip address='192.168.199.1' netmask='255.255.255.0'>
    <dhcp><range start='192.168.199.10' end='192.168.199.50'/></dhcp>
  </ip>
</network>
XML
sudo virsh -c qemu:///system net-define /tmp/tcnet.xml
sudo virsh -c qemu:///system net-start tcnet
```

结果：`net-list` 显示 `tcnet active`；宿主出现网桥 `tcvbr0 192.168.199.1/24`；`nft list ruleset` 中新增 7 条与 `masquerade`/`192.168.199` 相关规则，说明 NAT 转发已自动下发。`net-destroy` + `net-undefine` 后网桥与规则均被清除（`residual_bridge: Device "tcvbr0" does not exist`）。

> 注意：本机无 `/dev/kvm`，客户机只能 TCG 运行；验证虚拟网络“客户机获取地址/节点互通”时还需可引导客户机镜像（见 TC-TR-0022-02）。
