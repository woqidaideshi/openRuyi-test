# TC-TR-0022-04 ｜ 虚拟化操作异常诊断

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0022（虚拟化基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 虚拟化 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证域与虚拟网络的非法操作均被拒绝，返回明确诊断信息且不导致宿主崩溃或资源残留。

## 前置条件

1. 已安装 `qemu`、`libvirt-daemon`、`libvirt-client`，`virtqemud.socket` 与 `virtnetworkd.socket` 且均已启用并启动。
2. 已准备可引导的 openRuyi riscv64 客户机镜像（qcow2）及配套 UEFI 固件，并已创建差分磁盘与 NVRAM 副本，用于构造磁盘缺失与不可读场景。
3. 已存在一个可正常定义并启动的域，以及一个可正常定义的虚拟网络，用于构造重复操作场景。

## 测试步骤

1. 确认 libvirt 守护可连接：
    - 查看管理守护是否在监听：`systemctl is-active virtqemud.socket`
    - 查看网络守护是否在监听：`systemctl is-active virtnetworkd.socket`
    - 确认 virsh 可连接：`sudo virsh -c qemu:///system version`
2. 触发域定义类异常：
    - 定义不存在的 XML 文件：`sudo virsh -c qemu:///system define /var/tmp/nonexistent.xml`
    - 对已存在的域以不同 UUID 再次定义：执行 `sudo virsh -c qemu:///system dumpxml <已存在的域> > /tmp/dup.xml` 导出该域 XML，删除其中 `<uuid>` 行后执行 `sudo virsh -c qemu:///system define /tmp/dup.xml`
3. 触发域启停类异常：
    - 启动已在运行的域：`sudo virsh -c qemu:///system start <运行中的域>`
    - 停止处于 `shut off` 的域：`sudo virsh -c qemu:///system destroy <shut off 的域>`
    - 删除运行中带 NVRAM 的域定义（不加 `--nvram`）：`sudo virsh -c qemu:///system undefine <运行中的域>`
    - 删除运行中带 NVRAM 的域定义（加 `--nvram`）：`sudo virsh -c qemu:///system undefine --nvram <运行中的域>`，随后执行 `sudo virsh -c qemu:///system dominfo <运行中的域>` 查看该域运行状态与持久化状态，并确认 NVRAM 文件是否已删除
4. 触发网络类异常：
    - 启动已激活的网络：`sudo virsh -c qemu:///system net-start <已激活的网络>`
    - 定义已存在的网络：`sudo virsh -c qemu:///system net-define <该网络 XML>`
    - 启动不存在的网络：`sudo virsh -c qemu:///system net-start <不存在的网络>`
    - 停止不存在的网络：`sudo virsh -c qemu:///system net-destroy <不存在的网络>`
    - 启动网卡引用不存在网络的域：`sudo virsh -c qemu:///system start <该域>`
    - 删除激活中的网络定义：`sudo virsh -c qemu:///system net-undefine <已激活的网络>`，随后执行 `sudo virsh -c qemu:///system net-list --all` 查看 `State` 与 `Persistent` 列
5. 触发存储类异常：
    - 定义引用不存在磁盘路径的域：准备域 XML（`<source file>` 指向不存在的磁盘路径）后执行 `sudo virsh -c qemu:///system define <磁盘缺失 XML>`
    - 启动磁盘缺失域：`sudo virsh -c qemu:///system start <磁盘缺失域>`
    - 磁盘文件不可读后启动域：执行 `chmod 000 <该域磁盘文件>` 后执行 `sudo virsh -c qemu:///system start <该域>`
6. 确认宿主状态并清理临时资源：
    - 查看域列表：`sudo virsh -c qemu:///system list --all`
    - 查看网络列表：`sudo virsh -c qemu:///system net-list --all`
    - 查看是否残留 qemu 进程：`ps -eo pid,args | grep -F qemu-system-riscv64 | grep -v grep`
    - 停止步骤 3 中被转为非持久化的域：`sudo virsh -c qemu:///system destroy <该域>`
    - 删除步骤 5 中定义的磁盘缺失域：`sudo virsh -c qemu:///system undefine <磁盘缺失域>`

## 预期结果

1. 步骤 1：`virtqemud.socket` 与 `virtnetworkd.socket` 均正在监听（`systemctl is-active` 返回 `active`）；`virsh version` 正常返回，无连接错误。
2. 步骤 2：
    - 定义不存在的 XML：返回非 0，并提示文件不存在
    - 对已存在的域以不同 UUID 再次定义：返回非 0，并提示域名已存在
3. 步骤 3：
    - 启动已在运行的域：返回非 0，并提示域已运行
    - 停止处于 `shut off` 的域：返回非 0，并提示域未运行
    - `undefine` 运行中带 NVRAM 的域（不加 `--nvram`）：返回非 0，并提示需按 NVRAM 方式处理
    - `undefine --nvram` 同一运行中的域返回 0，`dominfo` 显示该域仍为 `running` 但 `Persistent` 为 `no`，NVRAM 文件已被删除
4. 步骤 4：
    - 启动已激活的网络：返回非 0，并提示网络已激活
    - 定义已存在的网络：返回非 0，并提示网络已存在
    - 启动不存在的网络：返回非 0，并提示网络不存在
    - 停止不存在的网络：返回非 0，并提示网络不存在
    - 启动网卡引用不存在网络的域：返回非 0，并提示网络不存在
    - 删除激活中的网络定义：返回 0，`net-list --all` 中该网络仍为 `active`，但 `Persistent` 列变为 `no`（libvirt 不阻止，重启守护后定义丢失）
5. 步骤 5：
    - 定义引用不存在磁盘路径的域：`define` 成功（定义阶段不校验存储）
    - 启动磁盘缺失域：返回非 0，并提示文件不存在
    - 磁盘文件不可读后启动域：返回非 0，并提示权限被拒
6. 步骤 6：上述命令均正常返回，宿主无崩溃；清理后 `list --all` 与 `net-list --all` 中不再有测试产生的临时资源，也无非预期 `qemu-system-riscv64` 进程。
