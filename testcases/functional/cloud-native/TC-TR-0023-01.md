# TC-TR-0023-01 ｜ 镜像拉取校验解包

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0023（容器运行时功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 云原生 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证容器镜像从规定仓库拉取、内容完整性校验与解包正常。

## 前置条件

1. 已安装 podman，具备可用用户或 root 权限。
2. 规定镜像仓库可达，且仓库中存在 riscv64 架构镜像。

## 测试步骤

1. 确认运行时与架构：
   ```bash
   podman version
   uname -m
   ```
2. 拉取与目标架构匹配的镜像：
   ```bash
   podman pull <仓库>/<镜像>:<标签>
   echo $?
   podman images
   ```
3. 内容完整性校验（获取镜像 digest）：
   ```bash
   podman inspect <镜像> --format '{{.Digest}}'
   ```
4. 确认可基于镜像创建容器：
   ```bash
   podman run --rm <镜像> uname -m
   ```

## 预期结果

1. 步骤 1：podman 版本信息正常，架构为 riscv64。
2. 步骤 2：镜像拉取成功，退出码为 0，`podman images` 可见。
3. 步骤 3：digest 与仓库公布值一致，内容完整性校验通过。
4. 步骤 4：解包正常，容器内 `uname -m` 输出 riscv64。

## 实测记录与环境说明（2026-11-10，riscv64 物理机）

实测环境：`podman 5.8.2`（riscv64）、网络后端 `netavark`、`/etc/containers/registries.conf` 未配置镜像加速。

### ⚠ 外网仓库不可达

- `https://registry-1.docker.io/v2/`：`curl` 返回 `000`（连接失败），`podman pull` 报 `connection reset by peer`；
- `https://quay.io/v2/`：`curl` 返回 `401`（可达但需认证），`podman pull` 常见 `TLS handshake timeout`，偶发可通。

因此若现场无可用的 registry 或镜像加速，**步骤 2 会因网络不可达而失败**（非产品缺陷）。

### 无仓库时的替代验证（已实测通过）

用“从宿主最小 rootfs 导入本地镜像”代替 `pull`，可完整验证镜像导入、解包与运行：

```bash
ROOT=/srv/tc-img/rootfs
sudo mkdir -p $ROOT
for b in /usr/bin/bash /usr/bin/uname /usr/bin/ip /usr/bin/ping /usr/bin/ls \
         /usr/bin/sleep /usr/bin/cat /usr/bin/env /usr/bin/mkdir; do
  real=$(readlink -f "$b")
  sudo install -D "$real" "$ROOT$real"
  for lib in $(ldd "$real" | awk '{print $3}' | grep '^/'); do sudo install -D "$lib" "$ROOT$lib"; done
  interp=$(ldd "$real" | awk '/ld-linux/{print $1}' | head -1)
  [ -n "$interp" ] && sudo install -D "$interp" "$ROOT$interp"
done
sudo ln -sf /usr/bin/bash $ROOT/bin/sh
printf 'root:x:0:0:root:/root:/bin/sh\n' | sudo tee $ROOT/etc/passwd >/dev/null
sudo tar -C $ROOT -cf /tmp/tc-rootfs.tar .
sudo podman import /tmp/tc-rootfs.tar tc-base:latest
sudo podman run --rm tc-base:latest /usr/bin/uname -m     # 输出 riscv64
```

实测结果：rootfs 仅 8.9MB，导入后 `podman images` 显示 `localhost/tc-base  latest  7e0dd06dc7bd  9.27 MB`；容器内 `uname -m` 输出 `riscv64`，退出码 `0`。

### 注意事项

1. `podman inspect --format '{{.Digest}}'` 对 **import 得到的本地镜像**返回本地 manifest 摘要（实测 `sha256:edc812fd88b73…`），**不是** 仓库公布的上游 digest，不能用于“与仓库公布值一致”的校验；该断言仅在真正 `pull` 自仓库时成立。
2. `{{.From}}` 字段对导入镜像不存在，会报 `can't evaluate field From`，脚本中不要使用。
3. rootless 与 root 的镜像存储是**两套**。本用例若用 `sudo podman`，则 `podman images`（无 sudo）看不到镜像，需全程保持同一用户上下文。
