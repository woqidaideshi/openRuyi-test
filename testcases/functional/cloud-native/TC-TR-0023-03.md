# TC-TR-0023-03 ｜ 容器网络

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0023（容器运行时功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 云原生 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证容器网络地址分配、路由设置、规定范围通信及隔离访问控制符合配置。

## 前置条件

1. 容器网络插件可用（podman 自带 CNI/netavark）。

## 测试步骤

1. 创建自定义网络：
   ```bash
   podman network create net1
   podman network ls
   ```
2. 验证地址分配：
   ```bash
   podman run --rm --network net1 <镜像> ip addr
   ```
3. 验证路由设置：
   ```bash
   podman run --rm --network net1 <镜像> ip route
   ```
4. 规定范围通信（两容器互 ping）：
   ```bash
   podman run -d --name n1 --network net1 <镜像> sleep infinity
   podman run -d --name n2 --network net1 <镜像> sleep infinity
   podman exec n1 ping -c 3 n2
   ```
5. 清理：
   ```bash
   podman rm -f n1 n2
   podman network rm net1
   ```

## 预期结果

1. 步骤 1：网络创建成功。
2. 步骤 2：容器获得网络地址。
3. 步骤 3：路由设置符合配置。
4. 步骤 4：两容器间 ping 通（0% 丢包）。
5. 步骤 5：清理完毕，无残留网络。

## 实测记录与环境说明（2026-11-10，riscv64 物理机，podman 5.8.2 + netavark）

| 步骤 | 实测结果 |
|---|---|
| `podman network create net1` | 成功，`podman network ls` 可见 `net1  bridge` |
| 容器内 `ip addr` | `eth0@if19  UP  10.89.0.2/24`（自动分配） |
| 容器内 `ip route` | `default via 10.89.0.1 dev eth0 proto static` + `10.89.0.0/24 dev eth0` |
| 两容器 `ping n2` | `3 packets transmitted, 3 received, 0% packet loss` |
| 清理 | `podman rm -f n1 n2` + `network rm net1` 均成功，`residual_containers=0` |

**内置 DNS 可用**：容器间可直接用**容器名**互访（`ping n2` 被解析为 `n2.dns.podman`），无需手查 IP。这比文档原写的“互 ping”更便利，建议验证时同时覆盖“按名解析”与“按 IP 访问”两种方式。

### 注意事项

1. 镜像内需包含 `ip`、`ping`、`sleep` 等命令；若使用精简镜像（如 distroless），需改用 `podman exec` 从宿主侧或用 `nc` 等可用工具验证。
2. 默认已有 `podman` 网络（`2f259bab93aa  podman  bridge`）属于内置网络，**不属于**残留，清理时不要删除。
3. 若在 rootless 下运行，`ping` 需要 `net.ipv4.ping_group_range` 允许，否则会报 `socket: Operation not permitted`；本实测使用 root（`sudo podman`）无此问题。
