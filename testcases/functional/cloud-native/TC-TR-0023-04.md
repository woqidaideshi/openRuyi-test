# TC-TR-0023-04 ｜ 异常场景与资源清理

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0023（容器运行时功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 云原生 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证无效认证、镜像损坏、空间不足等异常明确报错，失败后资源按策略清理。

## 前置条件

1. 已安装 podman。
2. 具备可创建 tmpfs 小容量目录的条件（root 权限）。
3. 已有一个体积大于 1M 的镜像归档（如约 120 MB 的 rootfs tar），用于触发空间不足。
4. 已有一个可运行的镜像，容器内包含 `uname`，用于验证失败后原有镜像仍可用。

## 测试步骤

1. 用错误凭据拉取私有镜像 `podman pull --creds <用户名>:<密码> <私有仓库>/<镜像>:<标签>`。
2. 用不存在的标签拉取镜像 `podman pull <仓库>/<镜像>:<不存在的标签>`。
3. 在 1M 的 tmpfs 目录下导入超大镜像：
   - 创建并挂载 1M 的 tmpfs `sudo mkdir -p /mnt/tiny && sudo mount -t tmpfs -o size=1M tmpfs /mnt/tiny`；
   - 将该归档导入 tmpfs 目录 `sudo podman --root /mnt/tiny/root --runroot /mnt/tiny/run import <超大镜像归档> <镜像名>:<标签>`。
4. 检查失败后的资源状态与已有镜像可用性：
   - 查看容器列表 `podman ps -a`；
   - 查看镜像列表 `podman images`；
   - 验证已有镜像仍可用 `podman run --rm <已有镜像> uname -m`。
5. 清理：
   - 卸载 tmpfs `sudo umount /mnt/tiny`；
   - 删除挂载点目录 `sudo rmdir /mnt/tiny`。

## 预期结果

1. 步骤 1：拉取失败，退出码为 125，输出明确的认证或网络错误。
2. 步骤 2：拉取失败，退出码为 125，提示仓库层错误（如 `manifest unknown`），不是连接层错误。
3. 步骤 3：tmpfs 挂载成功；导入失败，退出码为 125，提示 `no space left on device`。
4. 步骤 4：无残留容器，原有镜像完好，容器内 `uname -m` 输出 `riscv64`，未出现非目标数据损坏。
5. 步骤 5：tmpfs 已卸载，挂载点目录已删除。
