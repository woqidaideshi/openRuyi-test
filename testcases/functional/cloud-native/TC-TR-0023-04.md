# TC-TR-0023-04 ｜ 异常场景与资源清理

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0023（容器运行时功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 云原生 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证无效认证、镜像损坏、空间不足等异常明确报错，失败后资源按策略清理。

## 前置条件

1. 已安装 podman。
2. 具备可创建 tmpfs 小容量目录的条件（root 权限）。

## 测试步骤

1. 无效认证/私有镜像拉取（错误凭据）：
   ```bash
   podman pull docker.io/private/nonexist:tag
   echo $?
   ```
2. 拉取不存在的标签：
   ```bash
   podman pull docker.io/library/alpine:definitely-not-exist
   echo $?
   ```
3. 空间不足场景（小 tmpfs 下拉取镜像）：
   ```bash
   sudo mkdir -p /mnt/tiny && sudo mount -t tmpfs -o size=1M tmpfs /mnt/tiny
   TMPDIR=/mnt/tiny podman pull docker.io/library/alpine
   echo $?
   sudo umount /mnt/tiny && sudo rmdir /mnt/tiny
   ```
4. 核对失败后资源状态：
   ```bash
   podman ps -a
   podman images
   ```

## 预期结果

1. 步骤 1：无效认证/私有镜像拉取失败，返回非 0，明确报错。
2. 步骤 2：不存在的标签拉取失败，提示 manifest/tag 不存在。
3. 步骤 3：空间不足失败，返回非 0，提示 no space left on device。
4. 步骤 4：失败后无残留容器，无非目标数据损坏。

## 实测记录（2026-11-10，riscv64 物理机，podman 5.8.2）

所有异常场景均返回**非 0 退出码（`125`）**且诊断明确：

| 场景 | 实测关键输出 | rc |
|---|---|---|
| 拉取私有不存在镜像 `docker.io/private/nonexist:tag` | `pinging container registry registry-1.docker.io: … connection reset by peer` | 125 |
| 拉取不存在标签 `quay.io/libpod/alpine:definitely-not-exist` | `reading manifest definitely-not-exist in quay.io/libpod/alpine: **manifest unknown**` | 125 |
| 运行不存在的本地镜像 | `pinging container registry localhost: … connection refused` | 125 |
| 拉取不存在标签 `localhost/tc-base:no-such-tag` | `connection refused`（无本地 registry 服务） | 125 |
| 空间不足（2MB tmpfs 作为 storage root） | `write /usr/bin/ip: **no space left on device**` | 125 |

失败后复核：`residual_containers=0`，镜像列表仍为 `localhost/tc-base:latest`（原镜像完好），基础镜像可正常运行（`uname -m` → `riscv64`，`rc=0`），未出现非目标数据损坏。

### 环境说明与验证要点

1. **docker.io 在本环境不可达**（`curl` 返回 `000`），因此“无效认证”场景实际表现为**网络错误**而非 401；若要验证认证失败，需一个可达的私有仓库。
2. **空间不足场景的正确做法**是限制 **storage root**，而不是设置 `TMPDIR`（文档原写法无效，因为 `podman` 的镜像层写入 graphroot，不写 `TMPDIR`）：
   ```bash
   sudo mkdir -p /mnt/tiny && sudo mount -t tmpfs -o size=2M tmpfs /mnt/tiny
   sudo mkdir -p /mnt/tiny/root /mnt/tiny/run
   sudo podman --root /mnt/tiny/root --runroot /mnt/tiny/run import /tmp/probe.tar probe:1
   # 预期：write ...: no space left on device，rc=125
   sudo umount /mnt/tiny && sudo rmdir /mnt/tiny
   ```
3. 用 `localhost/<img>:<tag>` 测试“标签不存在”时，需先有本地 registry 监听 `localhost:443/5000`，否则得到的是 `connection refused`（连接层错误），**不是** `manifest unknown`（仓库层错误）。两者都属失败，但归因不同，报告时需区分。
