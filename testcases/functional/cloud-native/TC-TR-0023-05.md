# TC-TR-0023-05 ｜ 容器隔离与越权防护

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0023（容器运行时功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 云原生 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证默认容器的内核能力、挂载、设备、宿主文件系统、宿主端口与进程视图均被限制，不存在访问宿主资源的越权通道，并以特权容器、共享宿主 PID 命名空间的容器、共享宿主网络命名空间的容器作对照。

## 前置条件

1. 已安装 podman，具备 root 权限。
2. 已有可运行的镜像，镜像内包含 `mkdir`、`mount`、`wc`、`grep`、`ls`、`cat`、`nc` 等基本工具。
3. 宿主机具备 `python3`，用于启动临时测试服务。

## 测试步骤

1. 启动对照容器：
   - 启动默认（非特权）容器 c1，作为基准 `podman run -d --name c1 <镜像> sleep 300`；
   - 启动特权容器 c2，验证提升权限后各项限制是否放开 `podman run -d --name c2 --privileged <镜像> sleep 300`；
   - 启动共享宿主 PID 命名空间的容器 c3，验证进程视图隔离 `podman run -d --name c3 --pid=host <镜像> sleep 300`；
   - 启动共享宿主网络命名空间的容器 c4，验证网络视图隔离 `podman run -d --name c4 --network=host <镜像> sleep 300`。
2. 检查内核能力与 seccomp 模式：
   - 查看 c1 的有效能力与 seccomp 模式 `podman exec c1 grep -E 'CapEff|Seccomp' /proc/self/status`；
   - 查看 c2 的对应值 `podman exec c2 grep -E 'CapEff|Seccomp' /proc/self/status`。
3. 检查容器能否执行挂载操作：
   - 在 c1 内将 tmpfs 挂载到容器内路径 `/mnt/x` `podman exec c1 sh -c 'mkdir -p /mnt/x && mount -t tmpfs tmpfs /mnt/x'`；
   - 在 c2 内执行同一操作 `podman exec c2 sh -c 'mkdir -p /mnt/x && mount -t tmpfs tmpfs /mnt/x'`。
4. 检查设备可见范围：
   - 列出 c1 可见设备 `podman exec c1 ls /dev`；
   - 列出 c2 可见设备 `podman exec c2 ls /dev`。
5. 检查宿主文件系统可见性：
   - 创建宿主侧文件 `echo secret > /root/host-secret.txt`；
   - 在 c1 内读取该宿主文件 `podman exec c1 cat /root/host-secret.txt`。
6. 检查宿主容器引擎的控制通道：
   - 查看 c1 内是否存在宿主的容器引擎 socket `podman exec c1 ls /run/podman /var/run/docker.sock`；
   - 查看 c2 内是否可见 `podman exec c2 ls /run/podman /var/run/docker.sock`。
7. 检查进程与 cgroup 命名空间：
   - 查看 c1 的 cgroup 路径 `podman exec c1 cat /proc/1/cgroup`；
   - 统计 c1 内可见的进程数 `podman exec c1 sh -c 'ls /proc | grep -c "^[0-9]"'`；
   - 统计 c3 内可见的进程数，与 c1 对照 `podman exec c3 sh -c 'ls /proc | grep -c "^[0-9]"'`；
   - 在宿主机统计进程总数 `ls /proc | grep -c "^[0-9]"`。
8. 测 c1 访问宿主端口的可达性：
   - 在宿主机启动监听所有地址的服务（正对照）`python3 -m http.server 18080 --bind 0.0.0.0`；
   - 在宿主机启动仅监听本机的服务 `python3 -m http.server 18081 --bind 127.0.0.1`；
   - 取 c1 的默认网关（记作 `<网关>`）`podman exec c1 ip route`；
   - 从 c1 访问宿主 18080 端口 `podman exec c1 nc -z -w 2 <网关> 18080`；
   - 从 c1 访问宿主 18081 端口 `podman exec c1 nc -z -w 2 <网关> 18081`；
   - 从 c1 访问宿主未提供服务的 18082 端口 `podman exec c1 nc -z -w 2 <网关> 18082`；
   - 从 c4 访问宿主 127.0.0.1 的 18081 端口，验证 c1 的拒绝是否来自网络命名空间 `podman exec c4 nc -z -w 2 127.0.0.1 18081`；
   - 从 c4 访问宿主 127.0.0.1 的 18082 端口，验证探测方法能否分辨未开放端口 `podman exec c4 nc -z -w 2 127.0.0.1 18082`。
9. 清理：停止宿主机上的两个 `http.server` 进程，删除容器 c1、c2、c3、c4，删除宿主机上的 `/root/host-secret.txt`。

## 预期结果

1. 步骤 1：c1、c2、c3 与 c4 均处于 `running`。
2. 步骤 2：c1 的 `CapEff` 不含 `CAP_SYS_ADMIN`，`Seccomp` 为 `2`（已启用过滤）；c2 含 `CAP_SYS_ADMIN`，`Seccomp` 为 `0`。
3. 步骤 3：c1 报 `permission denied`，c2 挂载成功。
4. 步骤 4：c1 仅可见基础设备，不含 `/dev/mem`、`/dev/kvm` 与任何块设备；c2 可见 `/dev/mem` 与块设备（如 `/dev/nvme0n1`），设备数量明显多于 c1。
5. 步骤 5：c1 内 `/root/host-secret.txt` 不存在。
6. 步骤 6：c1 与 c2 内 `/run/podman`、`/var/run/docker.sock` 均不存在。
7. 步骤 7：c1 的 cgroup 路径为 `0::/`，可见进程数为个位数；c3 可见进程数与宿主机处于同一量级。
8. 步骤 8：c1 到宿主 18080 可连接，18081 与 18082 连接被拒绝；c4 访问宿主 127.0.0.1 的 18081 可连接、18082 连接被拒绝。
9. 步骤 9：容器、宿主临时文件与临时服务均已清理。
