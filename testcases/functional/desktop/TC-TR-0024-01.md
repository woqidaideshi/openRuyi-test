# TC-TR-0024-01 ｜ 显示器基础显示

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0024（显示器正常显示） |
| 测试类型 | 功能测试 |
| 功能模块 | 桌面与显示 |
| 优先级 | P2 |
| 覆盖设备 | 物理机 |
| 可自动化 | 否 |
| 自动化覆盖 | 否 |

## 描述

验证启动时系统日志在显示器上滚动显示，带桌面时登录管理器可显示（本期最低验收）。

## 前置条件

1. riscv64 物理机已连接显示器并正常供电，或 qemu 配置了显示输出。
2. 系统可正常引导；若为桌面版镜像，已安装并可启动显示管理器。

## 测试步骤

1. 接通显示器并上电，观察显示器是否点亮。
2. 观察固件与引导加载程序阶段的显示输出。
3. 观察内核启动阶段日志是否在显示器上滚动输出。
4. 启动完成后通过串口/SSH 辅助确认显示设备与服务：
   ```bash
   ls -la /dev/fb0 /dev/dri 2>&1
   systemctl is-active <显示管理器> 2>/dev/null
   journalctl -b | grep -iE 'display|drm|sddm|lightdm|gdm' | head
   ```
5. 若为桌面版镜像，观察是否正常显示登录管理器。

## 预期结果

1. 步骤 1：显示器正常点亮，无无信号提示。
2. 步骤 2：引导阶段有正常显示输出，无乱码。
3. 步骤 3：内核日志正常滚动显示，字体清晰，无花屏/闪烁/黑屏。
4. 步骤 4：存在 `/dev/fb0` 或 DRM 设备；桌面版显示管理器服务正常。
5. 步骤 5：桌面版镜像正常显示登录管理器，界面完整（判据待图形方向补充）。

## 实测记录与执行条件（2026-11-10，riscv64 物理机）

| 检查项 | 实测结果 |
|---|---|
| `/dev/fb0` | **不存在** |
| `/dev/dri` | **存在**，含 `card0`、`renderD128` |
| DRM 连接器 | `card0-DVI-D-1`、`card0-HDMI-A-1`、`card0-VGA-1`（状态均为 `disconnected`，未接显示器） |
| GPU 驱动 | `radeon 2.51.0` 已初始化（`[drm] Initialized radeon 2.51.0 for 0004:01:00.0`） |
| 显示管理器 | `sddm-0.21.0` 已安装但 `inactive`/`disabled`；`lightdm`/`gdm`/`xdm`/`greetd` 均 `not-found` |
| 默认 target | `graphical.target` |

**结论**：本机为**无头（headless）服务器场景且未接显示器**，所有 DRM 连接器均为 `disconnected`，无法验证“显示器正常显示”。

**重要提示（避免误判）**：
1. 无 `/dev/fb0` **不代表显示异常**——现代内核使用 DRM/KMS，`fb0` 仅在加载 `fbdev` 兼容层或特定配置下存在。判断显示能力应看 **`/dev/dri/card*` + `/sys/class/drm/*/status`**。
2. 连接器 `status=disconnected` 说明监视器未接或线缆未插，此时即使 GPU 正常也不会有显示输出。
3. `graphical.target` 为默认 target 但 `sddm` 未 enable：若产品预期“开机即出现登录管理器”，需确认安装时是否应启用 `sddm`；否则桌面版镜像应在镜像构建阶段启用显示管理器。
4. 真正的显示相关验证需：接入显示器（或 virt-manager 图形窗口）后，结合截图与人工判据执行；可通过串口/SSH 辅助采集 `journalctl -b | grep -iE 'drm|sddm'`。
