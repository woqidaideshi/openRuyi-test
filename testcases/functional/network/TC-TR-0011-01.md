# TC-TR-0011-01 ｜ wifi 连接成功与重启免密

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0011（使用 wifi 联网） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P2 |
| 覆盖设备 | 物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证在**没有缓存凭据**的前提下，使用正确密码完成 wifi 关联、获得地址、链路出口可用，且重启后无需再次输入密码即可自动连接。

## 前置条件

1. 配备真实无线网卡（`iw dev` 能列出无线接口）。
2. 已安装 `wpa_supplicant`、`NetworkManager`、`iw`。
3. 已知目标 SSID 与正确密码，且 AP 使用 WPA/WPA2 加密。
4. 无线网段具备外网出口。若 AP 只提供到网关的连通（无外网出口），应用层验证判为“环境中不可判定”，需在报告中注明，不计为产品失败。
5. **需在可占用整机、允许重启的测试窗口执行**。

## 测试步骤

1. 查看工具与无线能力：
   - 查看 `wpa_supplicant`、`NetworkManager`、`iw` 的安装情况；
   - 查看 `NetworkManager` 运行状态；
   - 执行 `iw dev` 列出无线接口。
2. 删除既有无线连接配置，并记录无线接口地址、默认路由与启动标识（`/proc/sys/kernel/random/boot_id`）基线。
3. 扫描无线网络，查看目标 SSID 及其安全类型。
4. 执行 `nmcli device wifi connect <SSID> password '<密码>'` 以正确密码发起连接，并在 60 秒内执行 `nmcli -f GENERAL.STATE device show <无线接口>` 查看设备状态。
5. 查看连接状态与地址：查看连接对象的激活状态、设备状态、无线接口地址与默认路由。
6. 访问无线出口：先 `ping` 无线网关，再尝试访问外网。
7. 重启系统后记录启动标识并与基线比对，查看设备状态、连接的开机自启属性与重新获取的地址。

> 判断是否具备无线能力要执行 `iw dev`，不要执行 `nmcli radio wifi`——后者在没有任何无线设备时也会返回 `enabled`。
> 必须先删除既有无线 profile，否则 `nmcli device wifi connect` 会复用已保存的 PSK，"用密码连上"未被真正验证。

## 预期结果

1. 步骤 1：
   - 三个工具均已安装；
   - `NetworkManager` 服务已启动；
   - `iw dev` 列出无线接口（含 `phy#0`）；
   - 若 `iw dev` 无输出，本用例不可执行。
2. 步骤 2：既有无线 profile 已删除（或原本不存在）；无线接口无地址，默认路由只剩非无线出口。
3. 步骤 3：扫描结果中出现目标 SSID，安全类型含 `WPA1 WPA2`。
4. 步骤 4：连接命令无报错，设备状态在 60 秒内达到 `100 (connected)`。
5. 步骤 5：
   - 无线 profile 为激活状态（`ACTIVE=yes`）；
   - 设备状态为 `100 (connected)`；
   - 无线接口获得地址；
   - 默认路由出现经无线接口的条目。
6. 步骤 6：`ping` 无线网关丢包率 0%（无线链路与 AP 出口可用）；若无线网段有外网出口，访问外网成功；若 AP 无外网出口，本步骤判为"环境中不可判定"并在报告中注明，不计为产品失败。
7. 步骤 7：
   - 启动标识与重启前不同（确实重启）；
   - 无线 profile 仍为激活状态，设备状态为 `100 (connected)`；
   - `connection.autoconnect` 为 `yes`，且重新获得地址；
   - 即**无需人工输入密码**即完成连接。
