# TC-TR-0011-01 ｜ wifi 连接成功与重启免密

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0011（使用 wifi 联网） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P2 |
| 覆盖设备 | 物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证在**没有缓存凭据**的前提下，使用正确密码完成 wifi 关联、获得地址、链路出口可用，且重启后无需再次输入密码即可自动连接。

## 前置条件

1. 配备真实无线网卡（`iw dev` 能列出无线接口）。
2. 已安装 `wpa_supplicant`、`NetworkManager`、`iw`。
3. 已知目标 SSID 与正确密码，且 AP 使用 WPA/WPA2 加密。
4. 无线网段具备外网出口，用于步骤 6 的应用层验证。若 AP 只提供到网关的连通（无外网出口），该步骤判为"环境中不可判定"，需在报告中注明，不计为产品失败。
5. **需在可占用整机、允许重启的测试窗口执行**。

## 测试步骤

1. 确认工具与无线能力：
   ```bash
   rpm -q wpa_supplicant NetworkManager iw
   systemctl is-active NetworkManager
   iw dev
   ```
   > 提示：判断是否具备无线能力要用 `iw dev`，**不要用 `nmcli radio wifi`**——后者在没有任何无线设备时也会返回 `enabled`。若 `iw dev` 无输出，本用例判为不可执行。

2. 删除既有的无线连接配置，确认回到"无缓存凭据"的起点：
   ```bash
   WIFI_IF=$(iw dev | awk '/Interface/{print $2; exit}')
   nmcli -t -f NAME,TYPE,DEVICE connection show | grep 802-11-wireless
   sudo nmcli connection delete '<无线连接名>' 2>/dev/null || echo "no-wifi-profile"
   ip -br addr show "$WIFI_IF"
   ip route show default
   ```
   > 必须删除或断开既有 profile：否则 `nmcli device wifi connect` 会复用已保存的 PSK，"用密码连上"这一步没有被真正验证。

3. 扫描目标 SSID：
   ```bash
   sudo nmcli device wifi rescan
   sleep 4
   nmcli -t -f SSID,SIGNAL,SECURITY device wifi list | grep '<SSID>'
   ```

4. 用正确密码发起连接，并轮询状态直到就绪（最长 60 秒）：
   ```bash
   sudo nmcli device wifi connect '<SSID>' password '<密码>'
   for i in $(seq 1 12); do
     st=$(nmcli -g GENERAL.STATE device show "$WIFI_IF")
     echo "poll#$i state=$st"
     case "$st" in *"100 (connected)"*|*activated*) break ;; esac
     sleep 5
   done
   ```
   > 连接是异步的，单次读取 `GENERAL.STATE` 常得到 `connecting`/`need-auth`，必须轮询。

5. 确认连接对象与地址分配：
   ```bash
   nmcli -t -f NAME,TYPE,ACTIVE connection show
   nmcli -g GENERAL.CONNECTION device show "$WIFI_IF"
   nmcli -g GENERAL.STATE device show "$WIFI_IF"
   ip -br addr show "$WIFI_IF"
   ip route show default
   ```

6. 验证无线出口可用（分层判定）：
   ```bash
   WIFI_GW=$(ip route show default dev "$WIFI_IF" | awk '{print $3; exit}')
   ping -c 3 -I "$WIFI_IF" "$WIFI_GW"
   ping -c 3 -I "$WIFI_IF" 223.5.5.5
   curl -sI -o /dev/null -w 'wifi_http=%{http_code}\n' --interface "$WIFI_IF" --max-time 10 https://openruyi.cn
   ```

7. 重启后确认免密自动连接：
   ```bash
   cat /proc/sys/kernel/random/boot_id > /var/tmp/tc-wifi.before
   sudo systemctl reboot
   ```

   重启后重新接入，执行：
   ```bash
   cat /proc/sys/kernel/random/boot_id > /var/tmp/tc-wifi.after
   [ "$(cat /var/tmp/tc-wifi.after)" != "$(cat /var/tmp/tc-wifi.before)" ]; echo "bootid-changed:$?"
   WIFI_IF=$(iw dev | awk '/Interface/{print $2; exit}')
   nmcli -t -f NAME,TYPE,ACTIVE connection show
   nmcli -g GENERAL.STATE device show "$WIFI_IF"
   nmcli -g connection.autoconnect connection show '<无线连接名>'
   ip -br addr show "$WIFI_IF"
   rm -f /var/tmp/tc-wifi.before /var/tmp/tc-wifi.after
   ```

## 预期结果

1. 步骤 1：`wpa_supplicant`、`NetworkManager`、`iw` 均输出版本（实测 openEuler 26.09 为 `2.12` / `1.56.0` / `5.19`），`NetworkManager` 为 `active`，`iw dev` 列出 `Interface wlan0`（含 `phy#0`）。
2. 步骤 2：既有无线 profile 被删除（或原本不存在、输出 `no-wifi-profile`）；无线接口无地址（实测删除后 `wlan0` 为 `DOWN`），`ip route show default` 只剩非无线出口（实测只剩 `default via 10.213.0.1 dev eth0`，共 1 条）。
3. 步骤 3：扫描结果中出现目标 SSID，安全类型含 `WPA1 WPA2`（实测多个 BSSID 命中）。
4. 步骤 4：`nmcli device wifi connect` 退出码为 0，轮询在 60 秒内出现 `100 (connected)`（实测第 1 次轮询即达）。
5. 步骤 5：
   - `nmcli -t -f NAME,TYPE,ACTIVE connection show` 中无线 profile 的 `ACTIVE` 为 `yes`（实测 `ISRC-Wifi:802-11-wireless:yes`）；
   - `GENERAL.CONNECTION` 返回该 profile 名，`GENERAL.STATE` 为 `100 (connected)`；
   - 无线接口获得地址（实测 `10.213.22.235/20`），`ip route show default` 出现经无线接口的默认路由（实测 `via 10.213.16.1 dev wlan0 metric 600`）。
6. 步骤 6：
   - `ping -I "$WIFI_IF" "$WIFI_GW"` 丢包率 0%、退出码 0（证明无线链路与 AP 出口可用，实测 RTT 4～32 ms）；
   - 若无线网段有外网出口：`ping 223.5.5.5` 丢包率 0% 且 `curl` 返回 `wifi_http=200`；
   - 若无线网段无外网出口（实测该环境即如此：`ping 223.5.5.5` 100% 丢包、`wifi_http=000`），本步骤判为**环境中不可判定**并在报告中注明，不计为产品失败。
7. 步骤 7：`bootid-changed` 退出码为 0（确认确实重启）；重启后无线 profile 的 `ACTIVE` 为 `yes`、`GENERAL.STATE` 为 `100 (connected)`、`connection.autoconnect` 为 `yes`，且无线接口重新获得地址——即**无需人工输入密码**即完成连接。

## 实测记录

| 项目 | 实测值 |
|---|---|
| 执行环境 | `openEuler 26.09`，`aarch64`，`NetworkManager-1.56.0-4.oe2609.aarch64`、`wpa_supplicant-2.12-1.oe2609.aarch64`、`iw-5.19-1.oe2609.aarch64` |
| 网卡与路由基线 | `eth0` = `10.213.8.121/20`（有线，默认路由 `via 10.213.0.1 metric 100`）；`wlan0` = `10.213.22.235/20`（无线，默认路由 `via 10.213.16.1 metric 600`）；wifi profile `ISRC-Wifi` 已激活且 `autoconnect=yes` |
| **必须先断开/删除 wifi 连接** | 实测 `nmcli connection down ISRC-Wifi` → `down_rc=0`，`nmcli connection delete ISRC-Wifi` → `delete_rc=0`；删除后 profile 列表只剩 `eth0`/`lo`/`docker0`，`wlan0` 变为 `DOWN`、无地址，`ip route show default` 只剩 1 条（有线）。不删除时连接会复用已存 PSK，测不到"用密码认证" |
| 扫描 | `nmcli device wifi rescan` 后 `nmcli -t -f SSID,SIGNAL,SECURITY device wifi list` 命中 `ISRC-Wifi` 共 16 条（多 BSSID），安全类型 `WPA1 WPA2` |
| 正确密码连接 | `sudo nmcli device wifi connect ISRC-Wifi password <PSK>` → `connect_rc=0`；轮询第 1 次即 `100 (connected)`；获得 `10.213.22.235/20`，默认路由 `via 10.213.16.1 dev wlan0 metric 600` |
| 无线出口能力 | 经 `wlan0`：`ping 10.213.16.1`（AP 网关）0% 丢包，RTT 4.4～31.9 ms；`ping 223.5.5.5` **100% 丢包**；`curl --interface wlan0 https://openruyi.cn` → `000`/rc=28。即该 AP **只提供到网关的连通、无外网出口**，因此步骤 6 的应用层判据在本环境不可判定，不是产品缺陷 |
| **字段名坑** | `nmcli -t -f ACTIVE,SSID connection show` 实测报错：`invalid field 'SSID'; allowed fields: NAME,UUID,TYPE,...,ACTIVE,DEVICE,STATE,...`。原因不是引号：三种写法（不加引号、`"ACTIVE,SSID"`、`'ACTIVE,SSID'`）报错完全一致，因为 `-f` 的取值是 nmcli 字段名、不经 shell 展开；根因是 connection 对象没有 SSID 字段。正确取 SSID：`nmcli -t -f ACTIVE,SSID device wifi` → `yes:ISRC-Wifi`，或 `nmcli -g 802-11-wireless.ssid connection show ISRC-Wifi` → `ISRC-Wifi` |
| 免密判据可判定化 | 原 CSV 的"检查未产生再次输入密码的交互"无法机械断言；改为三条可测结果：`ACTIVE=yes`、`GENERAL.STATE=100 (connected)`、`connection.autoconnect=yes`，配合 `boot_id` 变化确认重启 |
| 测试通道约束 | 该机 `eth0`（10.213.8.121）与 `wlan0`（10.213.22.235）分属不同网段；从测试侧访问 `10.213.22.235` 实测 100% 丢包、SSH 超时，因此**不能通过断开有线来验证无线独占出口**，否则会失去对机器的控制。若环境存在可路由到无线网段的管理通道，才可按 CSV 步骤 2 断开有线 |
| 重新连接耗时 | 删除 profile 后重新连接与关联耗时 < 5 秒（轮询首轮即完成），但轮询与超时仍应保留，换 AP 或弱信号场景会明显变慢 |
