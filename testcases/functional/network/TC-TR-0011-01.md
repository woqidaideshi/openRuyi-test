# TC-TR-0011-01 ｜ wifi 连接成功与重启免密

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0011（使用 wifi 联网） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P2 |
| 覆盖设备 | 物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证在**没有缓存凭据**的前提下，使用正确密码完成 wifi 连接、获得地址、链路出口可用，且重启后无需再次输入密码即可自动连接。

## 前置条件

1. 配备真实无线网卡（`iw dev` 能列出无线接口），且测试期间不占用其他无线连接。
2. 已安装 `wpa_supplicant`、`NetworkManager`、`iw`；若现场 AP 使用 SAE，则 `wpa_supplicant -v` 版本不低于 2.9。
3. 已知目标 SSID 与正确密码；AP 该 SSID 已配置好认证方式（WPA-PSK/WPA2-PSK、WPA3-SAE 或 WPA2-PSK/WPA3-SAE 混合）。
4. 无线网段具备外网出口；若 AP 无外网出口（仅能连通网关），访问外网判为“环境中不可判定”并注明，不计为产品失败。
5. **需在可占用整机、允许重启的测试窗口执行**。

## 测试步骤

1. 查看工具与无线能力：
   - 查看三个工具的安装情况与版本：`rpm -q wpa_supplicant NetworkManager iw`
   - 查看 `NetworkManager` 运行状态：`systemctl is-active NetworkManager`
   - 执行 `iw dev` 列出无线接口
2. 执行 `nmcli connection delete <连接名>` 删除既有无线连接配置，其中 `<连接名>` 为 `nmcli connection show` 的 `NAME` 列，默认与 SSID 相同），并记录无线接口无地址、无无线默认路由的基线以及启动标识（`/proc/sys/kernel/random/boot_id`）。
3. 执行 `nmcli device wifi list --rescan yes` 扫描无线网络，查看目标 SSID 及其安全类型。
4. 执行 `nmcli device wifi connect <SSID> password '<密码>'` 发起连接，并在 60 秒内执行 `nmcli -f GENERAL.STATE device show <无线接口>` 查看设备状态。
5. 查看连接与地址路由：
   - 激活的连接：`nmcli connection show --active`
   - 实际密钥管理方式：`wpa_cli -i <无线接口> status | grep key_mgmt`
   - 无线接口地址：`ip addr`
   - 默认路由：`ip route`
6. 访问无线网关：`ping` 无线网关。
7. 访问外网：执行 `curl -sL -o /dev/null -w '%{http_code}' https://openruyi.cn` 查看外网访问结果。
8. 重启系统，记录启动标识（`/proc/sys/kernel/random/boot_id`）并与步骤 2 的基线比对，复核设备状态、连接的开机自启属性（`nmcli -f connection.autoconnect connection show <连接名>`）与重新获取的地址。
9. 删除测试产生的无线连接配置。

> 如需覆盖其它认证方式，更换 AP 或修改其配置后重新执行本用例，并在报告中注明当次被测的认证方式（如 WPA2-PSK、WPA3-SAE）。
> 判断是否具备无线能力要执行 `iw dev`，不要执行 `nmcli radio wifi`——后者在没有任何无线设备时也会返回 `enabled`。
> 必须先删除既有无线 profile，否则 `nmcli device wifi connect` 会复用已保存的 PSK，"用密码连上"未被真正验证。

## 预期结果

1. 步骤 1：
   - 三个工具均已安装，且 `rpm -q` 输出中 `wpa_supplicant` 版本不低于 2.9；
   - `NetworkManager` 服务已启动；
   - `iw dev` 列出无线接口（含 `phy#0`）；
   - 若 `iw dev` 无输出，本用例不可执行。
2. 步骤 2：既有无线 profile 已删除（或原本不存在）；无线接口无地址，默认路由不含无线出口；启动标识已记录。
3. 步骤 3：扫描结果中出现目标 SSID，其 `SECURITY` 列含 `WPA1`/`WPA2`/`WPA3` 中至少一项（如 `WPA2`、`WPA1 WPA2`、`WPA3`、`WPA2 WPA3`），且不含 `802.1X`；记录当次取值。若 `SECURITY` 列为空（开放网络）或仅 `WEP`，本用例不适用。
4. 步骤 4：连接命令无报错，设备状态在 60 秒内达到 `100 (connected)`。
5. 步骤 5：
   - 激活的连接列表中存在目标 SSID 的 profile（`TYPE` 为 `wifi`，`DEVICE` 为无线接口）；
   - 实际 `key_mgmt` 与步骤 3 记录的 `SECURITY` 对应：`WPA1`/`WPA2`/`WPA1 WPA2` 时为 `WPA-PSK`/`WPA2-PSK`；`WPA3` 时为 `SAE`；`WPA2 WPA3` 时为 `SAE` 或 `WPA2-PSK`；不得为 `NONE` 或 `WPA-EAP`；
   - 无线接口获得地址；
   - 默认路由出现经无线接口的条目。
6. 步骤 6：`ping` 无线网关丢包率 0%（无线链路与 AP 出口可用）。
7. 步骤 7：外网访问成功，`curl` 返回 `http_code=200`；若 AP 无外网出口，本项判为"环境中不可判定"并在报告中注明，不计为产品失败。
8. 步骤 8：启动标识与重启前不同（确实重启）；无线 profile 仍为激活状态，设备状态为 `100 (connected)`；`connection.autoconnect` 为 `yes`，且重新获得地址；即**无需人工输入密码**即完成连接。
9. 步骤 9：测试 profile 已删除，无残留连接配置。
