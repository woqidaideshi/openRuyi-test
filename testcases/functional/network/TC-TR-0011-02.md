# TC-TR-0011-02 ｜ wifi 错误密码拒绝

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0011（使用 wifi 联网） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P2 |
| 覆盖设备 | 物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证在**没有缓存凭据**的前提下，使用错误密码连接 wifi 被拒绝：连接不建立、不获得地址、不产生默认路由，且返回非 0 退出码与明确的认证失败提示。

## 前置条件

1. 配备真实无线网卡（`iw dev` 能列出无线接口）。
2. 已安装 `wpa_supplicant`、`NetworkManager`、`iw`。
3. 已知目标 SSID 与**正确密码**（用于步骤 6 恢复连接）及一个**错误密码**。
4. AP 必须启用 WPA/WPA2 认证。若 AP 未启用认证，错误密码也会连上，此时本用例不适用。
5. 需在可占用整机的测试窗口执行（步骤 2 会删除现有无线连接配置）。

## 测试步骤

1. 确认工具与无线能力：
   ```bash
   rpm -q wpa_supplicant NetworkManager iw
   systemctl is-active NetworkManager
   iw dev
   ```
   > 判断是否具备无线能力要用 `iw dev`，**不要用 `nmcli radio wifi`**——后者在没有任何无线设备时也会返回 `enabled`。若 `iw dev` 无输出，本用例判为不可执行。

2. 删除既有无线连接配置，记录"无凭据"基线：
   ```bash
   WIFI_IF=$(iw dev | awk '/Interface/{print $2; exit}')
   sudo nmcli connection delete '<无线连接名>' 2>/dev/null || echo "no-wifi-profile"
   ip -br addr show "$WIFI_IF" > /var/tmp/tc-wifi-before.addr
   ip route show default > /var/tmp/tc-wifi-before.route
   cat /var/tmp/tc-wifi-before.addr
   cat /var/tmp/tc-wifi-before.route
   ```

3. 使用错误密码发起连接：
   ```bash
   sudo nmcli device wifi connect '<SSID>' password '<错误密码>'
   echo "wrong-connect:$?"
   ```

4. 确认设备未进入已连接状态（等待并观察最多 30 秒）：
   ```bash
   for i in $(seq 1 6); do
     st=$(nmcli -g GENERAL.STATE device show "$WIFI_IF")
     echo "poll#$i state=$st"
     case "$st" in *"100 (connected)"*) break ;; esac
     sleep 5
   done
   ```

5. 确认未获得地址、未建立无线默认路由、无激活的无线 profile：
   ```bash
   ip -br addr show "$WIFI_IF"
   ip route show default
   ip route show default dev "$WIFI_IF"
   echo "wifi-default-count=$(ip route show default dev "$WIFI_IF" | wc -l)"
   nmcli -t -f NAME,TYPE,ACTIVE connection show
   ```

6. 用正确密码恢复连接，避免破坏环境：
   ```bash
   sudo nmcli device wifi connect '<SSID>' password '<正确密码>'
   echo "restore-connect:$?"
   sleep 8
   nmcli -g GENERAL.STATE device show "$WIFI_IF"
   ip -br addr show "$WIFI_IF"
   ip route show default
   rm -f /var/tmp/tc-wifi-before.addr /var/tmp/tc-wifi-before.route
   ```

## 预期结果

1. 步骤 1：`wpa_supplicant`、`NetworkManager`、`iw` 均输出版本，`NetworkManager` 为 `active`，`iw dev` 列出无线接口。
2. 步骤 2：既有无线 profile 被删除（或输出 `no-wifi-profile`）；基线文件中无线接口无地址、默认路由不含无线出口（实测删除后 `wlan0` 为 `DOWN`，默认路由只剩 1 条有线）。
3. 步骤 3：`nmcli device wifi connect` **退出码非 0**（实测为 `4`）。
4. 步骤 4：轮询期间 `GENERAL.STATE` 始终未出现 `100 (connected)`（实测最终为 `30 (disconnected)`）。
5. 步骤 5：
   - `ip -br addr show "$WIFI_IF"` 无 IPv4 地址（实测为 `wlan0 DOWN`）；
   - `wifi-default-count` 为 `0`，`ip route show default` 与基线一致（未被无线路由污染）；
   - `nmcli -t -f NAME,TYPE,ACTIVE connection show` 中不存在 `ACTIVE=yes` 的 802-11-wireless 条目。
6. 步骤 6：`restore-connect` 退出码为 0，`GENERAL.STATE` 恢复为 `100 (connected)`，无线接口重新获得地址并出现无线默认路由，环境回到可用状态。

## 实测记录

| 项目 | 实测值 |
|---|---|
| 执行环境 | `openEuler 26.09`，`aarch64`，`NetworkManager-1.56.0-4.oe2609.aarch64`、`wpa_supplicant-2.12-1.oe2609.aarch64`、`iw-5.19-1.oe2609.aarch64` |
| 前置清理 | `nmcli connection delete ISRC-Wifi` → `delete_rc=0`；删除后 `wlan0` 为 `DOWN`、无地址，`ip route show default` 只剩 `default via 10.213.0.1 dev eth0` |
| 错误密码结果 | `sudo nmcli device wifi connect ISRC-Wifi password <错误密码>` → **退出码 `4`**；输出：`Passwords or encryption keys are required to access the wireless network 'ISRC-Wifi'.` 与 `Error: Connection activation failed: Secrets were required, but not provided.` |
| 失败后状态 | `wlan0` 为 `DOWN`，无 IPv4 地址；`ip route show default dev wlan0` 为空（计数 0）；`GENERAL.STATE` 为 `30 (disconnected)` |
| 恢复结果 | 用正确密码重新连接 → `restore_connect_rc=0`，`systemctl` 无介入，`wlan0:connected`，环境恢复 |
| **字段名坑** | `nmcli -t -f ACTIVE,SSID connection show` 实测报错 `invalid field 'SSID'`。原因不是引号：不加引号、双引号、单引号三种写法报错完全一致，因为 `-f` 是 nmcli 字段名而非 shell 字符串；根因是 connection 对象无 SSID 字段。正确取 SSID：`nmcli -t -f ACTIVE,SSID device wifi` 或 `nmcli -g 802-11-wireless.ssid connection show <名称>` |
| 判据可判定化 | 原 CSV 只要求"记录退出码与提示"；本用例补充了三条客观判据：状态非 `connected`、无地址、`wifi-default-count=0`，避免"提示看起来像失败但实际已连上"的误判 |
| 与 `TC-TR-0011-01` 的关系 | 两条用例共用"删除既有 profile"的起点：`-01` 验证正确密码能连上，`-02` 验证错误密码连不上。若 `-01` 未删除 profile，`-02` 也会因复用缓存 PSK 而不成立 |
