# TC-TR-0011-02 ｜ wifi 错误密码拒绝

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0011（使用 wifi 联网） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P2 |
| 覆盖设备 | 物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证在**没有缓存凭据**的前提下，使用错误密码连接 wifi 被拒绝：连接不建立、不获得地址、不产生默认路由，且返回非 0 退出码与明确的认证失败提示。

## 前置条件

1. 配备真实无线网卡（`iw dev` 能列出无线接口），且测试期间不占用其他无线连接。
2. 已安装 `wpa_supplicant`、`NetworkManager`、`iw`。
3. 已知目标 SSID、**正确密码**与一个**错误密码**。
4. AP 必须启用 **WPA-PSK/WPA2-PSK、WPA3-SAE 或 WPA2-PSK/WPA3-SAE 混合** 认证（非开放网络、非 802.1X/EAP）。若 AP 未启用认证，错误密码也会连上，此时本用例不适用。
5. 需在可占用整机的测试窗口执行。

## 测试步骤

1. 查看工具与无线能力：查看 `wpa_supplicant`、`NetworkManager`、`iw` 的安装情况与 `NetworkManager` 运行状态，并执行 `iw dev` 列出无线接口。
2. 删除既有的无线连接配置，并记录无线接口无地址、无无线默认路由的基线。
3. 执行 `nmcli device wifi list --rescan yes` 扫描无线网络，查看目标 SSID 及其安全类型。
4. 使用错误密码发起连接：执行 `nmcli device wifi connect <SSID> password '<错误密码>'`。
5. 等待后执行 `nmcli -f GENERAL.STATE device show <无线接口>` 查看设备状态——PSK 环境等待 30 秒；SAE 与混合模式等待 120 秒（SAE 握手失败前会重试若干次）。
6. 查看连接与地址路由：
   - 激活的连接：`nmcli connection show --active`
   - 无线接口地址：`ip addr`
   - 默认路由：`ip route`
7. 用正确密码重新连接，恢复环境。

> 判断是否具备无线能力要用 `iw dev`，不要用 `nmcli radio wifi`。

## 预期结果

1. 步骤 1：三个工具均已安装，`NetworkManager` 服务已启动，`iw dev` 列出无线接口。若 `iw dev` 无输出，本用例不可执行。
2. 步骤 2：既有无线 profile 已删除；无线接口无地址，默认路由不含无线出口。
3. 步骤 3：扫描结果中出现目标 SSID，其 `SECURITY` 列含 `WPA1`/`WPA2`/`WPA3` 中至少一项（如 `WPA2`、`WPA1 WPA2`、`WPA3`、`WPA2 WPA3`），且不含 `802.1X`；记录当次取值。若 `SECURITY` 列为空（开放网络）或仅 `WEP`，本用例不适用。
4. 步骤 4：连接命令失败并返回非 0 退出码，提示密码或加密密钥不正确。
5. 步骤 5：在对应等待窗口内（PSK 30 秒、SAE 与混合模式 120 秒）设备状态未出现 `100 (connected)`。
6. 步骤 6：
   - 激活的连接列表中不存在目标 SSID 的 profile（`TYPE` 为 `wifi`）；
   - 无线接口无 IPv4 地址；
   - 无经无线接口的默认路由（与基线一致）。
7. 步骤 7：重新连接成功，设备状态恢复为 `100 (connected)`，无线接口重新获得地址并出现无线默认路由，环境回到可用状态。
