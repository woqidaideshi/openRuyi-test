# TC-TR-0011-02 ｜ wifi 错误密码拒绝

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0011（使用 wifi 联网） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P2 |
| 覆盖设备 | 物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证在**没有缓存凭据**的前提下，使用错误密码连接 wifi 被拒绝：连接不建立、不获得地址、不产生默认路由，且返回非 0 退出码与明确的认证失败提示。

## 前置条件

1. 配备真实无线网卡（`iw dev` 能列出无线接口）。
2. 已安装 `wpa_supplicant`、`NetworkManager`、`iw`。
3. 已知目标 SSID、**正确密码**与一个**错误密码**。
4. AP 必须启用 WPA/WPA2 认证。若 AP 未启用认证，错误密码也会连上，此时本用例不适用。
5. 需在可占用整机的测试窗口执行。

## 测试步骤

1. 查看工具与无线能力：查看 `wpa_supplicant`、`NetworkManager`、`iw` 的安装情况与 `NetworkManager` 运行状态，并执行 `iw dev` 列出无线接口。
2. 删除既有的无线连接配置，并记录无线接口无地址、无无线默认路由的基线。
3. 扫描无线网络，查看目标 SSID 及其加密方式。
4. 使用错误密码发起连接：`nmcli device wifi connect`。
5. 等待 30 秒后，执行 `nmcli -f GENERAL.STATE device show <无线接口>` 查看设备状态。
6. 查看无线接口地址、默认路由与连接状态。
7. 用正确密码重新连接，恢复环境。

> 判断是否具备无线能力要用 `iw dev`，不要用 `nmcli radio wifi`。

## 预期结果

1. 步骤 1：三个工具均已安装，`NetworkManager` 为 `active`，`iw dev` 列出无线接口。若 `iw dev` 无输出，本用例不可执行。
2. 步骤 2：既有无线 profile 已删除；无线接口无地址，默认路由不含无线出口。
3. 步骤 3：扫描结果中出现目标 SSID，安全类型为 WPA/WPA2。若显示为开放网络（无加密），错误密码也会连上，本用例不适用，应直接结束并注明。
4. 步骤 4：连接命令失败并返回非 0 退出码，提示密码或加密密钥不正确。
5. 步骤 5：设备状态未出现 `100 (connected)`。
6. 步骤 6：
   - 无线接口无 IPv4 地址；
   - 无经无线接口的默认路由（与基线一致）；
   - 连接列表中不存在激活的无线连接。
7. 步骤 7：重新连接成功，设备状态恢复为 `100 (connected)`，无线接口重新获得地址并出现无线默认路由，环境回到可用状态。
