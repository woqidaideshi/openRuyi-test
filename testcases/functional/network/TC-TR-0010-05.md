# TC-TR-0010-05 ｜ 防火墙规则（nftables 直连）

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

在独立网络命名空间内直接操作 `nftables`，验证允许与拒绝规则正确生效：放行端口可从对端访问，未放行端口不被意外放通，删除放行规则后访问立即被阻断，且清理后规则集恢复基线。

## 前置条件

1. 已安装 `nftables`（提供 `nft` 命令）与 `python3`。
2. 具备 root 权限（sudo）。
3. 需要一个“对端”发起访问。本用例使用**主机自身的独立网络命名空间**作为对端，不依赖外部主机。
4. 系统可能已存在其他规则，**不得以"规则集为空"作为判据**，只能对比本次新增/删除的部分。
5. 被测环境可能已安装并启用 `firewalld`。注意，安装 firewalld 会替换/升级 `nftables`。

## 测试步骤

1. 查看 `nftables` 版本（`nft` 命令可用性），记录基线：当前 `nft` 完整规则集输出（表、链、规则，不含计数器值）。
2. 建立隔离环境：创建网络命名空间与一对 `veth`，在命名空间内为两个端口启动 HTTP 监听。
3. 在未加任何规则时，从主机访问命名空间内的两个端口（对照基线）。
4. 在命名空间的 `input` 链上下发"默认拒绝 + 仅放行 `8899`"策略。
5. 从主机访问两个端口；随后清空放行规则，再次访问 `8899`。
6. 清理：删除命名空间与 `veth`，查看规则集并与基线对照。

> 命名空间作为"对端"，避免修改宿主机策略影响自身流量。系统可能已有其他规则，判定只看本次新增与删除的部分，不以"规则集为空"为判据。

## 预期结果

1. 步骤 1：`nftables` 已安装、`nft` 命令可用；基线记录完成，内容为完整规则集（表、链、规则），不含计数器值，仅用于清理后比对。
2. 步骤 2：命名空间与 `veth` 创建成功，两个端口均处于 `LISTEN`。
3. 步骤 3：两个端口均返回 `200`，无规则时均可访问。
4. 步骤 4：规则下发无报错；规则集显示 `policy drop` 与 `tcp dport 8899 accept`。
5. 步骤 5：
   - 放行端口返回 `200`；
   - 未放行端口返回 `000`、访问失败（**无意外放行**）；
   - 清空放行规则后 `8899` 也返回 `000`（删除规则后立即被阻断）。
6. 步骤 6：命名空间与 `veth` 已删除，规则集与基线一致。
