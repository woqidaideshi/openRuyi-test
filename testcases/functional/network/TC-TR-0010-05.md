# TC-TR-0010-05 ｜ 防火墙规则（nftables 直连）

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

在独立网络命名空间内直接操作 `nftables`，验证允许与拒绝规则正确生效：放行端口可从对端访问，未放行端口不被意外放通，删除放行规则后访问立即被阻断，且清理后规则集恢复基线。

## 前置条件

1. 已安装 `nftables`（提供 `nft` 命令）与 `python3`。
2. 具备 root 权限（sudo）。
3. 需要一个"对端"发起访问。本用例使用**主机自身的独立网络命名空间**作为对端（步骤 2），不依赖外部主机。
4. 系统可能已存在其他规则，**不得以"规则集为空"作为判据**，只能对比本次新增/删除的部分。
5. 被测环境可能已安装并启用 `firewalld`。注意，安装 firewalld 会替换/升级 `nftables`。

## 测试步骤

1. 确认 `nftables` 已安装并记录防火墙基线：
   ```bash
   CASE_TMP=/var/tmp/tc-fw && rm -rf $CASE_TMP && mkdir -p $CASE_TMP
   rpm -q nftables || echo "MISSING:nftables"
   command -v nft
   sudo nft list ruleset > $CASE_TMP/before.ruleset
   wc -l < $CASE_TMP/before.ruleset
   ```
2. 建立隔离测试环境（命名空间作对端，两个监听端口）：
   ```bash
   sudo ip netns add tcfw
   sudo ip link add fv0 type veth peer name fv1
   sudo ip link set fv1 netns tcfw
   sudo ip addr add 198.51.100.1/24 dev fv0
   sudo ip link set fv0 up
   sudo ip netns exec tcfw ip addr add 198.51.100.2/24 dev fv1
   sudo ip netns exec tcfw ip link set fv1 up
   sudo ip netns exec tcfw ip link set lo up
   sudo ip netns exec tcfw setsid python3 -m http.server 8899 >/dev/null 2>&1 < /dev/null &
   sudo ip netns exec tcfw setsid python3 -m http.server 8898 >/dev/null 2>&1 < /dev/null &
   sleep 1
   sudo ip netns exec tcfw ss -ltn
   ```
3. 确认未加规则时两个端口均可达（对照基线）：
   ```bash
   curl -s -o /dev/null -w 'allow=%{http_code}\n' --max-time 4 http://198.51.100.2:8899/
   curl -s -o /dev/null -w 'deny=%{http_code}\n' --max-time 4 http://198.51.100.2:8898/
   ```
4. 下发"默认拒绝 + 仅允许 8899"策略：
   ```bash
   sudo ip netns exec tcfw nft add table inet fwt
   sudo ip netns exec tcfw nft add chain inet fwt input '{ type filter hook input priority filter; policy drop; }'
   sudo ip netns exec tcfw nft add rule inet fwt input tcp dport 8899 accept
   sudo ip netns exec tcfw nft add rule inet fwt input iif lo accept
   sudo ip netns exec tcfw nft list table inet fwt
   ```
5. 从对端验证允许、拒绝与删除后的失效：
   ```bash
   curl -s -o /dev/null -w 'allow=%{http_code}\n' --max-time 4 http://198.51.100.2:8899/
   curl -s -o /dev/null -w 'deny=%{http_code}\n' --max-time 4 http://198.51.100.2:8898/
   sudo ip netns exec tcfw nft flush chain inet fwt input
   curl -s -o /dev/null -w 'after_remove=%{http_code}\n' --max-time 4 http://198.51.100.2:8899/
   ```
6. 清理并确认规则集恢复基线：
   ```bash
   sudo ip netns del tcfw
   sudo ip link del fv0 2>/dev/null
   sudo nft list ruleset > $CASE_TMP/after.ruleset
   diff $CASE_TMP/before.ruleset $CASE_TMP/after.ruleset
   echo "ruleset-diff=$?"
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：`rpm -q nftables` 输出版本（实测 `nftables-1.1.6-9.4.or.riscv64`），不输出 `MISSING:nftables`；`command -v nft` 输出 `/usr/bin/nft`；`before.ruleset` 生成并输出行数（行数因环境而异，仅作为清理后的比对依据）。
2. 步骤 2：命名空间与 `veth` 建立成功（各命令退出码为 0），`ss -ltn` 显示 `8898`、`8899` 均处于 `LISTEN`。
3. 步骤 3：`allow=200` 与 `deny=200`，两个端口在无规则时均可访问（对照基线成立）。
4. 步骤 4：三条 `nft add` 退出码均为 0；`nft list table inet fwt` 显示 `policy drop` 与 `tcp dport 8899 accept`。
5. 步骤 5：
   - 放行端口 `8899` 返回 `200`（允许规则生效）；
   - 未放行端口 `8898` 返回 `000`、`curl` 退出码 `28`（**无意外放行**）；
   - 清空规则链后 `8899` 也返回 `000`、退出码 `28`（删除放行规则后立即被阻断）。
6. 步骤 6：`tcfw` 命名空间与 `fv0` 已删除，`after.ruleset` 与 `before.ruleset` 的 `diff` 退出码为 0（`ruleset-diff=0`），`$CASE_TMP` 已删除。

## 实测记录

| 项目 | 实测值 |
|---|---|
| 基线规则集 | **基线行数因环境而异**：实测同一台机器上先后出现 87 行（含 `table ip libvirt_network`、`table ip6 libvirt_network`、`table inet netavark`）、0 行（两次重启后 libvirtd/netavark 尚未重建规则）、364 行（安装并启用 firewalld 后，含 `table inet firewalld`）。因此判定只能用"清理后与基线 diff"，不能写死行数，也不能要求规则集为空 |
| 允许 + 默认拒绝 | 命名空间内 `policy drop`、仅 `tcp dport 8899 accept` 时：`8899` 返回 `200`，`8898` 返回 `000`、`curl` 退出码 `28` |
| 删除放行规则 | `nft flush chain` 后 `8899` 返回 `000`、退出码 `28`，说明拒绝立即生效 |
| 为何用命名空间 | 宿主上的 `input` 策略改为 `drop` 会影响宿主自身流量，因此策略类验证必须放在隔离命名空间内完成 |
| loopback 不足为判据 | 实测宿主机上 `policy accept` + `tcp dport 8899 drop` 时，`curl http://127.0.0.1:8899/` 返回 `000`（回环流量确实经过 `input` 钩子），但这只能证明"本机自访问被拒"，无法证明对外生效，故以命名空间对端（`198.51.100.2`）为准 |
| 跨主机对端（补充验证） | 实测从另一台主机（`10.20.238.103`）访问目标机 `10.213.6.175:8899`：放行时 `200`；下发 `drop` 后 `000`/`28`；同时 `22` 端口连接正常（`rc=0`），说明规则只作用于目标端口 |
| 清理方式 | `ip netns del` 会连带终止命名空间内的监听进程并销毁 `veth` 对端（实测删除后无残留监听，`ruleset` 与基线 `diff=0`）。**禁止**用 `pkill -f '<命令串>'`：实测通过 `ssh host '...'` 执行时会匹配到执行者自身命令行，导致 shell 被杀、清理中断（残留 `pid`），必须按 PID 或依赖命名空间销毁 |
| 未安装组件（历史记录） | 首次执行时实测 `rpm -q firewalld iptables` 均报 `not installed`，仅有 `nftables-1.1.5`；后续已可通过 `dnf install -y firewalld` 安装并测试，相关路径见 `TC-TR-0010-04`。另：`rpm -q wget` 也报未安装，但 `wget` 命令由 `wget2-wget` 提供（`GNU Wget2 2.2.1`），命令可用 |
