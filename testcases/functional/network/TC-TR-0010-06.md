# TC-TR-0010-06 ｜ 管理链路中断后的自动恢复

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

在真实管理链路上断开并恢复链路，验证 NetworkManager 能按既有配置自动重新应用（地址、默认路由、DNS 恢复，连通性恢复），无需人工执行 `nmcli connection up` 或重启网络服务。

## 前置条件

1. 已安装 `NetworkManager`、`iproute2`、`iputils`。
2. **被测连接必须为 `autoconnect=yes`**（`nmcli -g connection.autoconnect connection show '<连接>'`）；否则链路恢复后不会自动重连，本用例不适用。
3. **必须独占整机，并具备带外控制台（串口/IPMI/KVM）或物理接触条件**：步骤 3 主动断开被测链路后，需具备带外恢复手段。
4. 被测机的地址配置方式已知（静态或 DHCP），用于判定恢复后的地址是否与配置一致。
5. 机器上不要运行其他需要网络的任务，恢复期间网络会中断约 20～40 秒。

## 测试步骤

1. 自动探测环境并记录入口基线：
   ```bash
   CASE_TMP=/var/tmp/tc-net-recover && rm -rf $CASE_TMP && mkdir -p $CASE_TMP

   IFACE=$(ip route show default | awk '{print $5; exit}')
   CON=$(nmcli -g GENERAL.CONNECTION device show "$IFACE" | head -1)
   GW=$(ip route show default | awk '{print $3; exit}')
   CIDR=$(ip -o -4 addr show dev "$IFACE" | awk '{print $4; exit}')
   AUTOCONN=$(nmcli -g connection.autoconnect connection show "$CON")

   cat > $CASE_TMP/env.sh <<EOF
   IFACE=$IFACE
   CON="$CON"
   GW=$GW
   CIDR=$CIDR
   EOF

   ip -br addr > $CASE_TMP/before.addr
   ip route > $CASE_TMP/before.route
   cat /etc/resolv.conf > $CASE_TMP/before.resolv
   cat $CASE_TMP/env.sh
   echo "autoconnect=$AUTOCONN"
   ```
2. 设置自动恢复安全网（先启用链路，再兜底重连）：
   ```bash
   CASE_TMP=/var/tmp/tc-net-recover && . $CASE_TMP/env.sh
   sudo setsid bash -c '
     . /var/tmp/tc-net-recover/env.sh
     sleep 20
     ip link show "$IFACE" | grep -q "state UP" || ip link set "$IFACE" up
     echo "watchdog-link-up $(date +%T)" >> /var/tmp/tc-net-recover/watchdog.log
     sleep 30
     if ! ip -o -4 addr show dev "$IFACE" | grep -q .; then
       nmcli connection up "$CON" >> /var/tmp/tc-net-recover/watchdog.log 2>&1
       echo "watchdog-nmcli-up $(date +%T)" >> /var/tmp/tc-net-recover/watchdog.log
     fi
   ' >/dev/null 2>&1 < /dev/null &
   sleep 1
   echo "watchdog started"
   ```
3. 断开管理链路：

   执行后当前连接立即中断，链路将在约 20 秒后由安全网拉起：
   ```bash
   CASE_TMP=/var/tmp/tc-net-recover && . $CASE_TMP/env.sh
   sudo ip link set "$IFACE" down
   ```
4. 等待并重新接入，确认链路已被拉起：
   ```bash
   CASE_TMP=/var/tmp/tc-net-recover && . $CASE_TMP/env.sh
   cat $CASE_TMP/watchdog.log
   ip -br addr show "$IFACE"
   ```
5. 验证 NetworkManager 已按配置自动恢复：
   ```bash
   CASE_TMP=/var/tmp/tc-net-recover && . $CASE_TMP/env.sh
   ip -br addr show "$IFACE"
   ip route
   cat /etc/resolv.conf
   ping -c 4 "$GW"
   nmcli -g GENERAL.STATE device show "$IFACE"
   ```
6. 核对未发生兜底重连，并清理：
   ```bash
   CASE_TMP=/var/tmp/tc-net-recover && . $CASE_TMP/env.sh
   grep -c "watchdog-nmcli-up" $CASE_TMP/watchdog.log
   diff $CASE_TMP/before.route <(ip route); echo "route-diff=$?"
   diff $CASE_TMP/before.resolv /etc/resolv.conf; echo "resolv-diff=$?"
   ping -c 3 "$GW"
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：`IFACE`、`CON`、`GW`、`CIDR` 均探测出非空值（实测 `eth2` / `Wired connection 2` / `10.213.0.1` / `10.213.6.175/20`），`autoconnect=yes`；`before.addr`、`before.route`、`before.resolv` 均已生成。
2. 步骤 2：安全网启动成功，`watchdog.log` 尚不存在（尚未触发）。
3. 步骤 3：`ip link set "$IFACE" down` 执行后管理会话中断（这是预期现象）。
4. 步骤 4：重新接入成功；`watchdog.log` 含 `watchdog-link-up`，`ip -br addr` 显示接口已 `UP`。
5. 步骤 5：
   - 地址恢复为 `$CIDR`（静态配置）或重新获取到同网段地址（DHCP）；
   - `ip route` 恢复默认路由（`default via $GW`）；
   - `/etc/resolv.conf` 恢复原有 `nameserver`；
   - `ping $GW` 0% 丢包、退出码 0；
   - `nmcli` 显示设备状态为 `connected`（或 `100 (connected)`）。
6. 步骤 6：`grep -c "watchdog-nmcli-up"` 结果为 `0`（**说明是 NetworkManager 自动恢复，而非兜底重连生效**）；`route-diff` 与 `resolv-diff` 退出码为 0；`ping $GW` 通过；`$CASE_TMP` 已删除。

## 实测记录

| 项目 | 实测值 |
|---|---|
| 本轮状态 | 已设计但未执行：步骤 3 会主动断开本机唯一管理链路，需在具备带外控制台的窗口内执行；共享机器上不做 |
| 与 `TC-TR-0010-03` 的分工 | `-03` 用 veth + 命名空间验证**内核链路**中断与恢复，不涉及 NetworkManager，可安全并行；本用例验证**NetworkManager 按配置自动恢复**，需独占整机 |
| 关键判据 | `grep -c "watchdog-nmcli-up"` 必须为 0——若命中，说明是安全网里的 `nmcli connection up` 恢复了连接，不能算"自动恢复"，应判为不通过（或需重测并排查 NM 未自动重连的原因） |
| 为什么需要两层安全网 | `watchdog-link-up` 只恢复链路（`ip link set up`）；若 NM 未自动激活，30 秒后才会 `nmcli connection up` 兜底。两层分离才能区分"自动恢复"与"人工恢复" |
| 同类风险参考 | 实测该机 `eth0`（`sophgo-dwmac`）因 MDIO 无 PHY 无法 up（见 `TC-TR-0010-03` 已知问题），执行前应确认目标链路的 PHY 正常，否则 `ip link set up` 可能失败 |
