# TC-TR-0010-06 ｜ 管理链路中断后的自动恢复

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

在真实管理链路上断开并恢复链路，验证 NetworkManager 能按既有配置自动重新应用（地址、默认路由、DNS 恢复，连通性恢复），无需人工执行 `nmcli connection up` 或重启网络服务。

## 前置条件

1. 已安装 `NetworkManager`、`iproute2`、`iputils`。
2. **必须独占整机**：用例会断开本机唯一管理链路，并需具备带外控制台（串口/IPMI/KVM）或物理接触条件作为兜底。
3. 被测机的地址配置方式已知（静态或 DHCP），用于判定恢复后的地址是否与配置一致。
4. 已部署**恢复安全网**：链路 down 后 **60 秒**仍未 UP 时执行 `ip link set <接口> up`；再过 **60 秒**仍未获得地址时执行 `nmcli connection up <连接>`；每次触发写入日志，供后续核对。等待时间需显著大于产品正常恢复时间，以免安全网先于 NetworkManager 动作、掩盖其自动恢复行为；测试结束后需移除该安全网。
5. 机器上不要运行其他需要网络的任务，恢复期间网络会中断约 30～60 秒。

## 测试步骤

1. 记录入口基线：连接名、接口、网关、地址/前缀、默认路由、DNS 与 `connection.autoconnect` 值，写入临时文件。
2. 开启自动重连：若 `connection.autoconnect` 不为 `yes`，执行 `nmcli connection modify '<连接>' connection.autoconnect yes` 设为 `yes`，并回读该值。
3. 断开管理链路：将接口置为 down。
4. 重新接入，查看接口状态。
5. 查看恢复后的网络状态：
   - 执行 `ip -br addr` 查看接口地址；
   - 执行 `ip route` 查看默认路由；
   - 查看 `/etc/resolv.conf` 中的 `nameserver`；
   - `ping` 网关；
   - 用 `nmcli` 查看设备状态。
6. 复核与清理：
   - 查看安全网日志，并比对默认路由、DNS 与基线；
   - 移除恢复安全网；
   - 将 `connection.autoconnect` 还原为基线值；
   - 删除临时文件与安全网日志。

## 预期结果

1. 步骤 1：基线记录完整并已写入临时文件，含连接名、接口、网关、地址/前缀、默认路由、DNS 与 `autoconnect` 原值。
2. 步骤 2：`connection.autoconnect` 回读为 `yes`。
3. 步骤 3：链路已断开，管理会话中断（预期现象）。
4. 步骤 4：可重新接入，接口已处于 `UP` 状态。
5. 步骤 5：
   - 地址恢复为原地址/前缀（DHCP 下为同网段地址）；
   - 默认路由恢复为原网关；
   - `/etc/resolv.conf` 中的 `nameserver` 恢复；
   - `ping` 网关丢包率 0%；
   - `nmcli` 显示设备状态为 `connected`。
6. 步骤 6：
   - 安全网日志中无 `ip link set` / `nmcli connection up` 记录（恢复由 NetworkManager 自动完成，非安全网介入），且默认路由与 DNS 与基线一致；
   - 恢复安全网已移除；
   - `connection.autoconnect` 与基线值一致；
   - 临时文件与安全网日志已删除。
