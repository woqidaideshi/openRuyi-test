# TC-TR-0010-03 ｜ 防火墙规则生效

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证防火墙允许与拒绝规则正确生效，无非预期放行。

## 前置条件

1. 已安装 nftables（`nft` 可用），具备 root 权限（sudo）。
2. 具备可验证端口的服务（本机 22 端口，或可临时起一个监听端口）。

## 测试步骤

1. 查看当前 nftables 规则：
   ```bash
   sudo nft list ruleset
   ```
2. 起一个测试监听端口（8899）：
   ```bash
   python3 -m http.server 8899 >/dev/null 2>&1 &
   sleep 1
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8899/
   ```
3. 添加拒绝规则并验证：
   ```bash
   sudo nft add table inet tc-filter
   sudo nft add chain inet tc-filter input '{ type filter hook input priority 0; policy accept; }'
   sudo nft add rule inet tc-filter input tcp dport 8899 drop
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8899/
   echo $?
   ```
4. 删除拒绝规则后验证恢复：
   ```bash
   sudo nft flush chain inet tc-filter input
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8899/
   ```
5. 清理规则表与测试进程：
   ```bash
   sudo nft delete table inet tc-filter
   pkill -f 'http.server 8899'
   ```

## 预期结果

1. 步骤 2：测试端口可访问（HTTP 200）。
2. 步骤 3：添加 drop 规则后访问被拒（curl 返回 `000`、退出码 `28`（超时））。
3. 步骤 4：删除规则后访问恢复（HTTP 200）。
4. 步骤 5：规则与进程清理完毕，`nft list ruleset` 为空。

> 实测补充：当前镜像默认**未加载任何 nftables 规则**（`nft list ruleset` 输出为空），因此基线为全放行；放行基线不依赖任何预置规则。
