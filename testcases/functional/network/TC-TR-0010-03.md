# TC-TR-0010-03 ｜ 连通性与链路故障恢复

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证与规定节点之间的网络连通，以及链路中断后连通性能够自动恢复、无需重启网络服务。网关地址与对端节点均由命令自动获取。

## 前置条件

1. 网关地址与对端节点地址**由步骤 1 自动获取**：网关取自默认路由；对端优先取邻居表中除网关外的已知节点，取不到时回退为网关。可用 `PEER=` 环境变量指定（"规定节点"清单待需求方明确）。
2. 已安装 `iproute2`、`iputils`。
3. 本用例使用**隔离方案**（步骤 3～6）制造链路故障，不触碰承载管理连接的接口，因此可在与其他用例共享的机器上执行。
4. 主机具备创建网络命名空间的条件（`sudo ip netns` 可用），用于在不触碰管理连接的前提下制造链路故障。

## 测试步骤

1. 自动探测网关与对端节点，记录入口基线：
   ```bash
   CASE_TMP=/var/tmp/tc-net-conn && rm -rf $CASE_TMP && mkdir -p $CASE_TMP

   IFACE=$(ip route show default | awk '{print $5; exit}')
   GW=$(ip route show default | awk '{print $3; exit}')
   PEER=${PEER:-$(ip neigh show dev "$IFACE" | awk '$NF=="REACHABLE"||$NF=="STALE"||$NF=="DELAY"{print $1}' | grep -v "^$GW$" | head -1)}
   PEER=${PEER:-$GW}

   cat > $CASE_TMP/env.sh <<EOF
   IFACE=$IFACE
   GW=$GW
   PEER=$PEER
   EOF

   ip -br addr > $CASE_TMP/before.addr
   ip route > $CASE_TMP/before.route
   ip neigh show dev "$IFACE" > $CASE_TMP/before.neigh
   cat $CASE_TMP/env.sh
   ip -br addr
   ip route
   ```
2. 验证与规定节点的基础连通性：
   ```bash
   CASE_TMP=/var/tmp/tc-net-conn && . $CASE_TMP/env.sh
   ping -c 4 "$GW"
   ping -c 4 "$PEER"
   ```
3. 建立隔离测试链路（veth + 网络命名空间，不影响管理连接）：
   ```bash
   CASE_TMP=/var/tmp/tc-net-conn && . $CASE_TMP/env.sh
   sudo ip netns add tcn
   sudo ip link add veth0 type veth peer name veth1
   sudo ip link set veth1 netns tcn
   sudo ip addr add 192.0.2.1/24 dev veth0
   sudo ip link set veth0 up
   sudo ip netns exec tcn ip addr add 192.0.2.2/24 dev veth1
   sudo ip netns exec tcn ip link set veth1 up
   sleep 1
   ping -c 4 -W 1 192.0.2.2
   ```
   > 若被测机有**不影响管理通道**的第二块物理网口，也可把步骤 3～6 改为物理链路方案：`sudo ip link set <非管理接口> down` → `ping -c 2 "$GW"` → `sudo ip link set <非管理接口> up` → `ping -c 4 "$GW"`，判据不变（丢包率 100% → 恢复 0%）。
   > 否则只能用 veth + 网络命名空间，避免断开管理链路导致无法继续执行。
4. 制造链路故障并确认连通中断：
   ```bash
   CASE_TMP=/var/tmp/tc-net-conn && . $CASE_TMP/env.sh
   sudo ip link set veth0 down
   ping -c 2 -W 1 192.0.2.2
   ```
5. 解除故障并确认连通自动恢复：
   ```bash
   CASE_TMP=/var/tmp/tc-net-conn && . $CASE_TMP/env.sh
   sudo ip link set veth0 up
   sleep 1
   ping -c 4 -W 1 192.0.2.2
   ```
6. 清理隔离环境并复核原网络：
   ```bash
   CASE_TMP=/var/tmp/tc-net-conn && . $CASE_TMP/env.sh
   sudo ip netns del tcn
   ip link show veth0
   ip route
   ping -c 3 "$GW"
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：`IFACE`、`GW` 探测出非空值，`PEER` 取到非空值（从邻居表选出，排除网关；无其他邻居时回退为网关并记录）；`env.sh`、`before.addr`、`before.route`、`before.neigh` 均已生成。
2. 步骤 2：`GW` 与 `PEER` 均可达，丢包率 0%，退出码为 0。
3. 步骤 3：`netns` 与 `veth` 创建成功（各命令退出码为 0），`192.0.2.2` 可达（丢包率 0%，退出码 0）。
4. 步骤 4：故障生效，`ping` 丢包率 100%，退出码非 0。
5. 步骤 5：链路恢复后连通性自动恢复（丢包率 0%，退出码 0），且未重启 `NetworkManager`。
6. 步骤 6：`veth0` 已随命名空间删除（`ip link show veth0` 返回非 0，提示 `Device "veth0" does not exist`）；默认路由与 `GW` 连通保持（退出码 0）；`$CASE_TMP` 已删除。
