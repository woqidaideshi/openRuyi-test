# TC-TR-0010-03 ｜ 连通性与链路故障恢复

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证被测机与规定节点之间的连通性，以及链路中断后连通性能自动恢复、无需重启网络服务。网关取自默认路由，对端节点取自邻居表（也可用 `PEER=` 指定）。

## 前置条件

1. 系统已安装 `iproute2` 与 `iputils`，具备 `sudo` 权限。
2. 已配置默认路由与可用网关，邻居表中存在同网段节点。
3. 具备创建网络命名空间的条件（用于在不影响管理连接的前提下制造链路故障）。

## 测试步骤

1. 检测基础连通性：分别 `ping` 默认网关与对端节点各 4 次。
2. 建立隔离测试链路：创建网络命名空间，用一对 `veth` 与主机相连，两端配置 `192.0.2.0/24` 地址并启用，互 `ping`。
3. 制造链路故障：将 `veth0` 置为 down，再次 `ping` 对端。
4. 解除故障：将 `veth0` 置为 up，等待链路就绪后再次 `ping` 对端。
5. 复核网络服务状态：查看 `NetworkManager` 的运行状态。
6. 清理：删除网络命名空间，查看 `veth` 对端、默认路由与网关连通情况。

> 若被测机有**不影响管理通道**的第二块物理网口，可把步骤 2～5 替换为物理链路方案：先对该网口执行 `ip link set <网口> down` 后 `ping` 网关，再执行 `ip link set <网口> up` 后再次 `ping` 网关，判据不变。

## 预期结果

1. 步骤 1：网关与对端节点均可达，丢包率 0%。
2. 步骤 2：命名空间与 `veth` 创建成功，两端互 `ping` 丢包率 0%。
3. 步骤 3：链路中断，`ping` 丢包率 100%。
4. 步骤 4：链路恢复后 `ping` 丢包率 0%，连通自动恢复，无需人工干预。
5. 步骤 5：`NetworkManager` 在故障前后状态一致，未发生重启。
6. 步骤 6：`veth0` 已随命名空间删除，默认路由仍存在，网关仍可达。
