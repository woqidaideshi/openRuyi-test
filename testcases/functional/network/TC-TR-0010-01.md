# TC-TR-0010-01 ｜ 静态地址配置、连通性与重启保持

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证在指定连接上配置静态地址（地址/前缀、网关、DNS）后配置生效、DNS 解析与应用层访问正常，且该配置在系统重启后保持有效。环境参数（接口、连接名、地址/前缀、网关、DNS）均由命令自动探测。

## 前置条件

1. 已安装 `NetworkManager`、`iproute2`、`iputils`、`curl`。
2. 目标机已联网且存在默认路由（用于自动探测接口、网关与 DNS）。
3. **需在可占用整机、允许重启的测试窗口执行**；不要在多人共用的机器上执行。
4. 用例会**保留当前地址**只改配置方式，因此配置与重启后 IP 不变、连接可自动恢复。若要验证地址变更，执行文末「可选：改用同网段空闲地址」。
5. 被测连接的原配置必须可还原。
6. 域名解析与应用层访问依赖外部站点可达（默认 `openruyi.cn`，可用 `DOMAIN=` 覆盖）；离线环境应在报告中注明该步骤未能执行。

## 测试步骤

1. 记录入口基线：当前使用的连接名、接口、地址/前缀、网关与 DNS，以及 `/etc/resolv.conf` 内容和启动标识（`/proc/sys/kernel/random/boot_id`）。
2. 将连接改为静态配置：设置 `ipv4.method manual` 并下发地址/前缀、网关与 DNS，然后重新激活该连接。
3. 读取配置结果：查看接口地址与默认路由，并用 `nmcli` 回读 `ipv4` 参数。
4. 读取解析与访问结果：
   - 用 `getent hosts` 解析域名；
   - `ping` 网关与域名；
   - 用 `curl` 访问该域名的 HTTPS 页面。
5. 重启系统后重新接入，记录启动标识并与基线比对。
6. 重启后复核恢复结果：
   - 复核地址与默认路由；
   - 复核 DNS 与 `/etc/resolv.conf`；
   - 复核解析与访问能力。
7. 按步骤 1 的基线还原连接配置，并复检 `/etc/resolv.conf` 与网关连通。

> 若需验证“地址变更后生效”（而非仅改配置方式），可把步骤 2 的地址换成同网段空闲地址（先用 `arping -D` 探测未被占用）；注意配置后原 IP 失效，需通过带外控制台或已知新地址重新接入。

## 预期结果

1. 步骤 1：基线记录完整，含连接名、接口、地址/前缀、网关、DNS 与启动标识。
2. 步骤 2：配置下发与连接重新激活均成功，无报错。
3. 步骤 3：
   - 接口地址为原地址/前缀；
   - 默认路由指向原网关，且不再带 `proto dhcp`（已变为 `proto static`）；
   - `ipv4.method` 回读为 `manual`，地址、网关与 DNS 与下发值一致。
4. 步骤 4：
   - 域名解析成功；
   - `ping` 网关与域名丢包率 0%；
   - `curl` 返回 `http_code=200`。
5. 步骤 5：
   - 重新接入成功；
   - 启动标识与重启前不同（确实重启）。
6. 步骤 6：
   - 地址与默认路由保持；
   - `/etc/resolv.conf` 中的 DNS 保持；
   - 解析与访问仍正常。
7. 步骤 7：连接恢复为基线配置（`ipv4.method` 回到 `auto`），`/etc/resolv.conf` 与基线一致，网关可达。
