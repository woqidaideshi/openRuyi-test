# TC-TR-0010-01 ｜ 静态地址配置、连通性与重启保持

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证在指定连接上配置静态地址（地址/前缀、网关、DNS）后配置生效、DNS 解析与应用层访问正常，且该配置在系统重启后保持有效。环境参数（接口、连接名、地址/前缀、网关、DNS）均由命令自动探测。

## 前置条件

1. 已安装 `NetworkManager`、`iproute2`、`iputils`、`curl`。
2. 目标机已联网且存在默认路由（用于自动探测接口、网关与 DNS）。
3. **需在可占用整机、允许重启的测试窗口执行**；不要在多人共用的机器上执行。
4. 用例会**保留当前地址**只改配置方式，因此配置与重启后 IP 不变、连接可自动恢复。若要验证地址变更，执行文末「可选：改用同网段空闲地址」。
5. 被测连接的原配置必须可还原（步骤 1 自动记录）。
6. 域名解析与应用层访问依赖外部站点可达（默认 `openruyi.cn`，可用 `DOMAIN=` 覆盖）；离线环境应在报告中注明该步骤未能执行。

## 测试步骤

1. 自动探测环境并记录入口基线，结果写入 `$CASE_TMP/env.sh` 供后续步骤（含重启后）复用：
   ```bash
   CASE_TMP=/var/tmp/tc-net-static && rm -rf $CASE_TMP && mkdir -p $CASE_TMP

   IFACE=$(ip route show default | awk '{print $5; exit}')
   CON=$(nmcli -g GENERAL.CONNECTION device show "$IFACE" | head -1)
   CIDR=$(ip -o -4 addr show dev "$IFACE" | awk '{print $4; exit}')
   GW=$(ip route show default | awk '{print $3; exit}')
   DNS=$(nmcli -g IP4.DNS device show "$IFACE" | head -1 | tr -d ' ' | tr '|' ',' | sed 's/,$//')
   [ -z "$DNS" ] && DNS=$(awk '/^nameserver/{printf "%s,",$2}' /etc/resolv.conf | sed 's/,$//')
   DOMAIN=${DOMAIN:-openruyi.cn}
   PEER=${PEER:-$GW}

   OUT=$(nmcli -g ipv4.method,ipv4.addresses,ipv4.gateway,ipv4.dns connection show "$CON")
   BEFORE_METHOD=$(printf '%s\n' "$OUT" | sed -n '1p')
   BEFORE_ADDR=$(printf '%s\n' "$OUT" | sed -n '2p')
   BEFORE_GW=$(printf '%s\n' "$OUT" | sed -n '3p')
   BEFORE_DNS=$(printf '%s\n' "$OUT" | sed -n '4p')

   cat > $CASE_TMP/env.sh <<EOF
   IFACE=$IFACE
   CON="$CON"
   CIDR=$CIDR
   GW=$GW
   DNS=$DNS
   DOMAIN=$DOMAIN
   PEER=$PEER
   BEFORE_METHOD=$BEFORE_METHOD
   BEFORE_ADDR=$BEFORE_ADDR
   BEFORE_GW=$BEFORE_GW
   BEFORE_DNS=$BEFORE_DNS
   EOF

   nmcli connection show > $CASE_TMP/before.conn
   ip -br addr > $CASE_TMP/before.addr
   ip route > $CASE_TMP/before.route
   cat /etc/resolv.conf > $CASE_TMP/before.resolv
   cat /proc/sys/kernel/random/boot_id > $CASE_TMP/before.bootid
   cat $CASE_TMP/before.conn
   cat $CASE_TMP/env.sh
   ```
2. 下发静态地址配置并重新激活连接：
   ```bash
   CASE_TMP=/var/tmp/tc-net-static && . $CASE_TMP/env.sh
   sudo nmcli connection modify "$CON" \
     ipv4.method manual \
     ipv4.addresses "$CIDR" \
     ipv4.gateway "$GW" \
     ipv4.dns "$DNS" \
     ipv4.never-default no
   sudo nmcli connection up "$CON"
   ```
3. 确认配置已生效（地址、默认路由与参数回读）：
   ```bash
   CASE_TMP=/var/tmp/tc-net-static && . $CASE_TMP/env.sh
   ip -br addr show "$IFACE"
   ip route
   nmcli -g ipv4.method,ipv4.addresses,ipv4.gateway,ipv4.dns connection show "$CON"
   ```
4. 确认 DNS 解析、网络连通与应用层访问：
   ```bash
   CASE_TMP=/var/tmp/tc-net-static && . $CASE_TMP/env.sh
   getent hosts "$DOMAIN"
   ping -c 3 "$DOMAIN"
   ping -c 3 "$GW"
   ping -c 3 "$PEER"
   curl -sI -o /dev/null -w 'http_code=%{http_code}\n' --max-time 10 "https://$DOMAIN"
   command -v wget >/dev/null && wget --spider -q "https://$DOMAIN" && echo "wget_ok"
   ```
5. 重启系统：

   执行重启：
   ```bash
   sudo reboot
   ```

   重启后重新接入，确认已切换到新的启动：
   ```bash
   CASE_TMP=/var/tmp/tc-net-static && . $CASE_TMP/env.sh
   cat /proc/sys/kernel/random/boot_id > $CASE_TMP/after.bootid
   echo "before=$(cat $CASE_TMP/before.bootid) after=$(cat $CASE_TMP/after.bootid)"
   [ "$(cat $CASE_TMP/after.bootid)" != "$(cat $CASE_TMP/before.bootid)" ]
   echo "bootid-changed:$?"
   ```
6. 复核重启后配置与连通性保持：
   ```bash
   CASE_TMP=/var/tmp/tc-net-static && . $CASE_TMP/env.sh
   ip -br addr show "$IFACE"
   ip route
   cat /etc/resolv.conf
   getent hosts "$DOMAIN"
   ping -c 3 "$GW"
   curl -sI -o /dev/null -w 'http_code=%{http_code}\n' --max-time 10 "https://$DOMAIN"
   ```
7. 按步骤 1 的基线还原并复检：
   ```bash
   CASE_TMP=/var/tmp/tc-net-static && . $CASE_TMP/env.sh
   sudo nmcli connection modify "$CON" \
     ipv4.method "$BEFORE_METHOD" \
     ipv4.addresses "$BEFORE_ADDR" \
     ipv4.gateway "$BEFORE_GW" \
     ipv4.dns "$BEFORE_DNS"
   sudo nmcli connection up "$CON"
   diff $CASE_TMP/before.resolv /etc/resolv.conf
   ping -c 3 "$GW"
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：`IFACE`、`CON`、`CIDR`、`GW`、`DNS` 均探测出非空值并写入 `env.sh`（实测 `eth2` / `Wired connection 2` / `10.213.6.175/20` / `10.213.0.1` / `10.200.0.5,10.200.0.4`）；`before.conn` 能列出当前连接，`before.addr`、`before.route`、`before.resolv`、`before.bootid` 均已生成。
2. 步骤 2：`nmcli connection modify` 与 `nmcli connection up` 退出码均为 0。
3. 步骤 3：
   - `ip -br addr show "$IFACE"` 显示的地址与 `$CIDR` 一致；
   - `ip route` 中存在 `default via $GW`，且该行**不再带 `proto dhcp`**（地址来源已由 DHCP 变为静态，实测变为 `proto static`）；
   - `nmcli` 回读 `ipv4.method` 为 `manual`，地址、网关、DNS 与下发值一致。
4. 步骤 4：
   - `getent hosts "$DOMAIN"` 退出码 0；
   - `ping "$DOMAIN"`、`ping "$GW"`、`ping "$PEER"` 均 0% 丢包、退出码 0；
   - `curl` 返回 `http_code=200`；
   - 若系统有 `wget` 命令（实测由 `wget2-wget` 提供），输出 `wget_ok`；无则跳过并在报告中注明。
5. 步骤 5：`bootid-changed` 退出码为 `0`，即 `after.bootid` 与 `before.bootid` 不同（确认系统确实重启，避免"未重启却判为通过"）。
6. 步骤 6：重启后地址仍等于 `$CIDR`、默认网关与 `/etc/resolv.conf` 中的 DNS 保持有效，`getent`、`ping $GW` 与 `curl` 仍通过（判据同步骤 3、4）。
7. 步骤 7：连接恢复为步骤 1 记录的 `BEFORE_*` 配置，`diff` 无输出（退出码 0），`ping $GW` 通过，`$CASE_TMP` 已删除。

## 可选：改用同网段空闲地址

若需验证"地址变更后生效"（而非仅改配置方式），在步骤 2 前插入以下探测，并用 `$FREE_IP/$PFX` 替换 `$CIDR`。注意配置后**原 IP 失效**，需通过带外控制台或已知新地址重新接入。

```bash
CASE_TMP=/var/tmp/tc-net-static && . $CASE_TMP/env.sh
PFX=${CIDR#*/}
for n in 200 201 202 203 204; do
  CAND=$(python3 -c "import ipaddress,sys;print(ipaddress.ip_interface(sys.argv[1]).network.network_address+int(sys.argv[2]))" "$CIDR" "$n")
  [ "$CAND" = "${CIDR%/*}" ] && continue
  [ "$CAND" = "$GW" ] && continue
  sudo arping -D -I "$IFACE" -c 2 "$CAND" >/dev/null 2>&1 && { FREE_IP="$CAND"; break; }
done
echo "FREE_IP=${FREE_IP:-<未找到>}/$PFX"
```

## 实测记录

| 项目 | 实测值 |
|---|---|
| 环境核对 | 本用例依赖：`NetworkManager-1.54.3-7.4.or.riscv64`、`iproute2-6.16.0-3.17.or.riscv64`、`iputils-20250605-2.35.or.riscv64`、`curl-8.21.0-12.6.or.riscv64`，`systemctl is-active NetworkManager` → `active`。防火墙相关包（`firewalld`/`nftables`）的检查归属 `TC-TR-0010-04`/`-05` |
| `wget` 包名 | 实测 `rpm -q wget` 报 `not installed`，但 **`wget` 命令可用**——由 `wget2-wget-2.2.1-5.37.or.riscv64`（GNU Wget2）提供，`/usr/bin/wget`，`wget --spider` 实测返回 `wget_ok` |
| 自动探测（本机） | `IFACE=eth2`、`CON=Wired connection 2`、`CIDR=10.213.6.175/20`、`GW=10.213.0.1`、`DNS=10.200.0.5,10.200.0.4`，全部自动获得 |
| `nmcli -g` 输出格式 | **多字段是逐行输出，不是冒号分隔**：`-g ipv4.method,ipv4.addresses,ipv4.gateway,ipv4.dns` 实测输出 4 行（`auto` 加 3 行空值）。基线解析必须用 `sed -n 'Np'`，用 `awk -F:` 会全部取到第一行 |
| DHCP 连接的基线值 | 基线为 `auto` 时 `ipv4.addresses`/`ipv4.gateway`/`ipv4.dns` 均为空（地址来自 DHCP），还原时只需把 `method` 设回 `auto` 并清空其余字段 |
| DNS 探测兜底 | `nmcli -g IP4.DNS device show <接口>` 返回 `10.200.0.5 \| 10.200.0.4`（管道符分隔），需转成逗号；为空时从 `/etc/resolv.conf` 的 `nameserver` 行兜底 |
| `arping -D` 语义 | 实测：无人应答（空闲）返回 0；命中在用地址（网关 `10.213.0.1`）返回 1。**网络地址 `10.213.0.0` 也返回 0**，必须显式排除网络号、广播、当前地址与网关 |
| 静态配置实测 | 管理口 `eth2` 上：`modify` 与 `up` 退出码均为 0；`ip -br addr` 显示 `10.213.6.175/20`；回读 `manual / 10.213.6.175/20 / 10.213.0.1 / 10.200.0.5,10.200.0.4` |
| 路由来源变化 | 静态前：`default via 10.213.0.1 dev eth2 proto dhcp`；静态后：`default via 10.213.0.1 dev eth2 **proto static**`；还原为 `auto` 后又变回 `proto dhcp` |
| 解析与访问 | `getent hosts openruyi.cn` → `36.110.52.101`，退出码 0；`ping openruyi.cn` 0% 丢包、退出码 0；`curl -I` 返回 `HTTP/1.1 200 OK`（`http_code=200`）；`wget --spider` 由 `wget2-wget` 提供，实测输出 `wget_ok` |
| 重启后保持 | 重启后（实测约 111 秒恢复）地址、`proto static` 默认路由、`resolv.conf` 中的 DNS 均保持，`getent` 与 `ping` 通过 |
| 还原结果 | `modify`/`up` 退出码 0，`ip route` 回到 `proto dhcp`，`diff before.resolv /etc/resolv.conf` 退出码 0 |
| 重启判据更正 | **`btime` 不能用作重启判据**：该机 RTC 为 `2026-06-23`、`System clock synchronized: no`，`btime` 由墙钟推导，重启后反而变小（`1786451035` < `1794196236`）。改用 `/proc/sys/kernel/random/boot_id`（实测重启前后由 `38f33a3a…` 变为 `f8e3e2e1…`） |
| 执行安全措施 | 因静态配置会重新应用连接，实测时用 `setsid` 后台执行 `nmcli`，并设 120 秒看门狗：未及时写入成功标记则自动回滚为 `auto`，保证配置错误时能自动回到可用状态 |
| 变量跨重启保留 | 重启后 shell 变量丢失，故步骤 1 写入 `/var/tmp/.../env.sh`，后续每步先 `.` 加载。**每步开头必须先写 `CASE_TMP=/var/tmp/tc-net-static` 再 `. $CASE_TMP/env.sh`**——只写后者时变量为空会变成 `. /env.sh`，实测报 `No such file or directory`。`CASE_TMP` 不能用 `/tmp`——实测 `/tmp` 为 tmpfs（`tmpfs /tmp tmpfs rw,noatime`），重启即清空 |
| 网卡现状 | `eth2` 为管理口；`eth0`、`eth1` 均为 DOWN，且 `eth0` 无法 up（详见 `TC-TR-0010-03` 的已知问题） |
| 自动化前提 | 步骤 5 需夹具层支持"发出重启 → 等待主机恢复 → 新会话续跑"；其余步骤为纯命令 + 退出码判定 |
