# TC-TR-0010-01 ｜ 网络配置/DNS/路由与重启保持

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证静态/DHCP 网络配置、DNS 解析及路由正常，且配置在重启后保持有效。

## 前置条件

1. 已安装 NetworkManager、iproute2、iputils、curl；若需用 `wget` 验证，需已安装 **`wget2-wget`** 兼容包（见下方说明）。

> **`wget` 说明（重要）**：openRuyi Base 仓**不提供 GNU `wget` 包**（`dnf repoquery wget` 无结果），但提供：
> | 包 | 提供的命令 | 说明 |
> |---|---|---|
> | `wget2` | `/usr/bin/wget2` | 新一代下载器（`GNU Wget2 2.2.1`） |
> | `wget2-wget` | `/usr/bin/wget` → 指向 `wget2` 的符号链接 | 兼容层，使 `wget` 命令可用 |
>
> 实测：`rpm -q wget` → `package wget is not installed`，但 `command -v wget` → `/usr/bin/wget`（来自 `wget2-wget-2.2.1-5.37.or.riscv64`），且 `wget -q -O <file> https://openruyi.cn` 可正常下载（`rc=0`）。
> **若环境中 `wget` 不存在**，应先 `sudo dnf install -y wget2-wget`；或直接用 `curl` 完成等价验证。
2. 具备可配置的网络环境（支持 DHCP 或可配置静态地址，含可用网关与 DNS）。

## 测试步骤

1. 确认网络相关包与服务：
   ```bash
   rpm -q NetworkManager iproute2 iputils curl
   systemctl is-active NetworkManager
   ```
   > 注意：提供 `ip`/`ss` 的包名为 **`iproute2`**，不是 `iproute`；写成 `iproute` 会得到 `package iproute is not installed`。
2. 记录当前连接、地址与路由：
   ```bash
   nmcli connection show
   ip addr
   ip route
   ```
3. 验证 DNS 解析：
   ```bash
   getent hosts openruyi.cn
   echo $?
   ```
4. 验证连通性（网关与外网）：
   ```bash
   ping -c 3 openruyi.cn
   curl -I https://openruyi.cn
   ```
5. 确认连接为自动连接（重启后保持的前提，可代替破坏性的重启验证）：
   ```bash
   nmcli -t -f NAME,AUTOCONNECT connection show
   ```
6. 重启系统后核对配置保持（重启前记录，重启后对比）：
   ```bash
   ip addr
   ip route
   getent hosts openruyi.cn
   ```

## 预期结果

1. 步骤 1：相关包已安装（`iproute2` 已装，实测版本 `6.16.0-3.17.or.riscv64`），NetworkManager 状态为 `active`。
2. 步骤 2：正确显示当前连接、接口地址与默认路由（实测管理口为 `eth2`，地址 `10.213.6.175/20`，默认路由 `default via 10.213.0.1`）。
3. 步骤 3：`getent hosts openruyi.cn` 解析成功（实测返回 `36.110.52.101`），退出码为 0。
4. 步骤 4：`ping` 可通（实测 0% 丢包），`curl -I` 返回 `HTTP/1.1 200 OK`。
5. 步骤 5：管理口对应连接的 `AUTOCONNECT` 为 `yes`（实测 `Wired connection 2:yes`）。
6. 步骤 6：重启后地址、路由、DNS 解析保持有效。
   > 提示：步骤 6 需重启设备，应在可占用设备的测试窗口内执行，避免影响其他并行用例。
