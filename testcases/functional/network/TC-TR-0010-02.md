# TC-TR-0010-02 ｜ DHCP 获取、DNS/路由与重启保持

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证连接切换为 DHCP 后能够获取地址与默认路由、DNS 解析与网络连通正常，且重启后仍持有有效租约并保持可解析、可连通。

## 前置条件

1. 已安装 `NetworkManager`、`iproute2`、`iputils`。
2. 目标网段存在可用的 DHCP 服务端。**切换前必须先确认**，否则 `ipv4.method auto` 会覆盖原有配置，在拿到地址前连接可能长时间不可用。
3. **需在可占用整机、允许重启的测试窗口执行**。
4. 被测连接原有配置由步骤 1 自动记录，用例可在任意入口状态下执行并还原。

## 测试步骤

1. 自动探测环境并记录入口基线，结果写入 `$CASE_TMP/env.sh` 供后续步骤（含重启后）复用：
   ```bash
   CASE_TMP=/var/tmp/tc-net-dhcp && rm -rf $CASE_TMP && mkdir -p $CASE_TMP

   IFACE=$(ip route show default | awk '{print $5; exit}')
   CON=$(nmcli -g GENERAL.CONNECTION device show "$IFACE" | head -1)
   GW=$(ip route show default | awk '{print $3; exit}')
   DOMAIN=${DOMAIN:-openruyi.cn}
   PEER=${PEER:-$GW}

   OUT=$(nmcli -g ipv4.method,ipv4.addresses,ipv4.gateway,ipv4.dns connection show "$CON")
   BEFORE_METHOD=$(printf '%s\n' "$OUT" | sed -n '1p')
   BEFORE_ADDR=$(printf '%s\n' "$OUT" | sed -n '2p')
   BEFORE_GW=$(printf '%s\n' "$OUT" | sed -n '3p')
   BEFORE_DNS=$(printf '%s\n' "$OUT" | sed -n '4p')

   cat > $CASE_TMP/env.sh <<EOF
   IFACE=$IFACE
   CON="$CON"
   GW=$GW
   DOMAIN=$DOMAIN
   PEER=$PEER
   BEFORE_METHOD=$BEFORE_METHOD
   BEFORE_ADDR=$BEFORE_ADDR
   BEFORE_GW=$BEFORE_GW
   BEFORE_DNS=$BEFORE_DNS
   EOF

   cat /etc/resolv.conf > $CASE_TMP/before.resolv
   cat /proc/sys/kernel/random/boot_id > $CASE_TMP/before.bootid
   cat $CASE_TMP/env.sh
   ```
2. 切换为 DHCP 并重新激活连接：
   ```bash
   CASE_TMP=/var/tmp/tc-net-dhcp && . $CASE_TMP/env.sh
   sudo nmcli connection modify "$CON" ipv4.method auto
   sudo nmcli connection up "$CON"
   sleep 5
   ```
3. 确认地址获取结果与默认路由：
   ```bash
   CASE_TMP=/var/tmp/tc-net-dhcp && . $CASE_TMP/env.sh
   ip -br addr show "$IFACE"
   ip route
   ```
4. 确认 DNS 解析、网络连通与应用层访问：
   ```bash
   CASE_TMP=/var/tmp/tc-net-dhcp && . $CASE_TMP/env.sh
   cat /etc/resolv.conf
   getent hosts "$DOMAIN"
   ping -c 3 "$DOMAIN"
   ping -c 3 "$GW"
   ping -c 3 "$PEER"
   curl -sI -o /dev/null -w 'http_code=%{http_code}\n' --max-time 10 "https://$DOMAIN"
   command -v wget >/dev/null && wget --spider -q "https://$DOMAIN" && echo "wget_ok"
   ```
5. 重启系统：

   执行重启：
   ```bash
   sudo reboot
   ```

   重启后重新接入，确认已切换到新的启动：
   ```bash
   CASE_TMP=/var/tmp/tc-net-dhcp && . $CASE_TMP/env.sh
   cat /proc/sys/kernel/random/boot_id > $CASE_TMP/after.bootid
   echo "before=$(cat $CASE_TMP/before.bootid) after=$(cat $CASE_TMP/after.bootid)"
   [ "$(cat $CASE_TMP/after.bootid)" != "$(cat $CASE_TMP/before.bootid)" ]
   echo "bootid-changed:$?"
   ```
6. 复核重启后租约与连通性保持：
   ```bash
   CASE_TMP=/var/tmp/tc-net-dhcp && . $CASE_TMP/env.sh
   ip -br addr show "$IFACE"
   ip route
   cat /etc/resolv.conf
   getent hosts "$DOMAIN"
   ping -c 3 "$GW"
   curl -sI -o /dev/null -w 'http_code=%{http_code}\n' --max-time 10 "https://$DOMAIN"
   ```
7. 按步骤 1 的基线还原并复检：
   ```bash
   CASE_TMP=/var/tmp/tc-net-dhcp && . $CASE_TMP/env.sh
   sudo nmcli connection modify "$CON" \
     ipv4.method "$BEFORE_METHOD" \
     ipv4.addresses "$BEFORE_ADDR" \
     ipv4.gateway "$BEFORE_GW" \
     ipv4.dns "$BEFORE_DNS"
   sudo nmcli connection up "$CON"
   ip route
   ping -c 3 "$GW"
   rm -rf $CASE_TMP
   ```

## 预期结果

1. 步骤 1：`IFACE`、`CON`、`GW` 均探测出非空值并写入 `env.sh`；`before.resolv` 与 `before.bootid` 已生成。
2. 步骤 2：`nmcli connection modify` 与 `nmcli connection up` 退出码均为 0。
3. 步骤 3：
   - `ip -br addr show "$IFACE"` 显示接口已获得地址，且与 `$GW` 处于同一网段；
   - `ip route` 中存在默认路由，且该行**标记 `proto dhcp`**（地址来源为 DHCP，与静态配置的关键区别）；
   - **不校验具体 IP 值**，因续租后地址可能变化。
4. 步骤 4：`/etc/resolv.conf` 中存在 DHCP 下发的 `nameserver`；`getent hosts "$DOMAIN"` 退出码 0；`ping "$DOMAIN"`、`ping "$GW"`、`ping "$PEER"` 均 0% 丢包、退出码 0；`curl` 返回 `http_code=200`（安装了 `wget` 时还应输出 `wget_ok`，未安装则跳过并注明）。
5. 步骤 5：`bootid-changed` 退出码为 `0`，即 `after.bootid` 与 `before.bootid` 不同（确认系统确实重启）。
6. 步骤 6：重启后仍有地址且默认路由标记 `proto dhcp`，`/etc/resolv.conf`、解析与连通均保持有效（判据同步骤 3、4）；地址值与重启前不同不影响判定。
7. 步骤 7：连接恢复为步骤 1 记录的 `BEFORE_*` 配置，`ip route` 正常，`ping $GW` 通过，`$CASE_TMP` 已删除。
