# TC-TR-0010-02 ｜ DHCP 获取、DNS/路由与重启保持

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证连接切换为 DHCP 后能够获取地址与默认路由、DNS 解析与网络连通正常，且重启后仍持有有效租约并保持可解析、可连通。

## 前置条件

1. 已安装 `NetworkManager`、`iproute2`、`iputils`。
2. 目标网段存在可用的 DHCP 服务端。**切换前必须先确认**，否则 `ipv4.method auto` 会覆盖原有配置，在拿到地址前连接可能长时间不可用。
3. **需在可占用整机、允许重启的测试窗口执行**。
4. 被测连接原有配置必须可还原，用例可在任意入口状态下执行。

## 测试步骤

1. 记录入口基线：当前使用的连接名、接口、网关、原有的 `ipv4` 配置，以及 `/etc/resolv.conf` 内容与启动标识（`/proc/sys/kernel/random/boot_id`）。
2. 将连接切换为 DHCP：设置 `ipv4.method auto` 并重新激活连接，等待地址获取完成。
3. 读取地址获取结果：查看接口地址与默认路由。
4. 读取解析与访问结果（下文 `<目标域名>` 均指代同一公网域名，需可解析且 HTTPS 可访问，示例取 `openruyi.cn`）：
   - 查看 `/etc/resolv.conf` 中的 `nameserver`；
   - 执行 `getent hosts <目标域名>` 解析域名；
   - `ping` 网关与 `<目标域名>`；
   - 执行 `curl -sL -o /dev/null -w '%{http_code}' https://<目标域名>` 访问该域名的 HTTPS 页面（`-L` 跟随重定向）。
5. 重启系统后重新接入，记录启动标识并与基线比对。
6. 重启后复核恢复结果：
   - 复核地址与默认路由；
   - 复核 DNS 与 `/etc/resolv.conf`；
   - 复核解析与访问能力。
7. 按步骤 1 的基线还原连接配置，并复检默认路由与网关连通。

## 预期结果

1. 步骤 1：基线记录完整，含连接名、接口、网关、原有 `ipv4` 配置与启动标识。
2. 步骤 2：切换命令与连接重新激活均成功，无报错。
3. 步骤 3：接口已获得地址且与网关同网段；默认路由**标记 `proto dhcp`**（与静态配置的关键区别）；**不校验具体 IP 值**，因续租后地址可能变化。
4. 步骤 4：
   - `/etc/resolv.conf` 中存在 DHCP 下发的 `nameserver`；
   - `getent hosts <目标域名>` 返回非空结果（同时含域名与地址）且退出码为 0；
   - `ping` 网关与 `<目标域名>` 丢包率 0%；
   - `curl` 返回 `http_code=200`。
5. 步骤 5：
   - 重新接入成功；
   - 启动标识与重启前不同（确实重启）。
6. 步骤 6：
   - 仍有地址，且默认路由仍标记 `proto dhcp`；
   - DNS 保持有效；
   - 解析与访问仍正常；
   - 地址值与重启前不同不影响判定。
7. 步骤 7：连接恢复为基线配置，默认路由正常，网关可达。
