# TC-TR-0010-02 ｜ 连通性与故障恢复

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证规定节点间网络连通，故障解除后能够按配置恢复。

## 前置条件

1. 规定节点可达（如网关、对端节点）。
2. 具备制造/解除网络故障的手段（如对非管理接口执行 `ip link set <接口> down/up`，或使用 veth/namespace 方案）。
3. **禁止**对承载管理连接（SSH）的接口执行 down，否则将丢失对机器的控制。

## 测试步骤

1. 记录当前网络接口与默认路由：
   ```bash
   ip addr
   ip route
   ```
2. 验证连通性：
   ```bash
   ping -c 4 <网关>
   echo $?
   ```
   > 重要：判断连通性必须**直接**用 `echo $?` 取 `ping` 退出码。写成 `ping ... | tail -2; echo $?` 会得到 `tail` 的退出码（恒为 0），导致故障态误判为正常。
3. 制造网络故障（对非管理接口执行 down）：
   ```bash
   sudo ip link set <非管理接口> down
   ping -c 2 <网关>
   echo $?
   ```
4. 故障解除后验证恢复：
   ```bash
   sudo ip link set <非管理接口> up
   ping -c 4 <网关>
   ip addr
   ip route
   ```

### 安全替代方案（备用网口无法 up 或仅有单网口时）

用 veth 对 + 网络命名空间制造可复现的链路故障，完全不触碰管理网口：
```bash
sudo ip netns add tcx
sudo ip link add veth0 type veth peer name veth1
sudo ip link set veth1 netns tcx
sudo ip addr add 192.0.2.1/24 dev veth0
sudo ip link set veth0 up
sudo ip netns exec tcx ip addr add 192.0.2.2/24 dev veth1
sudo ip netns exec tcx ip link set veth1 up
sleep 1
ping -c 4 -W 1 192.0.2.2; echo "baseline_rc=$?"
sudo ip link set veth0 down
ping -c 2 -W 1 192.0.2.2; echo "fault_rc=$?"
sudo ip link set veth0 up; sleep 1
ping -c 4 -W 1 192.0.2.2; echo "recovered_rc=$?"
sudo ip netns del tcx
```

## 预期结果

1. 步骤 2：ping 全部可达（0% 丢包），退出码为 `0`。
2. 步骤 3：故障生效，ping 不可达（100% 丢包），退出码非 0（实测为 `1`）。
3. 步骤 4：故障解除后按配置恢复，ping 可达（0% 丢包，退出码 `0`）且网络配置正确。
4. 替代方案：`baseline_rc=0` → `fault_rc=1` → `recovered_rc=0`；删除 netns 后 veth0 同步消失（`Device "veth0" does not exist`）。

## 已知问题（2026-11-10 在 riscv64 物理机实测）

**现象**：备用网口 `eth0`（`sophgo-dwmac`，平台设备 `7030006000.ethernet`）无法启用：

```
$ sudo ip link set eth0 up
RTNETLINK answers: No such device        # ENODEV
$ sudo nmcli device connect eth0
Error: Connection activation failed: The device could not be readied for configuration.
```

**根因**：内核日志显示 MDIO 总线上未发现 PHY，phylink 无 PHY 可用导致 `ndo_open` 返回 `-ENODEV`：

```
[ 18.802060] mdio_bus stmmac-0: MDIO device at address 0 is missing.
[ 18.749715] sophgo-dwmac 7030006000.ethernet: Active PHY interface: RGMII (1)
```

`/sys/class/net/eth0/carrier` 为 `unknown`，`eth1` 可 up 但 `carrier=0`（未接网线）。

**影响**：本机无法用 `eth0` 作为"非管理接口"制造物理链路故障，应改用上方 veth/namespace 替代方案，或接入网线后重新验证。
