| 字段 | 值 |
|---|---|
| 关联需求 | TR-0010（网络基础功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

通过 `firewall-cmd` 验证防火墙允许与拒绝规则正确生效：未放行端口默认不可达，放行后对端可访问，未放行的对照端口不被意外放通，`--permanent` 规则在重启后仍生效，移除放行规则后立即重新阻断。

## 前置条件

1. 已安装 `firewalld`。
2. 具备 root 权限（sudo）。
3. **需要一台能访问被测机的外部对端主机**，回环地址不能代替。
4. 默认 zone 的 `services` 中已包含管理连接所使用的服务（`public` zone 默认包含 `ssh`）。
5. `firewalld` 与 `nftables` 包存在替代关系：安装 `firewalld` 会替换/升级 `nftables` 包，`nft` 命令仍可正常使用。
6. **需在被测机上选取两个未被监听、未被 `firewall-cmd` 放行（含 rich rule）的端口**（默认从 `18800` 起），分别作放行端口与对照端口；区间内无可用端口时用例判为不可执行。
7. **需重启整机**，须在可占用整机的测试窗口执行。

## 测试步骤

1. 用 `firewall-cmd --state` 查看 `firewalld` 状态，并记录默认 zone、`services`、运行时/`--permanent` 的 `--list-ports` 与启动标识（`/proc/sys/kernel/random/boot_id`）作为基线。
2. 选取两个测试端口（均未被监听、未被放行），并在被测机上为这两个端口启动临时 HTTP 监听。
3. 从**对端主机**访问这两个端口。
4. 放行其中一个端口（运行时与 `--permanent` 同时下发）并 `--reload`，再查看运行时与永久端口列表。
5. 从**对端主机**再次访问两个端口。
6. 重启系统后重新接入，记录启动标识并与基线比对。
7. 重启后查看 `firewalld` 状态与端口列表，重新起监听，并从**对端主机**访问两个端口。
8. 移除运行时与永久放行规则并 `--reload`，再从**对端主机**再次访问该端口。
9. 清理：停止临时监听，查看运行时与永久端口列表。

> 回环地址不能代替对端主机：默认 zone 对未放行端口是 reject 行为，回环访问得到的结果不具代表性。

## 预期结果

1. 步骤 1：`firewalld` 已安装，`--state` 输出 `running`；默认 zone 为 `public`，其 `services` 含 `ssh`；端口列表与启动标识的基线记录完成。
2. 步骤 2：两个端口均未被监听、未被放行，且两者互不相同；两个端口均进入 `LISTEN` 状态。
3. 步骤 3：两个端口访问均失败（`http_code=000`，连接被拒绝）。若出现 `200`，说明端口选取不当，应重新选取。
4. 步骤 4：放行命令均返回 `success`，`--reload` 无报错；运行时与永久端口列表均包含该端口，`--query-port` 查询为已放行。
5. 步骤 5：已放行端口返回 `200`；对照端口仍为 `000`、访问失败（**无意外放行**）。
6. 步骤 6：
   - 重新接入成功；
   - 启动标识与重启前不同（确实重启）。
7. 步骤 7：
   - `firewalld` 为 `active`；
   - 运行时与永久端口列表重启后仍包含该端口（**`--permanent` 生效**）；
   - 对端访问放行端口为 `200`、对照端口仍失败。
8. 步骤 8：
   - 移除与 `--reload` 均无报错；
   - 两个端口列表均不再包含该端口，`--query-port` 查询为未放行；
   - 对端访问该端口恢复为 `000`。
9. 步骤 9：
   - 所选端口无监听残留；
   - 运行时与永久端口列表均恢复为基线；
   - `--list-all` 中 `ports` 为空、`services` 仍为基线值。
