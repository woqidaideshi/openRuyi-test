# TC-TR-0012-01 ｜ ssh 有效凭据建立会话

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0012（正常通过 ssh 连接 openruyi 机器） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证使用有效凭据通过 ssh 建立**交互式 Shell 会话**：会话内 `whoami` 为 `openruyi`，可执行命令并在家目录完成文件创建/读取/删除，`exit` 后正常退出且能再次连接；密码与密钥两种凭据均可登录。

## 前置条件

1. 已安装所需软件：**被测机（服务端）**装 `openssh-server`；执行 ssh 命令的**主机（客户端）**装 `openssh-clients` 与 `sshpass`。默认在被测机上以 `localhost` 自环执行（客户端与服务端为同一台机器）。
2. `sshd` 服务处于运行状态，`22/TCP` 处于监听，防火墙已放行 ssh。
3. 被测机存在普通用户 `openruyi` 且家目录可写；已知其有效密码，或已有可用私钥。

## 测试步骤

1. 登录并进入交互式 Shell：执行 `ssh -p <端口> openruyi@localhost`，使用有效凭据登录。
   > 步骤 1～4 在同一会话内完成，中途不退出。
   > 脚本/管道环境下需加 `-tt` 强制分配 TTY，否则会退化为非交互执行。
   > 若要覆盖“从外部客户端连接到被测机”的场景，在另一台客户端把 `localhost` 换成被测机地址，其余不变。
2. 在提示符下查看身份、目录与交互模式：
   - 执行 `whoami`；
   - 执行 `pwd`；
   - 执行 `echo "flags=$-"`；
   - 执行 `tty`。
   > `echo $-` 打印当前 shell 的选项标志，其中 **`i` 表示交互模式**。交互式会话输出形如 `himBHs`，屏幕上同时出现提示符。
3. 在提示符下完成文件创建、读取、删除：在用户家目录写入 `tc-file`、读取其内容后删除。
4. 在提示符下执行 `exit` 退出。
5. 退出后再次连接，并执行一条命令。
6. 使用错误密码尝试连接。
7. 安装临时密钥并用其登录：生成一对临时密钥，将公钥追加到 `~/.ssh/authorized_keys`，再用该私钥登录（不提供密码），登录后执行 `whoami`。
8. 移除临时公钥，再次尝试以该密钥登录，并删除临时密钥文件。

## 预期结果

1. 步骤 1：登录成功并出现交互式提示符 `[openruyi@<主机名> ~]$`。
2. 步骤 2：
   - `whoami` 输出 `openruyi`；
   - `pwd` 输出 `/home/openruyi`；
   - `flags=` 包含交互标志 `i`；
   - `tty` 输出 `/dev/pts/N`（不是 `not a tty`）。
3. 步骤 3：写入后读取内容一致；删除后确认文件已不存在，家目录无残留。
4. 步骤 4：输入 `exit` 后输出 `logout` 与会话结束提示，会话立即结束且未挂起。
5. 步骤 5：重新连接成功，命令可正常执行。
6. 步骤 6：连接被拒绝，提示 `Permission denied`，未建立会话。
7. 步骤 7：登录成功，`whoami` 输出 `openruyi`（全程未提供密码，可确认走的是密钥认证）。
8. 步骤 8：
   - 移除临时公钥成功，`authorized_keys` 行数回到安装前的值；
   - 再以公钥认证连接被拒绝（临时密钥确实失效，未残留后门）；
   - 临时密钥文件已删除。
