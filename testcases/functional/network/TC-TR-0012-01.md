# TC-TR-0012-01 ｜ ssh 有效凭据建立会话

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0012（正常通过 ssh 连接 openruyi 机器） |
| 测试类型 | 功能测试 |
| 功能模块 | 网络 |
| 优先级 | P2 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证使用有效凭据通过 ssh 建立**交互式 Shell 会话**：会话内 `whoami` 为 `openruyi`，可执行命令并在家目录完成文件创建/读取/删除，`exit` 后正常退出且能再次连接；密码与密钥两种凭据均可登录。

## 前置条件

1. 已安装所需软件：**被测机（服务端）**装 `openssh-server`；执行 ssh 命令的**主机（客户端）**装 `openssh-clients` 与 `sshpass`。默认在被测机自身执行（自环）。
2. `sshd` 服务处于运行状态，`22/TCP` 处于监听，防火墙已放行 ssh。
3. 被测机存在普通用户 `openruyi` 且家目录可写；已知其有效密码，或已有可用私钥。

## 测试步骤

1. 登录并进入交互式 Shell：
   ```bash
   sshpass -p '<正确密码>' ssh -tt -p <端口> -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no openruyi@localhost
   ```
   > 需求原文的 `ssh -p <端口> openruyi@<目标地址>` **不带命令参数**，登录后直接进入交互式 Shell，后续命令都在这个会话里敲。
   > 人工执行时终端本身就是 TTY，可省掉 `-tt`；脚本/管道环境必须加 `-tt` 强制分配 TTY。不加 `-tt` 且 stdin 非终端时，ssh 输出 `Pseudo-terminal will not be allocated because stdin is not a terminal.`，退化为非交互执行，**不满足**"进入交互式 Shell"。
   > `<端口>` 为 `sshd` 监听端口，默认 `22`；若被测机改过端口，填实际值——这一步同时验证 `-p` 参数生效。
   > 默认连 `localhost`（自环，同时用到本地 ssh 客户端与本地 sshd）。若在另一台客户端主机上执行 `ssh -p <端口> openruyi@<被测机IP>`，判据不变。

2. 在会话内确认身份、目录与交互模式：
   ```
   [openruyi@<主机名> ~]$ whoami
   [openruyi@<主机名> ~]$ pwd
   [openruyi@<主机名> ~]$ echo "flags=$-"
   [openruyi@<主机名> ~]$ tty
   ```

3. 在会话内完成文件创建/读取/删除（授权目录即用户家目录）：
   ```
   [openruyi@<主机名> ~]$ echo hi > ~/tc-file
   [openruyi@<主机名> ~]$ cat ~/tc-file
   [openruyi@<主机名> ~]$ rm ~/tc-file
   [openruyi@<主机名> ~]$ ls ~/tc-file && echo STILL_THERE || echo FILE_GONE
   ```
   > 最后一行故意让 `ls` 失败，用 `&& / ||` 把结论变成标记行，既保留 `No such file or directory` 原始报错，又不让整段退出码非 0。

4. 在会话内执行 exit 正常退出：
   ```
   [openruyi@<主机名> ~]$ exit
   ```
   > 步骤 1～4 是**同一个会话内的连续操作**。自动化测试可用一条流水线等价完成：
   > ```bash
   > printf 'whoami\npwd\necho "flags=$-"\ntty\necho hi > ~/tc-file\ncat ~/tc-file\nrm ~/tc-file\nls ~/tc-file && echo STILL_THERE || echo FILE_GONE\nexit\n' | sshpass -p '<正确密码>' ssh -tt -p <端口> -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no openruyi@localhost
   > ```
   > `-tt` 让管道输入仍走伪终端，因此提示符、命令回显、`logout`、`Connection closed` 都会出现，判定方式与人工执行一致。

5. 退出后再次连接：
   ```bash
   sshpass -p '<正确密码>' ssh -p <端口> -n -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no openruyi@localhost 'echo reconnect-ok' </dev/null
   ```

6. 使用错误密码尝试连接：
   ```bash
   sshpass -p '<错误密码>' ssh -p <端口> -n -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no -o NumberOfPasswordPrompts=1 openruyi@localhost 'echo should-not-happen' </dev/null
   ```

7. 用临时密钥登录（安装公钥后禁用密码认证验证）：
   ```bash
   ssh-keygen -t ed25519 -N '' -f /tmp/tc-sshkey -q
   ssh-keygen -lf /tmp/tc-sshkey.pub
   sshpass -p '<正确密码>' ssh -p <端口> -n -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null openruyi@localhost 'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys' < /tmp/tc-sshkey.pub
   ssh -p <端口> -n -i /tmp/tc-sshkey -o PreferredAuthentications=publickey -o PubkeyAuthentication=yes -o PasswordAuthentication=no -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null openruyi@localhost 'whoami'
   ```

8. 清理临时公钥并确认其失效：
   ```bash
   grep -v -F "$(cut -d' ' -f2 /tmp/tc-sshkey.pub)" ~/.ssh/authorized_keys > /tmp/tc-ak.new && mv /tmp/tc-ak.new ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
   rm -f /tmp/tc-sshkey /tmp/tc-sshkey.pub
   ssh -p <端口> -n -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=publickey -o PasswordAuthentication=no -o BatchMode=yes openruyi@localhost 'echo should-not-happen' </dev/null
   ```

## 预期结果

1. 步骤 1：以指定端口（默认 `22`）登录成功，出现交互式提示符 `[openruyi@<主机名> ~]$`，即已进入交互式 Shell；且未出现 `Pseudo-terminal will not be allocated` 提示。
2. 步骤 2：`whoami` 输出 `openruyi`，`pwd` 输出 `/home/openruyi`；`flags=` 包含交互标志 **`i`**（实测 `himBHs`）；`tty` 输出 `/dev/pts/N`（**不是** `not a tty`）。
3. 步骤 3：`cat` 输出 `hi`；`rm` 后 `ls ~/tc-file` 报 `No such file or directory` 并输出 **`FILE_GONE`**（不是 `STILL_THERE`），家目录无残留。
4. 步骤 4：输入 `exit` 后输出 `logout` 与 `Connection to <主机> closed.`，会话立即结束且未挂起；若用自动化流水线，整段退出码为 0。
5. 步骤 5：退出后重连成功，输出 `reconnect-ok`。
6. 步骤 6：连接被拒绝，提示 `Permission denied (publickey,password).`，**不输出** `should-not-happen`（未建立会话），命令退出码非 0（实测 `255`）。
7. 步骤 7：公钥安装后，用临时私钥且**禁用密码认证**仍能登录，`whoami` 输出 `openruyi`。
8. 步骤 8：`authorized_keys` 行数回到安装前的值，临时密钥文件已删除；再以公钥认证连接被拒绝，提示 `Permission denied (publickey,password).`，且不输出 `should-not-happen`（临时密钥确实失效，未残留后门）。

## 实测记录

| 项目 | 实测值 |
|---|---|
| 执行环境 | `openRuyi Creek`，`riscv64`，`sshd` 为 `active`，`ss -ltn` 显示 `0.0.0.0:22` 与 `[::]:22` 均在 `LISTEN` |
| sshd 认证配置 | `sudo sshd -T` 实测：`PasswordAuthentication yes`、`PubkeyAuthentication yes`、`UsePAM yes`、`KbdInteractiveAuthentication no`、`PermitRootLogin prohibit-password`、`MaxAuthTries 6`；`/etc/ssh/sshd_config` 无显式配置，均为默认值 |
| 端口放行 | `firewalld` 为 `active`，`public` zone 的 `services: dhcpv6-client ssh`，即 `22/TCP` 已放行 |
| 客户端工具 | `ssh` 命令由 **`openssh-clients`** 提供（实测 openRuyi riscv64 为 `openssh-clients-10.5p1-20.5.or.riscv64`，openEuler aarch64 为 `openssh-clients-9.6p1-26.oe2609.aarch64`）；**不存在名为 `ssh` 的包**（`rpm -q ssh` → `not installed`，仓库也无此包）。另有 `sshpass-1.10-4.13.or.riscv64`（仓库另有 `1.10-6.1.or`）与 `openssh-server-10.5p1-20.5.or.riscv64` |
| 步骤 1 实测 | `ssh -tt -p 22` 登录 `openruyi@10.213.6.175`，出现提示符 `[openruyi@openruyi-riscv64 ~]$`，说明已进入交互式 Shell 且 `-p` 参数生效 |
| 步骤 2 实测 | 会话内 `whoami` → `openruyi`；`pwd` → `/home/openruyi`；`echo "flags=$-"` → **`himBHs`**（含 `i`）；`tty` → **`/dev/pts/0`** |
| 步骤 3 实测 | 会话内 `cat ~/tc-file` → `hi`；`rm` 后 `ls ~/tc-file && echo STILL_THERE || echo FILE_GONE` → `ls: cannot access '/home/openruyi/tc-file': No such file or directory` + **`FILE_GONE`**，整段退出码 0 |
| 步骤 4 实测 | 会话内 `exit` → `logout` + `Connection to 10.213.6.175 closed.`，整段流水线退出码 0 |
| 步骤 5 实测 | 重连输出 `reconnect-ok`，退出码 0 |
| 交互式与非交互式对照 | 四种调用方式实测：`ssh host 'cmd'` → `$-`=`hBc`、`tty`=`not a tty`；`ssh -tt host 'cmd'` → `$-`=`hBc`、`tty`=`/dev/pts/0`（**有 TTY 但非交互**）；`ssh host` + 喂 stdin → `$-`=`hBs`、`not a tty`；`ssh -tt host` + 喂 stdin → `$-`=**`himBHs`**、`/dev/pts/0`、有提示符（**只有这种才是交互式 Shell**） |
| 密码认证路径 | `openruyi` 账户密码未知，为避免改动该账户，改用临时用户 `tcssh` 验证同一套命令：正确密码 → 登录成功（`tcssh` / `/home/tcssh`，退出码 0）、重连退出码 0；验证后已 `userdel -r` 删除（`id tcssh` 报 `no such user`，家目录已移除） |
| 步骤 6 实测（错误密码） | 在目标机上以临时用户 `tcssh` 验证：`sshpass -p 'wrong-password' ssh ...` → `Permission denied (publickey,password).`，**退出码 `255`**，未输出命令内容 |
| 与 TR-0013 的边界 | 步骤 6 只回答"错误密码能不能连上"；认证机制、拒绝策略及日志等按权重在 `TC-TR-0013-02` 详细验证，本用例不展开 |
| `chpasswd` 告警 | 临时用户设密码时出现 `Invalid ENCRYPT_METHOD value: 'yescrypt'. Defaulting to DES.`——`login.defs` 指定 `yescrypt` 但 `chpasswd` 不支持，回退到 DES。属镜像默认配置问题，不影响本用例结论，建议单独跟进（弱哈希） |
| `userdel` 竞态 | 首次 `userdel -r tcssh` 失败（`user is currently used by process`，退出码 8），因 SSH 会话进程尚未完全退出；等待或 `pkill -u tcssh` 后重试成功。清理带用户的用例时应留后重试 |
| 步骤 7 实测（临时密钥） | `ssh-keygen -t ed25519 -N ''` 生成临时密钥（指纹 `SHA256:q3qK8uuMG5QmbHddelDctvjHZXUhp2i42nJKIsW7OE0`）→ 写入 `~/.ssh/authorized_keys`（2→3 行）→ 用私钥且 `PasswordAuthentication=no` 登录，输出 `openruyi` 与 `key-session-ok`，登录成功 |
| 步骤 8 实测（清理） | 删除临时公钥后 `authorized_keys` 回到 2 行、临时密钥文件已删；再以 `PreferredAuthentications=publickey` 且不提供私钥连接，返回 `Permission denied (publickey,password).`，证明临时密钥已失效、未留后门 |
| 密钥认证覆盖现状 | 核查发现：`TC-TR-0013-02`/`-03` 均显式 `PubkeyAuthentication=no`，只测密码；`TC-TR-0013-05` 的“密钥”指磁盘加密口令。即密钥登录在本用例补充前**无任何用例覆盖** |
| 执行方式 | 步骤 1～4 在同一个交互式会话内完成（自动化用一条 `-tt` 流水线），步骤 5～8 各自为单条命令，按输出标记与是否建立会话判定，无需额外打印退出码 |
