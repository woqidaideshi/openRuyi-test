# TC-TR-0008-01 ｜ 修改当前用户密码

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0008（应当能够正常修改当前用户密码） |
| 测试类型 | 功能测试 |
| 功能模块 | 系统服务与管理 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证 `passwd` 能修改当前用户密码，新密码可登录、旧密码失效，且 openruyi 用户无法修改其他用户密码。

## 前置条件

1. 使用正确密码登录 `openruyi` 账户。
2. 系统中已存在其他非 root 用户账户（如 `test`）。
3. 准备一个与旧密码不同、且满足复杂度要求的新密码。
4. 本机 `sshd` 已运行且允许密码登录（`PasswordAuthentication yes`）。
5. 已安装 `sshpass`。

## 测试步骤

1. 修改当前用户密码：`passwd`，按提示依次输入当前密码、新密码，新密码须与旧密码不同。
2. 用旧密码 SSH 登录：`sshpass -p '<旧密码>' ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no openruyi@localhost 'cat /etc/os-release'`。
3. 用新密码 SSH 登录：`sshpass -p '<新密码>' ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o PreferredAuthentications=password -o PubkeyAuthentication=no openruyi@localhost 'cat /etc/os-release'`。
4. 尝试修改其他用户密码：`passwd <其他用户>`。

## 预期结果

1. 步骤 1：`passwd` 退出码为 0。
2. 步骤 2：旧密码登录被拒绝，退出码非 0，提示 Permission denied。
3. 步骤 3：新密码登录成功，退出码为 0，输出 `/etc/os-release` 内容。
4. 步骤 4：openruyi 修改其他用户密码失败，提示 "You may not view or modify password information for <其他用户>"，密码未被修改。
