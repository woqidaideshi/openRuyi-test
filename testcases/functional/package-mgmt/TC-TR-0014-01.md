## 描述

验证 rpm、dnf 基本命令可用；软件包能正常安装（依赖自动解析），未被依赖的包能正常卸载，被其他包依赖时卸载被拒绝。

## 前置条件

1. 已安装 rpm、dnf，具备 root 权限（sudo）。
2. 已配置可用 dnf 软件源。
3. `glibc` 已安装且被其他包依赖（`rpm -q --whatrequires glibc` 有输出）。

## 测试步骤

1. 查看 `rpm --version` 与 `dnf --version` 的输出，并用 `rpm -qa` 列出已安装包。
2. 记录 `htop` 的原始安装状态；若已安装，用 `dnf remove -y htop` 卸载，并用 `rpm -q htop` 查看其安装状态。
3. 安装测试包 `htop`，用 `rpm -q htop` 查看已安装版本，用 `dnf repoquery --requires htop` 查看依赖项，并核对依赖项在安装后是否均已满足。
4. 卸载 `htop`，再用 `rpm -q htop` 查看安装状态。
5. 用 `rpm -e glibc` 卸载被其他包依赖的 `glibc`，再用 `rpm -q glibc` 查看安装状态。
6. 清理：若 `htop` 原本已安装，用 `dnf install -y htop` 重新安装，并查看其安装状态。

## 预期结果

1. 步骤 1：两个命令均正常输出版本，`rpm -qa` 正常列出已安装包，退出码为 0。
2. 步骤 2：原始安装状态已记录；`rpm -q htop` 提示未安装。
3. 步骤 3：安装完成，退出码为 0；`rpm -q htop` 返回包名与版本；`dnf repoquery --requires htop` 列出的依赖项在安装后均已满足，无缺失。
4. 步骤 4：卸载完成，退出码为 0；`rpm -q htop` 退出码为 1（提示未安装）。
5. 步骤 5：卸载被拒绝，退出码非 0，输出 `error: Failed dependencies:`；`rpm -q glibc` 退出码为 0，未被误删。
6. 步骤 6：`htop` 的安装状态与测试前一致。

> `htop` 的依赖（`autoconf`、`automake`、`ncurses`、`ncurses-devel`、`glibc`）在基础镜像上通常已预装，此时安装不会触发依赖下载。若需验证“自动装依赖”，应另选依赖未预装的包，并在安装前记录该依赖包未安装。
