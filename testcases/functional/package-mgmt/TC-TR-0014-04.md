# TC-TR-0014-04 ｜ 仓库元数据正确性

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0014（包管理功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 软件包管理 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证仓库元数据（repodata）获取与校验正确，仓库不可达时报错合理。

## 前置条件

1. 已配置可用的 dnf 软件源。
2. 具备 root 权限（sudo）。

## 测试步骤

1. 执行 `dnf makecache` 刷新仓库元数据缓存，并查看缓存目录 `/var/cache/libdnf5` 的占用。
2. 执行 `dnf repolist` 查看已配置仓库，执行 `dnf repoquery --info bash` 查看包信息。
3. 执行 `dnf check --dependencies` 与 `dnf check-update` 核查元数据与已安装包的一致性。
4. 验证缓存真实生效：先在缓存存在时执行 `dnf -C repoquery --available bash` 查询，`dnf clean metadata` 后重复查询，再执行 `dnf makecache` 恢复。
5. 在 `/etc/yum.repos.d/` 下新增一个不可达仓库（`baseurl=http://127.0.0.1:9/unreachable/`，`enabled=1`）后执行 `dnf makecache`。
6. 移除该仓库文件，`dnf clean all` 后重新 `dnf makecache`。

> 步骤 4 的几条命令必须用同一身份执行（统一加 `sudo`）：缓存按用户隔离，身份不同会查到不同的缓存。

## 预期结果

1. 步骤 1：`makecache` 退出码为 0，输出 `Metadata cache created.`；缓存目录存在且有数据。
2. 步骤 2：`repolist` 列出已配置仓库；`repoquery --info` 返回完整包信息（版本、架构、大小、来源等）。
3. 步骤 3：`check --dependencies` 退出码为 0；`check-update` 无更新为 0、有更新为 100、出错为 1。
4. 步骤 4：缓存存在时查询退出码为 0；`clean metadata` 后同一查询退出码为 1，并提示 `no cache for repository`；`makecache` 后恢复为 0。
5. 步骤 5：`makecache` 退出码为 1，提示连接失败。
6. 步骤 6：移除该仓库后 `makecache` 退出码恢复为 0。
