# TC-TR-0014-03 ｜ 异常包操作与错误码

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0014（包管理功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 软件包管理 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证异常包操作返回合理错误码，不损坏已有包、不产生半安装状态。

## 前置条件

1. 具备 root 权限（sudo）。
2. 已配置可用的 dnf 软件源。
3. 存在一个普通用户账户（如 `openruyi`），用于验证权限不足场景。

## 测试步骤

1. 采集包状态基线：`dnf check --dependencies` 与 `rpm -Va --nofiles --nodigest` 的输出，保存到测试目录下供后续比对。
2. 安装不存在的包 `not-exist-pkg-xyz`。
3. 卸载未安装的包 `not-exist-pkg-xyz`。
4. 以普通用户 `openruyi` 身份安装 `htop`。
5. 执行 `rpm -ivh htop-<版本>.rpm` 安装一个截断的真实包：先执行 `dnf download htop` 取回 rpm，截取前 3000 字节后安装。
6. 选定一个本机未安装的包（记作 `<包名>`），执行 `dnf --assumeno install <包名>` 模拟事务中止，并执行 `rpm -q <包名>` 查看安装状态。
7. 重新采集包状态并与基线比对（`dnf check --dependencies` 与 `rpm -Va --nofiles --nodigest`）。
8. 清理：删除测试目录。

> 不要用 `dd if=/dev/urandom` 造损坏包：rpm 会把随机内容当成文件清单解析，报出语义不明的 `open of <乱码> failed: No such file or directory`。
> 步骤 6 必须选未安装的包：若包已安装，`--assumeno` 只会输出 `Nothing to do.` 且退出码为 0，无法验证中止行为。

## 预期结果

1. 步骤 1：两个基线均已采集（内容为系统当前已有的问题，可能为空）。
2. 步骤 2：退出码非 0，提示 `No match for argument`。
3. 步骤 3：退出码为 0，输出 `Nothing to do.`，未误删其他包。
4. 步骤 4：退出码非 0，提示需要超级用户权限。
5. 步骤 5：退出码非 0，提示包已损坏、无法安装，不产生半安装状态。
6. 步骤 6：`--assumeno` 输出 `Operation aborted by the user.`、退出码为 1；`rpm -q <包名>` 退出码仍为 1，未产生半安装状态。
7. 步骤 7：两次比对均无差异，异常操作未新增包状态问题。
8. 步骤 8：测试目录已删除，无残留。
