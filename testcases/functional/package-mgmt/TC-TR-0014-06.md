# TC-TR-0014-06 ｜ 异常包操作与错误码

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0014（包管理功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 软件包管理 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证异常包操作返回合理错误码，不损坏已有包、不产生半安装状态。

## 前置条件

1. 具备 root 权限（sudo）。
2. 已配置可用的 dnf 软件源。

## 测试步骤

1. 安装不存在的包，记录退出码：
   ```bash
   sudo dnf install -y not-exist-pkg-xyz
   echo $?
   ```
2. 卸载未安装的包，记录退出码：
   ```bash
   sudo dnf remove -y not-exist-pkg-xyz
   echo $?
   ```
3. 以普通用户执行安装（权限不足），记录退出码：
   ```bash
   dnf install -y htop
   echo $?
   ```
4. 使用 rpm 安装**截断的真实包**（比随机字节更接近真实损坏场景），记录退出码：
   ```bash
   sudo dnf download --destdir /tmp/tc-dl htop
   head -c 3000 /tmp/tc-dl/htop-*.riscv64.rpm > /tmp/bad.rpm
   sudo rpm -ivh /tmp/bad.rpm
   echo $?
   sudo rm -rf /tmp/tc-dl /tmp/bad.rpm
   ```
   > 不建议用 `dd if=/dev/urandom` 造“损坏包”：rpm 会把随机内容当成文件清单解析，报出 `open of <乱码> failed: No such file or directory`，语义不明。
5. 以事务中止方式安装（模拟用户取消），确认不产生半安装状态：
   ```bash
   sudo dnf --assumeno install -y tree
   echo $?
   rpm -q tree
   ```
6. 核对系统包状态与操作前一致：
   ```bash
   rpm -q htop
   sudo dnf check --dependencies
   echo $?
   sudo rpm -Va --nofiles --nodigest | head
   ```

## 预期结果

1. 步骤 1：退出码非 `0`，提示 `No match for argument`。
2. 步骤 2：dnf5 对未安装包返回 `0`，输出 `Nothing to do.`，不误删其他包。
3. 步骤 3：退出码非 `0`，提示需要超级用户权限。
4. 步骤 4：退出码非 `0`，提示包已损坏、无法安装，不产生半安装状态。
5. 步骤 5：事务被中止，输出 `Operation aborted by the user.`，`rpm -q tree` 退出码为 `1`。
6. 步骤 6：`dnf check --dependencies` 退出码为 `0`，`rpm -Va` 无异常输出，已有包未受损。

> **不要用 `dnf autoremove -y` 做清理**：它会卸载本机上所有不再被其他包依赖的包。实测一条命令删除了 46 个包，且无法通过 `dnf history undo` 完整恢复。清理只针对本次显式安装的包使用 `dnf remove`。
