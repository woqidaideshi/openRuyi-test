# TC-TR-0014-05 ｜ 仓库元数据正确性

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0014（包管理功能） |
| 测试类型 | 功能测试 |
| 功能模块 | 软件包管理 |
| 优先级 | P0 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证仓库元数据（repodata）获取与校验正确，仓库不可达时报错合理。

## 前置条件

1. 已配置可用的 dnf 软件源。
2. 具备 root 权限（sudo）。

## 测试步骤

1. 刷新仓库元数据缓存，并确认缓存落地：
   ```bash
   sudo dnf makecache
   echo $?
   du -sh /var/cache/libdnf5 2>/dev/null
   ```
2. 校验 repodata 内容与仓库信息：
   ```bash
   dnf repolist
   dnf repoquery --info bash | head -20
   ```
3. 校验元数据与已安装包的一致性：
   ```bash
   sudo dnf check --dependencies
   echo $?
   dnf check-update
   echo $?
   ```
4. 验证缓存真实生效，再清理并确认离线不可用（三条命令必须用同一身份执行，统一加 `sudo`）：
   ```bash
   sudo dnf -C repoquery --available bash
   echo $?
   sudo dnf clean metadata
   sudo dnf -C repoquery --available bash
   echo $?
   sudo dnf makecache
   echo $?
   ```
5. 配置不可达仓库后刷新，观察报错，事后清理：
   ```bash
   sudo tee /etc/yum.repos.d/_unreachable.repo > /dev/null <<'EOF'
   [_unreachable]
   name=unreachable
   baseurl=http://127.0.0.1:9/unreachable/
   enabled=1
   gpgcheck=0
   EOF
   sudo dnf makecache
   echo $?
   sudo rm -f /etc/yum.repos.d/_unreachable.repo
   sudo dnf clean all > /dev/null
   sudo dnf makecache
   ```

## 预期结果

1. 步骤 1：`makecache` 退出码为 `0`，输出 `Metadata cache created.`。
2. 步骤 2：`dnf repolist` 列出已配置仓库，`dnf repoquery --info bash` 返回完整包信息（版本、架构、大小、来源等）。
3. 步骤 3：`dnf check --dependencies` 退出码为 `0`；`dnf check-update` 无更新为 `0`、有更新为 `100`、出错为 `1`。
4. 步骤 4：有缓存时 `dnf -C repoquery --available bash` 退出码为 `0`；`clean metadata` 后同一查询退出码为 `1` 并提示 `no cache for repository`；`makecache` 后恢复为 `0`。
5. 步骤 5：新增不可达仓库后 `makecache` 退出码为 `1` 并提示连接失败；移除该仓库后恢复为 `0`。
