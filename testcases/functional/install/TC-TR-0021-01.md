# TC-TR-0021-01 ｜ cloud-init 有 data iso 启动服务

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0021（Cloud-init 正常使用） |
| 测试类型 | 功能测试 |
| 功能模块 | 安装与部署 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证挂载 data iso 启动 service 发布件后对应 service 被启动并可执行相关命令。

## 前置条件

1. 已安装 cloud-init。
2. 已准备含 user-data 的 data ISO（卷标 CIDATA）。

## 测试步骤

1. 确认 cloud-init 已安装：
   ```bash
   rpm -q cloud-init
   ```
2. 挂载 data ISO 后启动系统。
3. 查看 cloud-init 服务状态与执行结果：
   ```bash
   systemctl status cloud-init --no-pager
   cloud-init status
   ```
4. 确认本次启动 service 被触发：
   ```bash
   systemctl is-active cloud-init
   ```
5. 执行 user-data 中定义的相关命令。

## 预期结果

1. 步骤 1：cloud-init 已安装。
2. 步骤 3：有数据源时对应 service 被启动，`cloud-init status` 显示 `done`。
3. 步骤 4：`cloud-init` 服务状态为 `active`（本次启动被触发）。
4. 步骤 5：user-data 定义的动作执行成功。

## 执行条件说明（2026-11-10 实测）

已验证的 openRuyi riscv64 系统上：

| 检查项 | 实测结果 |
|---|---|
| `rpm -q cloud-init` | **未安装**（`package cloud-init is not installed`） |
| `cloud-init status` | `command not found` |
| 仓库可用性 | `cloud-init-25.3-7.11.or.riscv64`（Base 仓可安装） |
| 现存 seed 镜像 | `/home/openruyi/seed.img`：`ISO 9660`、`LABEL="cidata"`，但**仅有 `test.txt`，无 `user-data`/`meta-data`** |

**结论**：当前环境不具备执行条件（cloud-init 未安装，且现有 cidata 种子镜像内容不完整，不含 cloud-init 必需的 `user-data` 与 `meta-data`）。

**执行前准备（关键）**：
1. 安装 cloud-init：`sudo dnf install -y cloud-init`；
2. data ISO 必须是合法 NoCloud 种子，**至少包含 `user-data` 和 `meta-data` 两个文件**，卷标为 `CIDATA`：
   ```bash
   CASE_TMP=/tmp/tc-cloudinit && mkdir -p $CASE_TMP && cd $CASE_TMP
   printf '#cloud-config\nruncmd:\n  - [ sh, -c, "echo cloudinit-ok > /tmp/ci-proof" ]\n' > user-data
   printf 'instance-id: tc-0021-01\nlocal-hostname: ci-vm\n' > meta-data
   genisoimage -output $CASE_TMP/seed.iso -volid CIDATA -joliet -rock user-data meta-data
   ```
3. 将 data ISO 作为第二个光驱挂到虚拟机后**首次启动**；cloud-init 仅在首次实例化时执行，**同一镜像重复启动会被 `instance-id` 去重**，首次验证后需重新使用未见过的 `instance-id` 或新磁盘。
4. 判定“已触发”的推荐证据链：
   ```bash
   cloud-init status --long
   ls -l /var/lib/cloud/instances/
   cat /var/lib/cloud/data/result.json 2>/dev/null | head
   ls -l /tmp/ci-proof        # user-data 里定义的动作产物
   ```
5. 清理临时目录：
   ```bash
   rm -rf $CASE_TMP
   ```
