# TC-TR-0021-01 ｜ cloud-init 数据源启动与配置执行

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0021（Cloud-init 正常使用） |
| 测试类型 | 功能测试 |
| 功能模块 | 安装与部署 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证挂载含 `user-data` 的 data ISO 启动时 cloud-init 服务被启动并执行配置动作；移除 data ISO 后重启，对应服务不被启动。

## 前置条件

1. 具备可重复启动的测试环境，可控制是否挂载 data ISO。

## 测试步骤

1. 执行 `rpm -q cloud-init` 查看安装情况，执行 `systemctl is-enabled cloud-init-local cloud-init-main cloud-init-network cloud-config cloud-final` 查看各 unit 是否随系统启动；未启用的服务需执行 `systemctl enable` 启用。
2. 生成 data ISO：
    - `user-data` 定义生成标记文件 `/root/ci-proof` 的动作，内容如下：

        ```yaml
        #cloud-config
        runcmd:
          - [ sh, -c, "echo ok > /root/ci-proof" ]
        ```

    - `meta-data` 包含元数据信息，只设置 `instance-id`（不设 `local-hostname`，避免改动被测机主机名），内容如下：

        ```
        instance-id: ci-test-01
        ```

        重复执行本用例时，须更换新的 `instance-id`（如 `ci-test-02`）。否则，cloud-init 会因判定实例已初始化而跳过 `runcmd`，导致标记文件 `/root/ci-proof` 无法生成。

    - 将两个文件打包为卷标 `CIDATA` 的 data ISO，执行 `xorriso -as mkisofs -output ci-seed.iso -volid CIDATA -joliet -rock user-data meta-data`。
3. 系统启动前接入 data ISO：
    - 虚拟机：通过 `-drive` 参数接入 data ISO，例如 `-drive file=ci-seed.iso,format=raw,if=virtio`。
    - 物理机：将 data ISO 写入 U 盘，开机前插入物理机。
4. 启动系统并登录，执行 `sudo cloud-init status --long` 查看 cloud-init 执行状态。
5. 检查标记文件 `/root/ci-proof` 是否存在及其内容。
6. 移除 data ISO 后重启系统：
    1. 删除步骤 5 生成的标记文件 `/root/ci-proof`；
    2. 关闭系统；
    3. 移除 data ISO：虚拟机去掉启动命令中的 `-drive` 参数，物理机拔出 U 盘；
    4. 启动系统并登录。
7. 执行 `sudo cloud-init status --long`，并检查标记文件 `/root/ci-proof` 是否存在。

## 预期结果

1. 步骤 1：cloud-init 已安装，输出中可见版本号；`cloud-init-local`、`cloud-init-main`、`cloud-init-network`、`cloud-config`、`cloud-final` 五个服务均已启用。
2. 步骤 2：文件生成与打包均无报错，生成 `ci-seed.iso` 且卷标为 `CIDATA`。
3. 步骤 3：data ISO 已接入，虚拟机启动参数无报错或物理机已识别插入的 U 盘。
4. 步骤 4：系统从原有系统盘正常引导启动，登录成功；`status` 为 `running` 或 `done`，`boot_status_code` 为 `enabled-by-generator`，`detail` 中数据源为 `DataSourceNoCloud [seed=/dev/vdb]`（seed 指向所接入的 data ISO 设备如 /dev/vdb）。
5. 步骤 5：`/root/ci-proof` 存在且内容为 `ok`。
6. 步骤 6：标记文件已删除，data ISO 已移除，系统从原有系统盘正常启动并可登录。
7. 步骤 7：`cloud-init status --long` 显示 `status: disabled`、`boot_status_code: disabled-by-generator`、`detail: Cloud-init disabled by cloud-init-generator`，即本次启动未找到数据源、cloud-init 未运行；`/root/ci-proof` 未被重新生成。
