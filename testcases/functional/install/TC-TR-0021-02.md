# TC-TR-0021-02 ｜ cloud-init 无 data iso 不启动

| 字段 | 值 |
|---|---|
| 关联需求 | TR-0021（Cloud-init 正常使用） |
| 测试类型 | 功能测试 |
| 功能模块 | 安装与部署 |
| 优先级 | P1 |
| 覆盖设备 | KVM/物理机 |
| 可自动化 | 是 |
| 自动化覆盖 | 否 |

## 描述

验证无 data iso 时启动发布件，对应 service 不被启动。

## 前置条件

1. 已安装 cloud-init。
2. 无 data ISO。

## 测试步骤

1. 不挂载 data ISO 启动系统。
2. 检查 cloud-init 服务状态：
   ```bash
   systemctl is-active cloud-init
   cloud-init status
   ```

## 预期结果

1. 步骤 2：无数据源时对应 service 未被启动（`inactive`），`cloud-init status` 显示 `not run` 或未运行。

## 执行条件说明（2026-11-10 实测）

同 TC-TR-0021-01，当前验证环境 `cloud-init` 未安装（`rpm -q cloud-init` → `package cloud-init is not installed`），无法执行本用例。

补充判定要点：
1. 需区分 “cloud-init 未安装” 与 “已安装但无数据源”。前者 `systemctl is-active cloud-init` 也返回 `inactive`，但**不能**作为通过依据；必须先确认 `rpm -q cloud-init` 成功、且对应 unit 存在：
   ```bash
   rpm -q cloud-init
   systemctl list-unit-files | grep cloud-init
   ```
2. 无数据源时应能看到明确的“未找到数据源”日志，建议一并采集：
   ```bash
   sudo journalctl -u cloud-init --no-pager | tail -20
   cloud-init status --long 2>&1
   ```
3. 若同一磁盘曾带 seed 启动过，cloud-init 可能因 `/var/lib/cloud/` 缓存而看起来“未运行”，需使用全新未实例化的磁盘验证。
